# 策略、风控、回测职责分层与参数归属

## 1. 目标

本文件用于统一以下三类参数的职责边界，并作为后续代码收口的唯一依据：

1. 策略/因子定义参数
2. 回测会话参数
3. 风控运行参数

要求：

1. 同一语义只能有一个主归属层。
2. 页面只能编辑自己所属层的参数，不能跨层代写、代存、代回填。
3. 结构化合同必须按层存储，不能靠平铺字段或别名回退混用。
4. 回测页可以读取策略定义，但不能反向改写策略定义。
5. 风控页可以读取策略/回测上下文用于展示，但不能持久化策略定义或回测假设。
6. 系统默认值页只能维护运行期规则默认值，不能再承载回测成本默认值并通过运行时规则注入到策略结构。

## 2. 分层定义

### 2.1 策略/因子定义层

职责：当前代码阶段只描述“这条策略本身怎么算指标、怎么算排序或目标权重”。

特征：

1. 脱离某一次回测依然成立。
2. 属于策略模板、策略实例、因子叠加合同本身。
3. 当前不负责开平仓、调仓、止损止盈执行；这些行为属于其他执行链路。
4. 应由策略创建页或策略编辑页维护。

主存储位置：

1. `rule_profile`
2. `factor_overlay`
3. 策略类型专属参数字段

典型参数：

1. `positionSize`
2. `stopLoss`
3. `takeProfit`
4. `maxDrawdownLimit`
5. `rebalanceDays`
6. `factor_overlay.targetPositionCount`
7. `factor_overlay.minimumCompositeScore`
8. 各策略专属参数，例如 `momentumPeriod`、`topN`、`fastPeriod`、`slowPeriod`

### 2.2 回测会话层

职责：描述“本次验证怎么跑”。

特征：

1. 只对某一次回测或研究实验有效。
2. 改变它不会改变策略定义，只会改变本次回测结果。
3. 应由策略回测页或因子回测页维护。

主存储位置：

1. `backtest_runtime`
2. `backtest_universe_*`
3. 回测请求中的 `costSpec`、`executionSpec`、`dataSpec`

典型参数：

1. `startDate` / `endDate` / `backtestPeriod`
2. `initialCapital`
3. `benchmark` / `benchmarkSymbol`
4. `commissionRate`
5. `slippageRate`
6. `dataSourceMode`
7. `marketFilters`
8. `sectorFilters`
9. `excludeSt`
10. `minListingDays`
11. `minTurnoverRate`
12. `maxPositions`
13. `minCompositeScore`
14. 研究增强项，例如 `enableWalkForward`、`enableMonteCarlo`

说明：

1. 当策略启用 `factor_overlay` 时，选股数和最低综合分由策略定义层负责，回测层不得再用 `maxPositions`、`minCompositeScore` 反向覆盖。
2. 因子回测页里的 `forwardDays`、`rebalanceDays`、`benchmarkSymbol`、`commissionRate`、`slippageRate` 属于因子研究运行参数，也归入回测会话层，不属于风控。

### 2.3 风控运行层

职责：描述“运行中允许下什么单、允许承受什么实时风险”。

特征：

1. 面向账户、组合、委托执行与实时监控。
2. 主要由风控页、RiskConfigService、RiskMonitorService 维护和消费。
3. 不应定义策略选股逻辑，也不应定义某次回测假设。

主存储位置：

1. RiskConfigService 持久化配置
2. 风控页动态参数配置
3. RiskMonitorService 运行时判定输入

典型参数：

1. `varWarningPercent`
2. `positionSizingMethod`
3. `maxPositionPercent`
4. `maxTotalExposure`
5. `orderSizeLimit`
6. `turnoverLimit`
7. `slippageLimit`
8. `level1Breaker`
9. `level2Breaker`
10. `level3Breaker`
11. `maxDailyLoss`

### 2.4 全局默认值层

职责：提供默认初值，不拥有业务语义。

规则：

1. 默认值层只能给各业务层提供初始值。
2. 默认值层不能替代业务归属层成为编辑入口。
3. `SystemSettingsPage` 可以维护全局默认初值，但不能改变参数归属。

## 4. 禁止事项

以下行为一律视为职责越界：

1. 风控页持久化 `backtest_assumptions`、`backtest_runtime` 或任何回测成本参数。
2. 回测页加载风险参数后再用白名单/黑名单清洗兜底。
3. `rebalanceDays` 同时作为 `rule_profile` 输入字段和 `execution_policy` 输入字段。
4. `factor_overlay.targetPositionCount` 与 `maxPositions` 混读。
5. `factor_overlay.minimumCompositeScore` 与 `minCompositeScore` 混读。
6. `slippageLimit` 兼容映射为 `slippageRate`。
7. `positionSizingMethod`、`maxPositionPercent`、`maxTotalExposure` 出现在策略创建页或回测页作为独立编辑入口。
8. `runtimeRuleDefaults.backtestAssumptions` 注入 `backtestAssumptionsSnapshot`。

## 5. 本次收口决定

本次优化先处理确定性最高、不会改变业务含义的混层点：

1. 风控页不再写入任何 `backtestAssumptions`。
2. 风控页不再把 `rebalanceDays` 当作风控参数。
3. 策略回测页从共享元数据中只读取 `backtest` 类参数，不再读取 `risk` 类参数再二次过滤。
4. `rebalanceDays` 只从策略定义层进入，执行频率只允许由其派生。
5. 系统默认值页不再维护和注入回测成本默认值。
6. 风控页不再维护 `maxPositions`；`excludeSt`、`minListingDays`、`minTurnoverRate` 已提为 `StrategyBacktestConfig` 显式字段，不再通过泛化参数容器回捞。
7. 组合运行期目标持仓数只认 `targetPositionCount`；`RiskMonitorService` 和 `TradingConnectionConfigService` 不再把 `maxPositions` 当组合运行期别名。

### 7.2 真正所有策略都需要的通用参数

实现规矩：

- 策略代码里禁止直接写数字字面量；窗口长度、阈值、默认值、数量单位、上下界、步长、容量等都必须先提升为具名常量或宏，再进入算法实现。
- 策略算法必须按大批量大数据场景设计；默认要求单次批处理可承载大规模标的和长时间序列，必须显式考虑复杂度、内存占用、批量吞吐、容量预留、减少重复分配、减少拷贝和避免无界状态膨胀。
- 若某个策略天然需要高频滚动计算，优先使用滚动窗口、增量更新、预分配容器、按批处理，而不是每个切片重复全窗口重算。
- 若策略涉及复杂矩阵、向量、协方差、回归或优化计算，允许直接使用 Eigen；但前提仍是服务于批量性能和数值实现清晰度，不能为了“用了库”反而增加拷贝、临时对象或边界污染。

这些参数在基类 `StrategyCommonConfig` 中定义，每个策略实例都能访问：

| 通用参数 | 类型 | 说明 |
| --- | --- | --- |
| `allow_short` | `bool` | 是否允许做空，决定输出信号是否包含负权重 |
| `max_positions` | `int` | 最大同时持仓数量，作为组合构建硬约束 |
| `max_weight_per_stock` | `double` | 单标的最大权重上限，例如 `0.1` |
| `min_weight_per_stock` | `double` | 单标的最小权重下限，例如 `0.0` |
| `weight_scheme` | `WeightScheme` | 权重分配方案，例如 `EQUAL`、`MARKET_CAP`、`SIGNAL_STRENGTH`、`RISK_PARITY` |
| `rebalance_frequency_days` | `RebalanceFrequencyDays` | 调仓天数，直接复用现有 strategy 域的调仓天数合同 |

注：资金、保证金、费率等属于账户层面的动态数据，不在此处，由 `AccountSnapshot` 提供。

### 7.3 各策略的个性化参数

个性化参数按策略类别拆开，每类只保留最核心配置，不再与通用参数混杂。

以下公式作为当前首版实现冻结口径；后续如果要改算法，先改这里，再改代码。

2026-05-30 冻结说明：当前 11 类策略统一以 core-only 计算接口为准；当前策略域只负责计算，不负责开平仓、持仓管理、调仓执行和止损止盈执行。后续如果要恢复执行行为或调整算法边界，必须先修改本节合同，再修改代码。

当前落地阶段说明：

- 当前 11 类策略代码统一只落核心计算函数。
- 当前策略域只负责计算，不负责开平仓、持仓管理、调仓执行和止损止盈执行。
- 双均线、海龟、布林带、RSI、统计配对、订单流、波动率价差当前代码不包含开平仓、持有期或执行编排，只输出指标计算结果。
- 多因子、机器学习当前代码输出排序或得分结果，不包含最终仓位分配。
- 风险平价当前代码输出波动率、原始权重、归一权重和目标权重结果，不包含调仓流程；完整目标公式仍以下文各节描述为准。

#### 7.3.1 趋势跟踪：双均线交叉

策略类型：`StrategyType::DOUBLE_MOVING_AVERAGE`

个性化参数合同：`DoubleMovingAverageStrategySpec`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `fast_period` | `int` | 快线周期，如 5 |
| `slow_period` | `int` | 慢线周期，如 20 |
| `price_type` | `TechnicalPriceType` | 使用的价格类型，直接复用现有 factor 域价格字段枚举，例如 `CLOSE` |

公式口径：

当前代码阶段：只实现选价、快慢均线和 `spread(t)` 计算，不实现按 `spread(t-1)` 与 `spread(t)` 触发的开平仓行为。

- 快均线：`MA_fast(t) = (1 / fast_period) * sum(P_{t-i}), i=0..fast_period-1`
- 慢均线：`MA_slow(t) = (1 / slow_period) * sum(P_{t-i}), i=0..slow_period-1`
- 价差信号：`spread(t) = MA_fast(t) - MA_slow(t)`
- 开多条件：`spread(t-1) <= 0 且 spread(t) > 0`
- 平多条件：`spread(t-1) >= 0 且 spread(t) < 0`
- 开空条件：仅当 `allow_short=true` 时允许，条件为 `spread(t-1) >= 0 且 spread(t) < 0`
- 平空条件：仅当存在空头持仓且 `spread(t-1) <= 0 且 spread(t) > 0`

#### 7.3.2 趋势跟踪：通道突破（海龟）

策略类型：`StrategyType::TURTLE_BREAKOUT`

个性化参数合同：`TurtleBreakoutStrategySpec`

| 参数                    | 类型       | 说明                         |
| ----------------------- | ---------- | ---------------------------- |
| `channel_period`      | `int`    | 通道计算周期，如 20          |
| `breakout_multiplier` | `double` | 突破倍数（ATR 倍数），如 1.0 |
| `atr_period`          | `int`    | ATR 计算周期，如 20          |

公式口径：

当前代码阶段：只实现 `Upper(t)`、`Lower(t)`、`TR(t)`、`ATR(t)` 计算，不实现突破开平仓行为。

- 上轨：`Upper(t) = max(High_{t-i}), i=1..channel_period`
- 下轨：`Lower(t) = min(Low_{t-i}), i=1..channel_period`
- 真实波幅：`TR(t) = max(High(t)-Low(t), abs(High(t)-Close(t-1)), abs(Low(t)-Close(t-1)))`
- 平均真实波幅：`ATR(t) = (1 / atr_period) * sum(TR_{t-i}), i=0..atr_period-1`
- 开多条件：`Close(t) > Upper(t) + breakout_multiplier * ATR(t)`
- 平多条件：`Close(t) < Lower(t)`
- 开空条件：仅当 `allow_short=true` 时允许，条件为 `Close(t) < Lower(t) - breakout_multiplier * ATR(t)`
- 平空条件：`Close(t) > Upper(t)`

#### 7.3.3 均值回复：布林带

策略类型：`StrategyType::BOLLINGER_BAND_MEAN_REVERSION`

个性化参数合同：`BollingerBandMeanReversionStrategySpec`

| 参数                | 类型       | 说明                                     |
| ------------------- | ---------- | ---------------------------------------- |
| `period`          | `int`    | 中轨和标准差计算周期，如 20              |
| `num_std`         | `double` | 带宽标准差倍数，如 2.0                   |
| `entry_threshold` | `double` | 偏离中轨的标准分数阈值，用于开仓，如 1.0 |
| `exit_threshold`  | `double` | 回归中轨的阈值，用于平仓，如 0.2         |

公式口径：

当前代码阶段：只实现 `Middle(t)`、`Std(t)`、`z(t)` 计算，不实现按阈值触发的开平仓行为。

- 中轨：`Middle(t) = (1 / period) * sum(P_{t-i}), i=0..period-1`
- 波动率：`Std(t) = std(P_{t-i}), i=0..period-1`
- 上下轨：`Upper(t) = Middle(t) + num_std * Std(t)`，`Lower(t) = Middle(t) - num_std * Std(t)`
- 标准分数：`z(t) = (P(t) - Middle(t)) / max(Std(t), eps)`
- 开多条件：`z(t) <= -entry_threshold`
- 平多条件：`z(t) >= -exit_threshold`
- 开空条件：仅当 `allow_short=true` 时允许，条件为 `z(t) >= entry_threshold`
- 平空条件：`z(t) <= exit_threshold`

#### 7.3.4 均值回复：RSI

策略类型：`StrategyType::RSI_MEAN_REVERSION`

个性化参数合同：`RsiMeanReversionStrategySpec`

| 参数           | 类型       | 说明                |
| -------------- | ---------- | ------------------- |
| `period`     | `int`    | RSI 计算周期，如 14 |
| `oversold`   | `double` | 超卖阈值，如 30     |
| `overbought` | `double` | 超买阈值，如 70     |

公式口径：

当前代码阶段：只实现 `AvgGain(t)`、`AvgLoss(t)`、`RSI(t)` 计算，不实现按阈值触发的开平仓行为。

- 涨跌幅：`delta(t) = Close(t) - Close(t-1)`
- 平均上涨：`AvgGain(t) = mean(max(delta, 0)) over period`
- 平均下跌：`AvgLoss(t) = mean(max(-delta, 0)) over period`
- 相对强弱：`RS(t) = AvgGain(t) / max(AvgLoss(t), eps)`
- RSI：`RSI(t) = 100 - 100 / (1 + RS(t))`
- 开多条件：`RSI(t) <= oversold`
- 平多条件：`RSI(t) >= 50`
- 开空条件：仅当 `allow_short=true` 时允许，条件为 `RSI(t) >= overbought`
- 平空条件：`RSI(t) <= 50`

#### 7.3.5 量化因子选股

策略类型：`StrategyType::MULTI_FACTOR_SELECTION`

个性化参数合同：`MultiFactorSelectionStrategySpec`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `factor_weights` | `FactorWeightList` | 直接复用现有引擎的因子权重合同 |
| `top_n` | `CandidateCount` | 选股数量，如 50 |
| `industry_neutral` | `bool` | 是否做行业中性化处理 |

公式口径：

当前代码阶段：只实现综合得分计算与按 `top_n` 截断，不实现 `weight_scheme=SIGNAL_STRENGTH` 的权重归一和最终仓位分配。

- 单因子标准分：`z_i(s, t) = standardized(factor_i(s, t))`
- 行业中性口径：若 `industry_neutral=true`，则使用 `z_i_neutral(s, t) = z_i(s, t) - mean_industry(z_i(*, t))`
- 综合得分：`Score(s, t) = sum(w_i * z_i_used(s, t))`
- 排序规则：按 `Score(s, t)` 从高到低排序，取前 `top_n`
- 权重归一：若 `weight_scheme=SIGNAL_STRENGTH`，则 `alloc(s, t) = max(Score(s, t), 0) / sum(max(Score(*, t), 0))`
- 若 `weight_scheme` 不是信号强度，则选股阶段只负责输出候选排序，最终仓位分配交给通用权重规则

#### 7.3.6 事件驱动：业绩惊喜

策略类型：`StrategyType::EARNINGS_SURPRISE`

个性化参数合同：`EarningsSurpriseStrategySpec`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `surprise_threshold` | `double` | 惊喜阈值，即实际超预期比例，如 0.2 |
| `hold_days` | `int` | 持有天数，到期平仓 |
| `event_sources` | `vector<EventSourceKind>` | 关注的事件源枚举集合，例如 `EARNINGS` |

公式口径：

当前代码阶段：只实现 `Surprise(t)` 计算和 `event_sources` 过滤，不实现按 `surprise_threshold` 开仓、按 `hold_days` 平仓的策略行为。

- 惊喜值：`Surprise(t) = (Actual(t) - Expected(t)) / max(abs(Expected(t)), eps)`
- 开多条件：`Surprise(t) >= surprise_threshold`
- 开空条件：仅当 `allow_short=true` 时允许，条件为 `Surprise(t) <= -surprise_threshold`
- 平仓条件：入场后持有 `hold_days` 个交易日即平仓
- 事件过滤：只有 `event_source in event_sources` 的事件才进入打分与信号生成

#### 7.3.7 套利：统计配对

策略类型：`StrategyType::STATISTICAL_PAIR_TRADING`

个性化参数合同：`StatisticalPairTradingStrategySpec`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `pair` | `TradingSymbolPair` | 配对资产标识结构，内部持有两个 `SymbolId` |
| `hedge_ratio` | `double` | 对冲比率（β），可由回归计算或静态指定 |
| `lookback` | `int` | 计算价差均值和标准差的窗口 |
| `entry_z` | `double` | 开仓 Z 值阈值，如 2.0 |
| `exit_z` | `double` | 平仓 Z 值阈值，如 0.5 |

公式口径：

当前代码阶段：只实现 `Spread(t)`、`MeanSpread(t)`、`StdSpread(t)`、`z(t)` 计算，不实现按 `entry_z`、`exit_z` 触发的开平仓和名义头寸配平。

- 对数价差：`Spread(t) = ln(P1(t)) - hedge_ratio * ln(P2(t))`
- 价差均值：`MeanSpread(t) = mean(Spread_{t-i}), i=0..lookback-1`
- 价差标准差：`StdSpread(t) = std(Spread_{t-i}), i=0..lookback-1`
- 标准分数：`z(t) = (Spread(t) - MeanSpread(t)) / max(StdSpread(t), eps)`
- 开仓条件：`z(t) >= entry_z` 时做空价差，`z(t) <= -entry_z` 时做多价差
- 平仓条件：`abs(z(t)) <= exit_z`
- 权重约束：多空腿名义头寸按 `1 : hedge_ratio` 配平

#### 7.3.8 资产配置：风险平价

策略类型：`StrategyType::RISK_PARITY_ALLOCATION`

个性化参数合同：`RiskParityAllocationStrategySpec`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `assets` | `SymbolIdList` | 配置的资产列表，直接复用现有引擎标的强类型列表 |
| `vol_lookback` | `int` | 波动率计算窗口，如 60 |
| `target_vol` | `double` | 可选的目标年化波动率，用于杠杆缩放，0 表示不缩放 |

公式口径：

当前代码阶段：输出 `sigma_i(t)`、归一权重和目标权重结果，不包含调仓频率控制和组合执行流程。

- 当前首版不做全协方差 ERC 求解，只做基于个体波动率的风险平价近似
- 单资产波动率：`sigma_i(t) = std(r_i(t-j)), j=0..vol_lookback-1`
- 原始权重：`w_i_raw(t) = 1 / max(sigma_i(t), eps)`
- 归一权重：`w_i(t) = w_i_raw(t) / sum(w_k_raw(t))`
- 组合波动率：`sigma_p(t) = std(sum(w_i(t) * r_i(t)))`
- 若 `target_vol > 0`，则缩放系数 `lambda(t) = target_vol / max(sigma_p(t), eps)`，最终权重 `w_i_final(t) = lambda(t) * w_i(t)`

#### 7.3.9 机器学习预测

策略类型：`StrategyType::MACHINE_LEARNING_SELECTION`

个性化参数合同：`MachineLearningSelectionStrategySpec`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `model_ref` | `ModelId` | 模型强类型 ID，沿用现有 `StrongId` 模式定义 |
| `feature_ids` | `vector<FeatureId>` | 使用的特征 ID 列表 |
| `top_n` | `CandidateCount` | 预测收益最高或概率最大的选股数量 |

公式口径：

当前代码阶段：只实现 `Pred(s, t)` 排序和前 `top_n` 排名输出，不实现 `allow_short=true` 下的双边候选生成。

- 特征向量：`X(s, t) = [feature_1(s, t), ..., feature_m(s, t)]`
- 模型输出：`Pred(s, t) = f_model(X(s, t))`
- 若模型是回归器，则 `Pred` 解释为未来收益预测值；若模型是分类器，则 `Pred` 解释为上涨概率或类别分数
- 排序规则：按 `Pred(s, t)` 从高到低排序，取前 `top_n`
- 若 `allow_short=true` 且模型支持双边排序，则可按 `Pred(s, t)` 最低的一组生成空头候选

#### 7.3.10 高频 / 订单流

策略类型：`StrategyType::ORDER_FLOW_IMBALANCE`

个性化参数合同：`OrderFlowImbalanceStrategySpec`

| 参数                    | 类型       | 说明                             |
| ----------------------- | ---------- | -------------------------------- |
| `depth_levels`        | `int`    | 使用的订单簿深度档数，如 5       |
| `imbalance_threshold` | `double` | 订单不平衡开仓阈值，如 0.3       |
| `max_hold_seconds`    | `int`    | 最大持仓时间（秒），超时强制平仓 |

公式口径：

当前代码阶段：只实现 `OFI(t)` 计算，不实现按 `imbalance_threshold` 开仓、按符号反转或 `max_hold_seconds` 平仓的策略行为。

- 买盘深度：`BidDepth(t) = sum(BidVolume_k(t)), k=1..depth_levels`
- 卖盘深度：`AskDepth(t) = sum(AskVolume_k(t)), k=1..depth_levels`
- 订单不平衡：`OFI(t) = (BidDepth(t) - AskDepth(t)) / max(BidDepth(t) + AskDepth(t), eps)`
- 开多条件：`OFI(t) >= imbalance_threshold`
- 开空条件：仅当 `allow_short=true` 时允许，条件为 `OFI(t) <= -imbalance_threshold`
- 平仓条件：`OFI` 符号反转或持仓时长达到 `max_hold_seconds`

#### 7.3.11 期权 / 波动率策略

策略类型：`StrategyType::VOLATILITY_SPREAD`

个性化参数合同：`VolatilitySpreadStrategySpec`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `underlying` | `SymbolId` | 标的资产强类型标识，直接复用现有引擎标的 ID |
| `option_chain_filter` | `OptionChainFilterSpec` | 结构化期权筛选合同，例如剩余到期天数区间、行权价距离区间 |
| `hv_window` | `int` | 历史波动率计算窗口，如 20 |
| `entry_spread_upper` | `double` | 当 IV-HV 高于此值时做空波动率，如 0.05 |
| `entry_spread_lower` | `double` | 当 IV-HV 低于此值时做多波动率，如 -0.05 |
| `delta_neutral` | `bool` | 是否保持 Delta 中性 |

公式口径：

当前代码阶段：只实现 `HV(t)`、`IV(t)`、`Spread(t)` 指标计算，不实现按 `entry_spread_upper`、`entry_spread_lower` 开平仓，也不实现 `delta_neutral` 和 `option_chain_filter` 的执行逻辑。

- 对数收益：`r(t) = ln(Close(t) / Close(t-1))`
- 历史波动率：`HV(t) = sqrt(252) * std(r_{t-j}), j=0..hv_window-1`
- 隐含波动率价差：`Spread(t) = IV(t) - HV(t)`
- 开空波动率条件：`Spread(t) >= entry_spread_upper`
- 开多波动率条件：`Spread(t) <= entry_spread_lower`
- 平仓条件：`entry_spread_lower < Spread(t) < entry_spread_upper`
- 若 `delta_neutral=true`，则建仓后需通过标的或对冲腿把组合净 Delta 调整到接近 0

### 7.4 落地方式草案

正式合同定义统一收敛在 [src/domain/strategies/include/StrategyDefinitionTypes.h](src/domain/strategies/include/StrategyDefinitionTypes.h#L1)。这里仅保留使用方式示例，不再在文档里重复定义第二份 `StrategyCommonConfig`。

```cpp
class IStrategy {
public:
	explicit IStrategy(const StrategyCommonConfig& commonCfg);
	virtual ~IStrategy() = default;
};
```

每个具体策略定义自己的个性配置结构体，并组合通用配置。

```cpp
class DoubleMovingAverageStrategy : public IStrategy {
public:
	DoubleMovingAverageStrategy(const StrategyCommonConfig& common,
					 const DoubleMovingAverageStrategySpec& spec)
		: IStrategy(common), spec_(spec) {}

private:
	DoubleMovingAverageStrategySpec spec_;
};
```

工厂统一组装通用配置和个性配置。

```cpp
factory.create(StrategyType::DOUBLE_MOVING_AVERAGE, commonConfig, specConfig);
```

目标：所有策略都有一致的通用部分，个性部分完全内聚在子类中，策略服务无需关心具体参数，整体结构保持纯净、可扩展且便于继续收敛为强类型合同。
