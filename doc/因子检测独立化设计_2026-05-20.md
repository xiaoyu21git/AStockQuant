# 因子检测独立化设计

## 1. 目标

本次改造只处理因子回测前的“因子检测 / support-map 检查”链路，目标如下：

- 将检测职责从 `FactorBacktestController` 中剥离，收敛到独立的 C++ 类。
- `FactorBacktestController` 只保留 UI 状态、异步调度、结果回填，不再承载检测规则与持久化细节。
- 检测结果按“特定缓存上下文”持久化，同一缓存上下文只做一次完整检测。
- 第二次打开时只分析当前因子是否新增或定义发生变化；未变化的因子直接复用持久化结果。
- 新的检查结果要合并回原持久化结果，而不是覆盖整份历史检测结果。

## 2. 范围

本次只改造以下能力：

- `buildFactorSupportMap()` 同步检测
- `requestFactorSupportMapAsync()` 异步检测内部调用链
- 检测结果持久化与增量复用

本次不改造以下能力：

- 回测执行器 `FactorBacktestExecutor`
- QML 展示合同
- `supportInfo` 的对外字段结构

## 3. 目标结构

### 3.1 新类

新增独立类：`FactorDetectionService`

放置位置：

- 头文件：`src/ui/bridge/include/FactorDetectionService.h`
- 实现：`src/ui/bridge/src/FactorDetectionService.cpp`

### 3.2 职责边界

`FactorDetectionService` 负责：

- 解析检测请求
- 解析检测运行时依赖
- 计算缓存上下文 scope key
- 加载与保存检测持久化文件
- 比对因子定义指纹
- 识别新增因子与变更因子
- 只对待检测因子执行真实检测
- 将新结果合并进既有持久化结果
- 输出当前请求对应的 `supportMap`

`FactorBacktestController` 只负责：

- 收集当前页面参数
- 调用 `FactorDetectionService`
- 更新 `m_lastSupportMapScopeKey`、`m_lastSupportMapCacheKey`
- 在异步线程中分发检测任务
- 发出 Qt signal

## 4. C++ 类接口

### 4.1 公共数据结构

`FactorDetectionService` 暴露以下结构：

- `RuntimeContext`
  - `database`
  - `dataChecker`
  - `instanceManager`
  - `errorMessage`

- `Request`
  - `factorIds`
  - `startDate`
  - `endDate`
  - `cacheSnapshot`
  - `dataSourceMode`
  - `selectedDatasetId`

- `Overrides`
  - `requiredWarmupTradingDaysOverrideForTests`
  - `resolveInstanceIdOverrideForTests`
  - `instanceInfoOverrideForTests`
  - `factorInstanceOverrideForTests`
  - `cacheFilePathOverrideForTests`

- `DetectionResult`
  - `supportMap`
  - `scopeKey`

### 4.2 方法

`FactorDetectionService` 提供以下公共方法：

- `resolveRuntimeContext(...)`
  - 统一构建检测所需运行时依赖

- `buildSupportMap(...)`
  - 执行完整检测流程，返回 `DetectionResult`

- `persistentCacheFilePath(...)`
  - 返回当前数据源/缓存集对应的持久化文件路径

## 5. 持久化模型

### 5.1 文件维度

检测结果仍然按“数据集绑定文件”存储，即单个缓存集绑定单个文件。

原因：

- 删除缓存集时可以直接清理对应检测文件
- 避免多个缓存集共用一份大文件造成相互污染

### 5.2 scope 维度

同一数据集下，不同检测上下文用 `scopeKey` 区分。`scopeKey` 由以下信息计算：

- `dataSourceMode`
- `selectedDatasetId`
- `startDate`
- `endDate`
- 归一化后的 `cacheSnapshot`

### 5.3 文件结构

持久化文件结构定义为：

```json
{
  "version": 2,
  "scopes": {
    "<scopeKey>": {
      "updatedAt": "2026-05-20T00:00:00Z",
      "factors": {
        "factor_a": {
          "definitionFingerprint": "...",
          "checkedAt": "2026-05-20T00:00:00Z",
          "supportInfo": {
            "factorId": "factor_a",
            "instanceId": "factor_a",
            "runtimeType": 1,
            "supported": true,
            "category": "supported",
            "reason": "字段与历史窗口检查通过",
            "requiredFields": ["close"],
            "missingFields": [],
            "sourceTable": 1
          }
        }
      }
    }
  }
}
```

### 5.4 持久化策略

与旧实现不同，新实现持久化“整份检测结果”，不仅持久化 `supported=true` 的通过项，也持久化失败项。

这样第二次打开时：

- 未变化因子直接复用既有结果
- 新增因子执行检测后追加到 `factors`
- 定义发生变化的因子重新检测并覆盖该因子的旧条目
- 其他未变化因子保持不动

## 6. 增量检测规则

### 6.1 需要重新检测的情况

只有以下情况才重新检测：

- 当前请求中出现了持久化文件里不存在的新因子
- 当前因子的 `definitionFingerprint` 与持久化值不同
- 当前因子缺少可用 `supportInfo`
- 当前检测运行时初始化失败，需要返回运行时失败结果

### 6.2 直接复用的情况

以下情况直接复用：

- 因子已存在于当前 `scopeKey`
- `definitionFingerprint` 未变化
- 持久化条目中存在完整 `supportInfo`

## 7. 检测结果合同

对外仍保持现有 `supportInfo` 合同，不修改字段名：

- `factorId`
- `instanceId`
- `runtimeType`
- `supported`
- `category`
- `reason`
- `requiredFields`
- `missingFields`
- `sourceTable`

这样 QML 和预检展示逻辑无需改口径。

## 8. Controller 接入方式

`FactorBacktestController` 改造为组合 `FactorDetectionService`：

- 构造时创建 `m_factorDetectionService`
- `buildFactorSupportMap()` 只组装 `Request`/`Overrides`/运行时上下文并调用服务
- `requestFactorSupportMapAsync()` 在线程池中调用同一个服务实例的同步检测方法

Controller 中删除的旧职责：

- 检测快照构建细节
- 检测缓存文件读写
- 因子定义指纹比对
- 检测结果合并逻辑

## 9. 测试要求

必须保留并扩展以下行为：

- 同一缓存上下文第二次打开时不重复检查未变化因子
- 新增因子只补新增项
- 变更因子只重查变更项
- 删除缓存集时删除对应检测持久化文件
- 失败项也会进入持久化结果，并在未变化时被直接复用

## 10. 实现约束

- 不再使用 controller 内部大段 free function 承载检测流程
- 检测流程必须收口到 `FactorDetectionService` 的类方法
- 不引入旧逻辑与新逻辑双实现并存
- 不修改现有 QML 对 `supportInfo` 的读取字段
