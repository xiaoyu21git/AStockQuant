## 2. 目标 PostgreSQL 结构

### 2.1 数据库名

`astock_quant` → `astock_quant`（不变）

### 2.2 Schema 设计

```
astock_quant
├── market          — 行情数据 (daily_bar, weekly_bar, monthly_bar, minute_bar)
├── financial       — 财务数据 (financial_indicator_daily)
├── reference       — 参考数据 (symbol_info, index_info, index_constituents, industry_classification)
├── factor          — 因子数据 (factor_instance, factor_template, factor_category, factor_parameter, factor_tags, factors, factor_combination, user_factor)
├── strategy        — 策略数据 (strategy, backtest_config, backtest_result, backtest_summary, strategy_backtest_results)
├── trading         — 交易数据 (trade_record, daily_position, daily_equity_snapshots)
├── cleaning        — 清洗数据 (cleaning_tasks, cleaning_results, cleaned_dataset, cleaned_dataset_items, cleaned_daily_bar)
├── data_source     — 数据源 (data_source_type, data_update_log, adjustment_factor, alternative_data, news_sentiment, policy_data, derivatives_data)
└── system          — 系统 (system_event, exchange_info)
```

### 2.3 数据类型映射

| MySQL | PostgreSQL |
|---|---|
| `bigint unsigned` | `bigint` (或 `bigint CHECK (>= 0)`) |
| `int unsigned` | `integer` (或 `integer CHECK (>= 0)`) |
| `smallint unsigned` | `smallint` |
| `tinyint` | `smallint` |
| `varchar(n)` | `varchar(n)` 或 `text` |
| `decimal(p,s)` | `numeric(p,s)` |
| `date` | `date` |
| `datetime/timestamp` | `timestamp` |
| `json` | `jsonb` |
| `enum(...)` | `varchar` + `CHECK` 约束 |
| `mediumtext` | `text` |
| `AUTO_INCREMENT` | `SERIAL` / `BIGSERIAL` / `GENERATED BY DEFAULT AS IDENTITY` |

### 2.4 索引策略

- MySQL 的 `UNIQUE KEY` → PostgreSQL `UNIQUE CONSTRAINT`
- 复合索引直接平移
- `daily_bar(symbol, trade_date)` UNIQUE → PG 同名约束
- `financial_indicator_daily(symbol_id, trade_date, report_date)` → 同名索引

```bash
# daily_bar — 1100万行，分批次

  --where="trade_date >= '2020-01-01'" \
  --compatible=postgresql --no-create-info \
```

## 4. 当前表结构缺陷与重构方案（新增）

### 4.1 已发现的缺陷

| # | 缺陷 | 影响 | 重构方案 |
|---|---|---|---|
| 1 | **无 `trade_calendar` 表** | Python 脚本依赖外部 API 获取交易日历，缓存过期导致日期判断错 | 迁移时新建 `system.trade_calendar`，通过 `daily_bar` 的 `DISTINCT trade_date` 自动填充 |
| 2 | **`financial_indicator_daily` 用 `symbol_id` (int)** | 与 `daily_bar.symbol` (varchar) 不统一，JOIN 需要中间映射 | 统一为 `symbol varchar(20)`，添加 FK → `symbol_info.symbol` |
| 3 | **`daily_bar_optimized` 冗余表** | 381 万行，671MB，与 `daily_bar` 数据重复 | **不迁**。`v_daily_bar_wide` 改读 `daily_bar` |
| 4 | **`symbol_info` 无 `symbol_id` 列** | `v_daily_bar_wide` 引用 `si.symbol_id` 实际是 `id` 列，列名混乱 | 统一用 `symbol varchar(20)` 做主键 |
| 5 | **无外键约束** | symbol_info ↔ daily_bar ↔ financial_indicator_daily 的关系靠约定 | 迁移时添加 FK（见 4.2） |
| 6 | **所有表在一个 schema** | 40+ 张表平铺，职责不清 | 迁移时按 9 个 schema 分拆（market/financial/reference/factor/strategy/trading/cleaning/data_source/system） |
| 7 | **`cleaned_daily_bar` 视图含乱码** | `cleaning_notes` 列文本损坏 | 迁移时修正为正确中文 |
| 8 | **`data_availability_view` 用 `COUNT(0)`** | MySQL 接受，PG 不接受 | 改为 `COUNT(*)` |

### 4.2 外键与关系重构

迁移后在 PG 添加以下约束：

```sql
-- 行情 ↔ 标的
ALTER TABLE market.daily_bar
  ADD CONSTRAINT fk_daily_bar_symbol FOREIGN KEY (symbol) REFERENCES reference.symbol_info(symbol);

-- 财务 ↔ 标的（先改 symbol_id → symbol）
ALTER TABLE financial.financial_indicator_daily
  ADD COLUMN symbol varchar(20);
UPDATE financial.financial_indicator_daily fid
  SET symbol = (SELECT si.symbol FROM reference.symbol_info si WHERE si.id = fid.symbol_id);
ALTER TABLE financial.financial_indicator_daily
  DROP COLUMN symbol_id,
  ADD CONSTRAINT fk_financial_symbol FOREIGN KEY (symbol) REFERENCES reference.symbol_info(symbol);

-- 指数成分股 ↔ 指数信息
ALTER TABLE reference.index_constituents
  ADD CONSTRAINT fk_index_constituents_idx FOREIGN KEY (index_symbol) REFERENCES reference.index_info(symbol),
  ADD CONSTRAINT fk_index_constituents_stock FOREIGN KEY (stock_symbol) REFERENCES reference.symbol_info(symbol);

-- 策略 ↔ 回测
ALTER TABLE strategy.backtest_config
  ADD CONSTRAINT fk_backtest_config_strategy FOREIGN KEY (strategy_id) REFERENCES strategy.strategy(strategy_id);
ALTER TABLE strategy.backtest_summary
  ADD CONSTRAINT fk_backtest_summary_config FOREIGN KEY (config_id) REFERENCES strategy.backtest_config(config_id);

-- 交易日历（新表）
CREATE TABLE system.trade_calendar (
    trade_date  date PRIMARY KEY,
    is_trading  boolean DEFAULT true
);
INSERT INTO system.trade_calendar (trade_date)
SELECT DISTINCT trade_date FROM market.daily_bar ORDER BY trade_date;
```

## 5. 风险与回退

| 风险 | 影响 | 缓解 |
|---|---|---|
| `ON DUPLICATE KEY UPDATE` → `ON CONFLICT` 语义不完全等价 | 日线导入可能重复 | 第 5 步 Python 逐个验证 UPSERT |
| PG 连接池配置不当 | 启动连接失败 | 保留 MySQL 配置 1 周，快速回退 |
| JSON 类型函数差异 (JSON_EXTRACT) | 策略查询失效 | 提前验证 factor_instance.full_config 读取 |
| libpq 异步通知差异 | 事件系统可能延迟 | 影响范围小，只在 `JujinApi` 用到 |

回退方案：
1. `git revert` C++ 改动
2. 改回 `DatabaseConnectionManager` 指向 MySQL
3. 重启应用
