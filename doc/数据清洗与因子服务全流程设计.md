# 数据清洗与因子服务全流程设计

## 1. 概述

本文档详细描述了AStockQuantEngine系统中数据清洗和因子服务的完整流程设计。系统目前面临的问题是：数据清洗完成后只保存在缓存中，无法持久化；因子服务不稳定；需要建立完整的数据存取流程。

## 3. 数据清洗流程

### 3.1 清洗流程设计

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  原始数据   │───▶│  数据清洗   │───▶│  清洗结果   │───▶│  持久化    │
│  (缓存/DB)  │    │  (引擎)     │    │  (缓存)     │    │  (数据库)  │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
       │                   │                   │                  │
       └───────────────────┼───────────────────┘                  │
                           │                                      │
                    ┌─────────────┐                         ┌─────────────┐
                    │  清洗规则   │                         │  清洗任务   │
                    │  (可配置)   │                         │  (元数据)   │
                    └─────────────┘                         └─────────────┘
```

### 3.2 清洗规则类型

1. **时间范围过滤** - 过滤指定时间范围外的数据
2. **价格过滤** - 过滤异常价格数据
3. **成交量过滤** - 过滤异常成交量数据
4. **完整性检查** - 检查必要字段
5. **异常值检测** - 使用IQR方法检测异常值
6. **重复数据删除** - 基于唯一键删除重复数据
7. **格式验证** - 验证数据格式
8. **自定义过滤** - 用户自定义过滤规则

### 3.3 持久化设计

#### 3.3.1 数据库表结构

```sql
-- 清洗任务表
CREATE TABLE cleaning_tasks (
    task_id INT PRIMARY KEY AUTO_INCREMENT,
    task_uuid VARCHAR(36) UNIQUE NOT NULL,
    symbol VARCHAR(20),
    start_date DATE,
    end_date DATE,
    original_record_count INT DEFAULT 0,
    cleaned_record_count INT DEFAULT 0,
    removed_record_count INT DEFAULT 0,
    data_quality_score DECIMAL(5,2),
    status VARCHAR(20) DEFAULT 'PENDING',
    start_time DATETIME,
    end_time DATETIME,
    duration_seconds INT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 清洗结果表
CREATE TABLE cleaning_results (
    result_id INT PRIMARY KEY AUTO_INCREMENT,
    task_id INT NOT NULL,
    symbol VARCHAR(20),
    trade_date DATE,
    open DECIMAL(10,4),
    high DECIMAL(10,4),
    low DECIMAL(10,4),
    close DECIMAL(10,4),
    volume BIGINT,
    turnover DECIMAL(15,2),
    is_cleaned BOOLEAN DEFAULT TRUE,
    FOREIGN KEY (task_id) REFERENCES cleaning_tasks(task_id),
    INDEX idx_task_id (task_id),
    INDEX idx_symbol_date (symbol, trade_date)
);
```

```cpp
class FactorService {
```

#### 4.2.2 缓存策略

1. **内存缓存** - 短期缓存，提高重复访问性能
2. **磁盘缓存** - 中期缓存，避免重复计算
3. **数据库持久化** - 长期存储，支持历史查询

#### 4.2.3 性能优化

1. **批量计算** - 支持批量股票因子计算
2. **并行计算** - 利用多核CPU并行计算
3. **增量计算** - 只计算新增数据

## 5. 数据存取流程

### 5.1 完整数据流

```
┌─────────────────────────────────────────────────────────────────────┐
│                           数据源 (外部API)                           │
└──────────────────────────────────┬──────────────────────────────────┘
                                   │
                                   ▼
┌─────────────────────────────────────────────────────────────────────┐
│                         DataFetchController                         │
│                    (数据获取、初步清洗、缓存)                        │
└──────────────────────────────────┬──────────────────────────────────┘
                                   │
                                   ▼
┌─────────────────────────────────────────────────────────────────────┐
│                         DataCleaningEngine                          │
│                    (深度清洗、规则应用、质量评估)                     │
└──────────────────────────────────┬──────────────────────────────────┘
                                   │
                                   ▼
┌─────────────────────────────────────────────────────────────────────┐
│                      DataCleaningPersistence                        │
│                    (数据库持久化、任务管理)                          │
└──────────────────────────────────┬──────────────────────────────────┘
                                   │
                                   ▼
┌─────────────────────────────────────────────────────────────────────┐
│                         CleanedDataCache                            │
│                    (内存缓存、快速访问)                              │
└──────────────────────────────────┬──────────────────────────────────┘
                                   │
                                   ▼
┌─────────────────────────────────────────────────────────────────────┐
│                         FactorService                               │
│                    (因子计算、缓存、持久化)                          │
└──────────────────────────────────┬──────────────────────────────────┘
                                   │
                                   ▼
┌─────────────────────────────────────────────────────────────────────┐
│                         BacktestEngine                              │
│                    (回测计算、结果存储)                              │
└─────────────────────────────────────────────────────────────────────┘
```

### 5.2 数据一致性保证

1. **事务处理** - 数据库操作使用事务保证一致性
2. **幂等性** - 重复操作不会产生副作用
3. **数据版本控制** - 支持数据版本管理和回滚
4. **完整性检查** - 数据写入前后进行完整性验证

## 7. 关键技术点

### 7.1 数据库连接池

使用`astock::database::ConnectionPool`管理数据库连接，提高性能和资源利用率。

### 7.2 异步处理

使用Qt的信号槽机制和QFuture实现异步操作，避免阻塞UI线程。

### 7.3 内存管理

使用智能指针和RAII原则管理资源，避免内存泄漏。

### 7.4 错误恢复

实现完善的错误处理和恢复机制，确保系统稳定性。
