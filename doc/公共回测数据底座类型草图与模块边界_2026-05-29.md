# 公共回测数据底座类型草图与模块边界

## 1. 文档目标

本文档是 [策略回测与因子回测公共底座收敛方案_2026-05-29.md](策略回测与因子回测公共底座收敛方案_2026-05-29.md) 的阶段 1 细化稿。

它只解决三件事：

1. 公共底座要抽出哪些核心类型。
2. 这些类型分别归哪个模块所有。
3. 策略回测和因子回测分别应该站在底座的哪一层，不允许越界到哪里。

本文档故意不展开实现细节，也不讨论 UI、页面状态、研究结果展示。

## 2. 设计前提

### 2.1 当前代码里已经存在可抽取原型

当前公共底座原型散落在两处：

1. `FactorBacktestExecutor::CachedMarketIndex`
2. `FactorBacktestExecutor::ExecutionMarketContext`
3. `HistoricalView`
4. `CachedRowHistoricalView`
5. `DirectCachedHistoricalView`
6. `FactorBacktestCachedBarUtils`
7. `HistoricalMarketDataCache` 中少量已经被迫补进去的缓存集逐日语义

阶段 1 不是重新设计一套全新的市场数据层，而是把这些已经存在、已经被验证过的公共数据语义抽出来，重新归位。

### 2.2 公共底座必须以强类型为主口径

当前因子侧大量接口仍使用：

1. `std::string date`
2. `std::string symbol`
3. `std::string field`

这些字符串接口来自历史路径，不应继续成为新公共底座的主合同。

本次阶段 1 的原则是：

1. 公共底座主合同只认 typed id 和 typed enum。
2. 若阶段迁移期仍需要字符串适配，只允许放在因子模块边界内，不能进入公共底座主接口。
3. 不允许再新建第二套“typed 主接口 + string 主接口”并长期共存。

## 3. 建议模块拆分

建议新增独立模块：`src/domain/backtest_market/`

该模块只承载共享回测数据底座，不承载策略执行或因子研究逻辑。

建议目录：

```text
src/domain/backtest_market/
  include/
    BacktestMarketTypes.h
    BacktestMarketField.h
    BacktestMarketBar.h
    BacktestMarketUniverse.h
    BacktestMarketDataView.h
    BacktestMarketContext.h
    BacktestMarketContextBuilder.h
    BacktestMarketDatasetResolver.h
  src/
    BacktestMarketContextBuilder.cpp
    BacktestMarketDatasetResolver.cpp
    DirectBacktestMarketDataView.cpp
    ArrowBacktestMarketDataView.cpp
```

命名不是冻结决定，但边界必须保持：

1. `factor/` 不再拥有公共历史视图和逐日 universe 真源。
2. `backtest/strategy_engine/` 不再拥有公共缓存集逐日语义真源。
3. 真源只能在共享模块里出现一次。

## 4. 核心类型草图

### 4.1 基础类型层

基础类型层只承载与策略、研究都无关的 typed primitive：

```cpp
namespace domain::backtest_market {

using SymbolId = strategy_engine::SymbolId;
using TradingDayIndex = strategy_engine::TradingDayIndex;
using UniverseId = strategy_engine::UniverseId;
using DatasetId = strategy_engine::DatasetId;
using PriceValue = strategy_engine::PriceValue;
using ShareQuantity = strategy_engine::ShareQuantity;
using DataSourceMode = strategy_engine::DataSourceMode;

}
```

阶段 1 可以临时复用现有 typed wrapper，避免先引入第三套 id 类型。

但要明确：

1. 这些类型只是共享 typed primitive。
2. 不代表公共底座依赖策略执行语义。
3. 后续若要进一步中性化，可再把这些 wrapper 提升到更底层的 shared typed module。

### 4.2 字段标识层

当前 `HistoricalView` 的 `field` 使用字符串。新底座不应延续该设计。

建议引入 typed field 标识：

```cpp
namespace domain::backtest_market {

enum class MarketField : std::uint16_t {
    Open,
    High,
    Low,
    Close,
    Volume,
    AdjustClose,
    AdjustFactor,
    TurnoverRate,
    MarketCap,
    IndustryCode,
    PeTtm,
    Pb,
    NetProfit,
    OperatingCashFlow,
};

}
```

要求：

1. 公共底座主视图只接受 `MarketField`。
2. 字段字符串到枚举的映射只允许出现在桥接层或因子旧接口适配层。
3. 不允许把字符串字段名继续穿透到底座主流程。

### 4.3 单日行情条目

公共底座应直接拥有统一的单日行情结构，不再由策略和因子各自维护一份等价概念。

```cpp
namespace domain::backtest_market {

struct MarketBar final {
    SymbolId symbolId;
    TradingDayIndex tradingDay;
    PriceValue openPrice;
    PriceValue highPrice;
    PriceValue lowPrice;
    PriceValue closePrice;
    ShareQuantity volume;

    [[nodiscard]] bool isValid() const;
};

}
```

说明：

1. 这层只承载公共市场 bar 事实。
2. 不包含策略侧的 `FactorSnapshot`。
3. 不包含因子研究侧的 future return。

### 4.4 逐日 universe 视图

当前最需要收敛的是“某天到底有哪些 symbol 真正可用于回测”。

建议把该语义单独抽成公共结构：

```cpp
namespace domain::backtest_market {

struct DailyUniverse final {
    TradingDayIndex tradingDay;
    UniverseId universeId;
    strategy_engine::SymbolIdList symbols;

    [[nodiscard]] bool isValid() const;
};

struct MarketUniverseTimeline final {
    std::vector<TradingDayIndex> tradeDays;
    std::vector<DailyUniverse> universesByDay;

    [[nodiscard]] std::optional<DailyUniverse> resolve(TradingDayIndex tradingDay) const;
};

}
```

这层要承载两类事实：

1. 数据里存在该 symbol 当日有效 bar。
2. 在更高层过滤后，该 symbol 是否仍允许参与当日计算。

因此建议分两个视图，不要再混成一个字段：

```cpp
namespace domain::backtest_market {

struct MarketUniverseContext final {
    MarketUniverseTimeline rawAvailableUniverse;
    MarketUniverseTimeline allowedUniverse;
};

}
```

这样可以替代当前因子侧 `symbolsByDate` 与 `allowedSymbolsByDate` 的并存散写。

### 4.5 历史数据视图主接口

公共底座需要一个统一历史视图，但不应继续暴露 string symbol/date/field 作为主接口。

建议主接口如下：

```cpp
namespace domain::backtest_market {

struct ValuePoint final {
    TradingDayIndex tradingDay;
    double value{0.0};
};

class IMarketDataView {
public:
    virtual ~IMarketDataView() = default;

    [[nodiscard]] virtual bool hasField(MarketField field) const = 0;

    [[nodiscard]] virtual std::optional<double> getValue(SymbolId symbolId,
                                                         TradingDayIndex tradingDay,
                                                         MarketField field) const = 0;

    [[nodiscard]] virtual std::vector<ValuePoint> getSeries(SymbolId symbolId,
                                                            TradingDayIndex startDay,
                                                            TradingDayIndex endDay,
                                                            MarketField field) const = 0;

    [[nodiscard]] virtual strategy_engine::SymbolIdList getAvailableSymbols(
        TradingDayIndex tradingDay) const = 0;

    [[nodiscard]] virtual std::unordered_map<std::uint32_t, double> getCrossSection(
        TradingDayIndex tradingDay,
        MarketField field,
        const strategy_engine::SymbolIdList& symbols) const = 0;
};

}
```

注意：

1. 这里返回 `std::unordered_map<std::uint32_t, double>` 只是表达索引化截面值，实际实现时优先考虑 typed symbol key 或稠密数组视图。
2. 不应把字符串 symbol 再带回主接口。
3. 若性能要求更高，可进一步提供 batch cross section / batch time series typed 接口。

### 4.6 公共市场上下文

当前 `ExecutionMarketContext` 已经隐含了公共底座的雏形，但混入了因子执行器私有组织方式。

建议抽成：

```cpp
namespace domain::backtest_market {

struct PreparedMarketContext final {
    std::vector<TradingDayIndex> tradeDays;
    MarketUniverseContext universeContext;
    std::shared_ptr<IMarketDataView> marketDataView;
};

}
```

要求：

1. 这层只回答市场数据准备结果。
2. 不包含 factor instance、规则、执行器、研究指标。
3. 不包含策略结果或研究结果。

### 4.7 公共构建器接口

需要一个唯一入口负责把 data source、dataset、bars、timeline 组装成公共上下文。

```cpp
namespace domain::backtest_market {

struct BuildMarketContextRequest final {
    DataSourceMode mode{DataSourceMode::Raw};
    DatasetId datasetId;
    TradingDayIndex startDay;
    TradingDayIndex endDay;
    strategy_engine::SymbolIdList requestedSymbols;
};

class IMarketContextBuilder {
public:
    virtual ~IMarketContextBuilder() = default;

    [[nodiscard]] virtual PreparedMarketContext build(const BuildMarketContextRequest& request) const = 0;
};

}
```

这将成为后续唯一合法的“公共市场上下文准备入口”。

## 5. 模块职责边界

### 5.1 公共底座模块职责

共享模块只负责：

1. 数据集 bars 解析和标准化。
2. tradeDays 生成。
3. raw available universe 生成。
4. allowed universe 生成。
5. HistoricalView 等价 typed 视图。
6. Arrow 与 row data backend 适配。

共享模块绝不负责：

1. 因子计算。
2. future return 研究值生成。
3. IC、IR、group return。
4. 规则判断。
5. 调仓决策。
6. 订单执行。
7. 策略结果或研究结果组装。

### 5.2 因子模块职责

因子模块只负责：

1. 基于 `PreparedMarketContext` 驱动因子计算。
2. 研究指标计算。
3. batch 研究执行。
4. 旧 `HistoricalView` string 接口到 typed 视图的内部单向适配，若阶段迁移确实还需要。

注意：

1. 这个适配只允许是模块内过渡实现。
2. 不允许重新暴露成公共模块第二主接口。

### 5.3 策略模块职责

策略模块只负责：

1. 基于 `PreparedMarketContext` 或其窄适配切片做分层决策。
2. 从公共 universe 里拿当日可用 symbols。
3. 从公共视图里取 bar 和因子所需字段。
4. 执行规则、组合、订单、权益更新。

策略模块不再负责：

1. 构建缓存集逐日 universe 真源。
2. 自己维护第二套 HistoricalView 等价抽象。
3. 自己维护另一套 dataset 行过滤与标准化规则。

## 6. 与现有接口的映射关系

### 6.1 因子侧映射

当前类型到目标类型的映射：

1. `FactorBacktestExecutor::CachedMarketIndex` 只保留研究专属部分，公共 trade day 与 market availability 信息移入 `PreparedMarketContext`。
2. `FactorBacktestExecutor::ExecutionMarketContext` 拆分为 `PreparedMarketContext` 加因子研究执行态。
3. `HistoricalView` 的能力映射到 `IMarketDataView`，字符串主接口不进入公共底座。
4. `CachedRowHistoricalView`、`DirectCachedHistoricalView` 迁为共享模块实现类。

### 6.2 策略侧映射

当前类型到目标类型的映射：

1. `HistoricalMarketDataCache` 从“数据底座 + 切片器”收缩成“策略引擎窄适配器”，或者在后续直接删除。
2. `IMarketDataCache::sliceForDay()` 不再承担底座构建，只消费已构建好的 `PreparedMarketContext`。
3. 缓存集按日收缩 universe 的真源迁到 `MarketUniverseContext`。

## 7. 阶段 1 交付物建议

阶段 1 完成时，至少要有以下交付物：

1. 共享模块骨架。
2. `IMarketDataView` typed 主接口。
3. `PreparedMarketContext` typed 上下文。
4. `MarketUniverseContext` typed timeline 结构。
5. `FactorBacktestExecutor` 去内嵌定义的迁移计划清单。

阶段 1 明确不做：

1. 不做策略引擎执行语义改写。
2. 不做因子研究结果合同改写。
3. 不做 UI 改动。

## 8. 禁止事项

阶段 1 开始后，以下做法全部禁止：

1. 再向 `HistoricalMarketDataCache` 添加新的公共底座语义。
2. 再把 `HistoricalView` 字符串接口当作新共享模块主合同。
3. 再在策略侧单独发明 `symbolsByDate`、`allowedSymbolsByDate`、trade day timeline 真源。
4. 再把 future return、IC、IR 这类研究数据塞进共享市场上下文。
