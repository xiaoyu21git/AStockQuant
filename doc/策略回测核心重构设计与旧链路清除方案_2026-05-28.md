# 策略回测核心重构设计与旧链路清除方案

## 1. 文档目的

本文档是策略回测核心重构前的唯一执行依据。

本次重构必须满足以下硬约束：

1. 引擎核心禁止使用 Qt 代码。
2. 不允许保留旧代码兼容层、回退路径、双实现并存路径。
3. 实现新代码之前，必须先删除旧代码。
4. 删除旧代码时，必须同步删除与旧链路直接耦合的旧测试。
5. 在策略回测链路中，不允许继续使用字符串字面量作为键值访问口径。
6. 在策略回测链路中，不允许继续使用 QVariantMap、QVariantList、QJsonObject、std::map<std::string, ...> 作为业务合同真源。
7. 设计先行，代码实现必须严格按本文档执行，不允许边写边改方向。

本文档只描述当前事实、删除范围、目标架构和执行顺序，不包含任何兼容方案。

## 2. 当前实现事实

### 2.1 当前仓库中并存两套策略回测实现

当前仓库中同时存在以下两套策略回测相关实现：

1. 已删除的大部分旧生产链路残留事实。
2. 新 typed engine 骨架。

截至当前源码状态，旧策略回测生产入口对应的以下文件已经不在 src 树中：

1. 继续收敛边界层和应用层的单一路径实现。
2. 或者先完成阶段 C，再进入真正的生产运行时接线。

## 3. 当前实现中违反新约束的事实

### 3.1 Qt 已经深入旧引擎链路

以下事实已经确认：

1. StrategyBacktestController 以 QObject、QTimer、QVariantMap 为公共合同。
2. DatabaseFactorDataProvider 直接依赖 QDate、QString、QStringList、QVariantMap。
3. BacktestRuleTemplateEvaluator 大量依赖 QVariantMap、QString、QJsonDocument、QStringList。
4. BacktestExecutionRuntime 内部也直接操作 QString、QVariantMap。

这说明当前旧链路不是“Qt 在边界，核心纯 C++”，而是 Qt 已经穿透到 domain/backtest 核心执行路径。

### 3.2 字符串键访问已经成为旧链路的主要配置机制

以下字符串键访问形式已经进入当前策略回测主链路：

1. StrategyBacktestController 从 QVariantMap 中读取 startDate、endDate、factorOverlaySnapshot、executionPolicySnapshot 等键。
2. DatabaseFactorDataProvider 从 FactorService 返回的 QVariantMap 中读取 status、data、message、error 等键。
3. BacktestRuntimeAssembly 和 BacktestDecisionRuntime 通过 std::map<std::string, double> 与 std::map<std::string, std::string> 传递 strategyParams 和 strategyOptions。
4. BacktestDecisionRuntime 通过 factor_overlay_json 等字符串键驱动因子叠加逻辑。
5. BacktestRuleTemplateEvaluator 用大量字符串键解析模板 binding、scope、decision 字段。

这说明旧链路当前不是“类型合同驱动”，而是“字符串键驱动”。

### 3.3 旧链路内部职责耦合严重

以下耦合已经确认：

1. StrategyBacktestController 同时负责参数拆解、股票池解析、旧引擎调用、结果持久化和进度轮询。
2. FactorBacktestEngine 同时负责 bar flatten、运行时装配、执行循环和结果收尾。
3. BacktestRuntimeAssembly 同时负责统一交易核心初始化、规则模板运行时装配和因子叠加运行时装配。
4. BacktestDecisionRuntime 同时负责策略参数解析、行为归一化、指标计算、因子叠加缓存和排序。
5. BacktestExecutionRuntime 同时负责逐 bar 执行、规则模板事件处理、交易意图执行和权益曲线更新。
6. FactorBacktestService 同时负责任务管理、缓存、因子加载、分组、分组回测和 IC/IR 汇总。

这不符合本次重构要求的明确分层和纯核心设计。

## 6. 重构后唯一允许的目标架构

### 6.1 分层要求

重构后的策略回测必须严格分为以下层次：

1. UI 层。
2. UI 边界适配层。
3. application/backtest 编排层。
4. domain/backtest/strategy_engine 纯 C++ 核心层。
5. 数据访问适配层。

### 6.2 Qt 约束

重构后必须满足以下 Qt 边界要求：

1. domain/backtest/strategy_engine 中不得包含任何 Qt 头文件。
2. domain/backtest/strategy_engine 中不得出现 QObject、QString、QVariantMap、QJsonObject、QDate、QTimer 等类型。
3. application/backtest 中不得把 QVariantMap 作为策略回测业务真源。
4. UI 边界层只能做类型转换，不得保留业务规则。

### 6.3 合同约束

重构后必须满足以下合同约束：

1. 策略回测请求必须是强类型对象，不允许 QVariantMap 请求。
2. 策略回测结果必须是强类型对象，不允许 QVariantMap 结果真源。
3. 因子叠加配置必须是强类型结构，不允许 factor_overlay_json 之类的字符串键协议。
4. 规则检查输入输出必须是强类型结构，不允许 QVariantMap 模板快照驱动。
5. 运行时参数不得通过 std::map<std::string, double> 或 std::map<std::string, std::string> 传播。

### 6.4 字符串键禁令

本次重构后，策略回测链路中禁止以下做法：

1. 使用任意字符串字面量从 QVariantMap 取值。
2. 使用任意字符串字面量从 QJsonObject 取值。
3. 使用任意字符串字面量从 std::map<std::string, ...> 取值。
4. 使用 snake_case 或 camelCase 的字符串键做合同兼容。

如果某个外部系统仍然只提供字符串键协议，则必须在策略回测链路外部把它一次性转换为强类型对象后再进入应用层，不允许字符串协议穿透进策略回测链路。

## 7. 新核心设计要求

### 7.1 唯一核心

后续只允许保留一套策略回测核心，目标就是当前的 domain/backtest/strategy_engine。

旧的 FactorBacktestEngine、BacktestRuntimeAssembly、BacktestDecisionRuntime、BacktestExecutionRuntime 不允许保留，也不允许以适配器名义继续并存。

### 7.2 必须补齐的新生产实现

在旧代码删除后，必须为以下 typed 接口补齐生产实现：

1. IMarketDataCache
2. ILayerSelectionStrategy
3. IRuleChecker
4. IExecutionSimulator
5. IPortfolioOptimizer
6. IExecutionPolicyStrategy

这些实现都必须是纯 C++，不得依赖 Qt 类型。

### 7.3 新入口要求

新的生产入口必须满足以下要求：

1. UI 不再直接 new 旧引擎。
2. UI 只能调用 application/backtest 暴露的 typed 服务。
3. application/backtest 通过 BacktestRequestFactory 构造 typed BacktestRequest。
4. application/backtest 通过 StrategyBacktestEngineGateway 和 BacktestApplicationService 驱动新核心。
5. 异步调度只允许使用 ThreadedAsyncBacktestScheduler 这一条路径。

### 7.4 阶段 C 的唯一生产实现归属

阶段 C 完成后，六个纯域依赖必须只存在一条生产实现路径，不允许为同一接口并存两套生产实现。

唯一允许的实现归属如下：

1. IMarketDataCache 的生产实现放在数据访问适配层，不放在 domain/backtest/strategy_engine 目录内。
2. ILayerSelectionStrategy 的生产实现放在纯 C++ typed 核心侧。
3. IRuleChecker 的生产实现放在纯 C++ typed 核心侧。
4. IExecutionSimulator 的生产实现放在纯 C++ typed 核心侧。
5. IPortfolioOptimizer 的生产实现放在纯 C++ typed 核心侧。
6. IExecutionPolicyStrategy 的生产实现放在纯 C++ typed 核心侧。

阶段 C 的第一版只允许定义以下唯一生产类：

1. HistoricalMarketDataCache：唯一的市场数据缓存适配器，实现 IMarketDataCache。
2. CanonicalLayerSelectionStrategy：唯一的选层策略，实现 ILayerSelectionStrategy。
3. CanonicalRuleChecker：唯一的规则检查器，实现 IRuleChecker。
4. CanonicalExecutionSimulator：唯一的执行模拟器，实现 IExecutionSimulator。
5. CanonicalPortfolioOptimizer：唯一的组合优化器，实现 IPortfolioOptimizer。
6. CanonicalExecutionPolicyStrategy：唯一的执行策略，实现 IExecutionPolicyStrategy。

这里的“唯一”含义如下：

1. 第一版生产代码中，不允许再做同级的 Standard、Default、Legacy、Compat、V2 等并列实现。
2. 如果某个接口内部需要多算法，只允许在该唯一生产类内部再按 typed 枚举和 typed 值对象分发。
3. 不允许通过字符串、QVariantMap、配置键名或 UI 传参在组合根层选择不同实现。

### 7.5 阶段 D 的唯一组合根

阶段 D 不允许由 StrategyService、StrategyBacktestRequestAdapter 或任何 UI 边界对象直接 new 六个依赖实现。

阶段 D 必须先建立唯一组合根：StrategyBacktestRuntimeHost。

该组合根是唯一允许持有完整运行时对象图的类，负责一次性装配如下对象：

1. HistoricalMarketDataCache
2. CanonicalLayerSelectionStrategy
3. CanonicalRuleChecker
4. CanonicalExecutionSimulator
5. CanonicalPortfolioOptimizer
6. CanonicalExecutionPolicyStrategy
7. StrategyBacktestEngine
8. StrategyBacktestEngineGateway
9. ThreadedAsyncBacktestScheduler
10. BacktestApplicationService
11. CanonicalBacktestRequestFactory
12. StrategyBacktestEntryService

组合根必须满足以下约束：

1. 只能存在一份生产实例，不允许每次点击回测时重新构造整套运行时图。
2. 只能通过构造注入和 RAII 持有依赖，不允许 service locator、全局裸指针和隐式静态可变状态。
3. 不允许把 Qt 对象作为组合根成员。
4. 不允许把 UI 生命周期绑定到引擎内部对象生命周期。

新的唯一生产调用路径固定为：

1. StrategyService 只向组合根索取 typed 服务，不自行装配运行时。
2. StrategyBacktestRequestAdapter 只负责边界解析和 typed 投影。
3. StrategyBacktestEntryService 作为唯一应用入口，同时承担 buildRequest、run、progress、tryCollect、cancel。
4. BacktestApplicationService 只负责运行与异步调度，不再承担组合根职责。
5. ThreadedAsyncBacktestScheduler 只负责任务执行、进度、取消和收口，不反向知道 UI。

因此，阶段 D 完成后的目标不是 `StrategyService::strategyBacktestApplicationService()` 返回某个临时对象，而是 `StrategyService` 只持有组合根暴露出的稳定 typed 服务引用。

### 7.6 对象生命周期与所有权规则

策略回测新链路的生命周期只能分为以下四层：

1. 进程级生命周期。
2. 调用级生命周期。
3. 任务级生命周期。
4. 单次执行级生命周期。

各层定义如下：

1. StrategyBacktestRuntimeHost 属于进程级生命周期，按需惰性初始化一次，直到应用退出才销毁。
2. HistoricalMarketDataCache 属于进程级生命周期，由组合根独占持有，不允许在每次回测中重建缓存对象。
3. CanonicalLayerSelectionStrategy、CanonicalRuleChecker、CanonicalExecutionSimulator、CanonicalPortfolioOptimizer、CanonicalExecutionPolicyStrategy 属于进程级生命周期，由组合根持有。
4. StrategyBacktestEngine、StrategyBacktestEngineGateway、ThreadedAsyncBacktestScheduler、BacktestApplicationService、CanonicalBacktestRequestFactory、StrategyBacktestEntryService 属于进程级生命周期，由组合根按依赖顺序持有。
5. StrategyBacktestRunContext、StrategyBacktestEntrySpec、BacktestRunOverrides、BacktestRequest、StrategyAggregate 归属于调用级生命周期，每次请求单独创建，不得跨请求缓存可变对象。
6. ThreadedAsyncBacktestScheduler 内部的 task entry、progress sink、cancellation observer 归属于任务级生命周期，由一次异步提交创建并在 collect 或销毁时收口。
7. BacktestRuntimeSession 归属于单次执行级生命周期，只允许存在于 StrategyBacktestEngine::execute 内部，不允许泄漏到组合根、UI 或缓存层。

所有权规则固定如下：

1. 组合根对生产对象图拥有唯一所有权。
2. 组合根向外只暴露引用或非拥有指针，不转移运行时所有权。
3. 组合根外部禁止保存六个核心依赖实现的 owning 指针。
4. StrategyService 不拥有 BacktestApplicationService，也不拥有 ThreadedAsyncBacktestScheduler。
5. StrategyBacktestRequestAdapter 不拥有 StrategyBacktestEntryService，也不缓存运行时对象图。

销毁规则固定如下：

1. 组合根销毁前必须先让 ThreadedAsyncBacktestScheduler 完成任务收口。
2. 异步任务收口完成后，才能按反向依赖顺序销毁 BacktestApplicationService、gateway、engine 和六个生产依赖。
3. 不允许让 UI 侧 QObject 析构顺序决定引擎主干对象是否安全收尾。

### 7.7 当前代码向目标组合根的收敛要求

从当前代码状态过渡到目标状态时，只允许按以下收敛顺序推进：
