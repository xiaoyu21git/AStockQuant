# 策略服务与QML交互桥接重定义方案（评审稿）

## 1. 目标

本方案定义两类新组件，并严格分责：

1. 策略应用服务类：负责策略的增删改查、启动、停止，以及与数据层交互将可视化策略配置持久化到数据库。
2. 策略列表模型类：单独作为 QAbstractListModel 子类，只负责渲染数据，不做业务计算、不做数据库操作、不做启动停止。

## 2. 设计原则

1. 单一职责：服务类只做业务编排，模型类只做展示适配。
2. Typed-only 主干：C++ 内部流程优先用枚举、值类型、结构体，字符串仅用于 QML 展示和错误边界。
3. 无兼容回退：只保留新合同字段，缺失关键字段直接失败。
4. 明确边界：QML 不直接触库，统一通过服务类调用。
5. 可测性：服务类可单测，模型类可用假数据做渲染测试。

## 3. 新类清单（建议命名）

1. StrategyBridge

   - 类型：QObject
   - 角色：QML 与领域层/仓储层之间的应用服务门面
2. StrategyListModel

   - 类型：QAbstractListModel
   - 角色：只渲染策略列表行数据

说明：

- 你当前已清空老解析器后，新的桥接入口由 StrategyBridge 对外暴露。
- StrategyListModel 不持有数据库连接，不依赖 RuntimeCoordinator。

## 4. 领域与边界对象（强制）

### 4.1 单一类型来源

桥接层必须以 [src/domain/strategies/include/StrategyDefinitionTypes.h](src/domain/strategies/include/StrategyDefinitionTypes.h) 为唯一类型来源，禁止桥接层自行发明平行类型口径。

### 4.2 桥接层必须使用的类型

1. 策略标识：`domain::strategies::StrategyUuid`（项目自定义 UUID）
2. 策略类型：`domain::strategies::StrategyType`
3. 因子标识列表：`std::vector<domain::strategies::FactorId>`
4. 规则标识列表：`std::vector<domain::strategies::RuleId>`
5. 策略名称、策略描述：允许字符串（`std::string` 或桥接边界转换后的等价字符串类型）

### 4.3 桥接请求结构合同（示意）

1. `BridgeUpsertRequest`
2. 字段：
   `strategyId: domain::strategies::StrategyUuid`
3. 字段：
   `hasStrategyId: bool`
4. 字段：
   `strategyName: string`
5. 字段：
   `description: string`
6. 字段：
   `strategyType: domain::strategies::StrategyType`
7. 字段：
   `factorIds: std::vector<domain::strategies::FactorId>`
8. 字段：
   `ruleIds: std::vector<domain::strategies::RuleId>`

### 4.4 明确禁止项

1. 禁止在桥接内部使用 `QVector<qulonglong>` 承载因子/规则 ID。
2. 禁止在桥接内部以 `qulonglong` 代替 `StrategyUuid` 表示策略主键。
3. 禁止将未转换的 `QVariantMap`、`QString` 业务字段继续向下层透传。
4. 禁止字符串兼容键、别名键、旧字段回填。

### 4.5 QML 边界说明

1. QML 输入可仍为 `QVariantMap/QVariantList`。
2. 仅允许在桥接入口做一次解析转换。
3. 解析完成后，下游只允许强类型结构与领域类型。

### 4.6 英文参数名释义（桥接合同基线）

本节用于明确“这些英文都表示什么”。桥接层只认以下固定名称；未列出的键一律视为非法输入。

#### 4.6.1 顶层 payload 元数据键

1. `strategyId`：策略业务主键（UUID）。
2. `strategyName`：策略名称。
3. `description`：策略描述。
4. `strategyType`：策略类型枚举索引。
5. `factorIds`：因子 ID 列表。
6. `ruleIds`：规则 ID 列表。
7. `parameters`：策略个性化参数对象（仅允许白名单子键）。
8. `statusIndex`：策略生命周期状态索引。
9. `assetTypeIndex`：资产类型索引。
10. `timeFrameIndex`：时间框架索引。

#### 4.6.2 parameters 个性化参数键

1. `selectedStrategyTypeIndex`：前端选中的策略类型索引。
2. `strategyBehaviorKind`：策略行为类型索引。
3. `factorImportContext`：因子导入上下文对象。
4. `factor_overlay`：因子叠加配置对象。
5. `rule_profile`：规则画像/规则概要对象。
6. `rule_composer_state`：规则编排器状态对象。
7. `rule_template_bindings`：规则模板绑定关系对象。
8. `backtest_settings`：回测设置对象。
9. `backtest_runtime`：回测运行时设置对象。
10. `advanced_options`：高级选项对象。
11. `optimization_method`：优化方法标识。
12. `tags`：标签列表。
13. `assetTypeIndex`：参数域内资产类型索引。
14. `timeFrameIndex`：参数域内时间框架索引。

#### 4.6.3 禁止下传字段（收到即失败）

1. `strategyCode`：历史策略编码字段，禁止桥接下传。
2. `version`：版本字符串字段，禁止桥接下传。
3. `author`：作者字段，禁止桥接下传。
4. `performanceMetrics`：性能统计对象，禁止桥接下传。
5. `engineStrategyId`：引擎侧 ID 字段，禁止桥接下传。

#### 4.6.4 单一命名规则

1. 同一语义只允许一个固定名称，不允许别名键。
2. 不做旧字段兼容、回填或同义映射。
3. 仅允许在桥接入口做一次解析，解析后只传 typed 结构。

#### 4.6.5 不包含在通用参数中的内容（强制）

1. 风险参数（如最大持仓比例、最大回撤等）
- 归属规则服务配置，通过 `RuleConfig` 与具体规则 ID 绑定。
- 策略只声明依赖规则，风险参数随规则存储。

2. 算法参数（如均线周期、RSI 阈值等）
- 由具体策略子类自行定义（如 `TrendStrategyParams`）。
- 通过 `updateParameters(void*)` 多态接口更新。

3. 运行时状态（当前持仓、历史信号等）
- 仅属于策略对象私有成员。
- 不暴露于通用参数，也不写入持久化存储。

4. 时间戳（创建时间、修改时间）
- 当前不作为通用参数强制项。
- 需要时按场景显式扩展。

## 5. StrategyBridge 设计

### 5.1 责任

1. createStrategy：创建策略并落库。
2. updateStrategy：更新策略定义与可视化配置并落库。
3. deleteStrategy：删除策略并清理关联运行态记录。
4. getStrategy：按 id 读取单条。
5. listStrategies：读取列表并推送给模型。
6. startStrategy：启动策略。
7. stopStrategy：停止策略。
8. saveVisualConfig：单独保存页面可视化配置。

### 5.2 建议属性

1. busy: bool
2. lastErrorMessage: QString（仅展示）
3. selectedStrategyId: QString（QML 展示边界）

### 5.3 建议信号

1. strategiesChanged
2. strategyCreated(id)
3. strategyUpdated(id)
4. strategyDeleted(id)
5. strategyStarted(id)
6. strategyStopped(id)
7. operationFailed(code, message)

### 5.4 建议 QML 可调用方法（草案）

1. createStrategy(payload: QVariantMap) -> bool
2. updateStrategy(payload: QVariantMap) -> bool
3. deleteStrategy(strategyId: QString) -> bool
4. getStrategy(strategyId: QString) -> QVariantMap
5. listStrategies() -> QVariantList
6. startStrategy(strategyId: QString) -> bool
7. stopStrategy(strategyId: QString) -> bool
8. saveVisualConfig(strategyId: QString, visualConfig: QVariantMap) -> bool

说明：

- 返回 false 时必须同步触发 operationFailed。
- 不做旧字段映射，不做默认回填，不做多口径兼容。

### 5.5 类型收敛补充（强制）

1. `strategyId` 在桥接内部必须解析为 `domain::strategies::StrategyUuid`。
2. `strategyType` 在桥接内部必须解析为 `domain::strategies::StrategyType`。
3. `factorIds/ruleIds` 在桥接内部必须解析为 `std::vector<domain::strategies::FactorId/RuleId>`。
4. 桥接内部不得保留 `QVector<qulonglong>` 作为临时容器。
5. `strategyName/description` 之外的业务字段不得以字符串口径向下传递。

## 6. StrategyListModel 设计

### 6.1 严格职责

只做三件事：

1. 存储已准备好的行数据快照。
2. 提供 rowCount 和 data。
3. 提供 roleNames。

明确不做：

1. 不访问数据库。
2. 不启动/停止策略。
3. 不做增删改查业务。
4. 不做策略规则计算。

### 6.2 建议角色

1. IdRole
2. NameRole
3. StatusRole
4. StatusTextRole
5. UpdatedAtRole
6. RunningRole

### 6.3 建议更新接口

1. replaceAll(items)
2. upsertOne(item)
3. removeById(id)
4. clear()

数据来源仅允许 StrategyBridge 推送。

## 7. 持久化设计

### 7.1 表建议

1. strategies
   - strategy_id 主键
   - strategy_name
   - strategy_status
   - runtime_config_json
   - created_at
   - updated_at
2. strategy_visual_configs
   - strategy_id 主键（或唯一）
   - visual_config_json
   - version
   - updated_at
3. strategy_runtime_instances
   - instance_id 主键
   - strategy_id
   - runtime_status
   - started_at
   - stopped_at
   - last_error

### 7.2 事务建议

1. createStrategy：写 strategies 与 strategy_visual_configs 同一事务。
2. updateStrategy：更新主表与 visual 表同一事务。
3. deleteStrategy：删除策略与关联实例同一事务。

### 7.3 一致性约束

1. 启动前必须存在策略主记录。
2. 删除策略时若运行中，先 stop 再删。
3. visual_config_json 只存新合同字段。

## 8. 交互流程

### 8.1 创建策略

1. QML 提交可视化配置 payload。
2. StrategyBridge 校验并转换为强类型。
3. Repository 事务写库。
4. Service 刷新列表并通知 StrategyListModel replaceAll。

### 8.2 启动策略

1. QML 调用 startStrategy。
2. Service 读取策略与配置。
3. RuntimeCoordinator 启动实例。
4. Repository 更新状态为 Running。
5. Service 通知模型刷新。

### 8.3 停止策略

1. QML 调用 stopStrategy。
2. RuntimeCoordinator 停止实例。
3. Repository 更新状态为 Stopped。
4. Service 通知模型刷新。

## 9. 错误处理与可观测性

1. 每个失败都给出错误码与展示消息。
2. 错误码为枚举，消息仅展示。
3. 关键操作记录审计日志：create、update、delete、start、stop。
4. 严禁静默失败。

## 10. 线程模型建议

1. QML 调用入口在主线程。
2. 数据库读写在工作线程执行。
3. 回到主线程发信号与更新 StrategyListModel。
4. 模型修改必须在所属线程执行。

## 13. 待你审核的关键决策点

1. StrategyBridge 的 QML 方法返回风格：bool + signal，还是直接返回结果对象。
2. StrategyStatus 枚举集合是否按 Draft/Ready/Running/Stopped/Failed 固定。
3. visual_config_json 是否单表独立存储（推荐独立）。
4. 删除策略是否强制先 stop（推荐强制）。
5. 列表是否支持分页（当前先全量刷新）。
6. `BridgeUpsertRequest` 是否按本稿固定为领域同构 typed 合同（建议固定）。
