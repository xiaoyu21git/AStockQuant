## 一、架构适配

### 1.1 为什么必须独立新建

| | 现有因子 | SupplyChainFactor |
|---|---|---|
| 数据来源 | HistoricalView (个股日线) | **PG 直连** (商品价格/映射/排名) |
| `getDataRequirements()` | 返回字段列表 | **返回空 `{}`** |
| 截面分布 | 每股票不同 | **同映射组完全相同** |
| 标准化 | 用户可配置 | **强制关闭** (否则同组信号被抹平) |

### 1.2 PG 连接方式

- 使用已有基础设施 `DatabaseConnectionPool` (单例)
- `SupplyChainRepository` 无参构造，内部 `DatabaseConnectionPool::instance().getConnection()` 获取连接
- 不依赖 `NativePgConnectionPool` (可能存在但不直接使用)

### 1.3 核心架构

```
PostgreSQL (3表)
  → SupplyChainRepository (C++ 数据访问层)
    → SupplyChainFactor::calculate(date)  ← 不经过 HistoricalView
      → 直接返回 CalculationResult        ← 不经过 executeWithCommonParams
```

-- 映射关系表 (ref schema)
CREATE TABLE ref.product_stock_mapping (
    id SERIAL PRIMARY KEY,
    product_id VARCHAR(32) NOT NULL,
    symbol VARCHAR(16) NOT NULL,
    weight DECIMAL(10,4) DEFAULT 1.0,
    effective_date DATE NOT NULL,          -- 防未来函数核心字段
    expired_date DATE DEFAULT '2099-12-31',
    version VARCHAR(32) DEFAULT 'ckg_v1', -- 多数据源版本标识
    UNIQUE(product_id, symbol, effective_date)

-- 商品价格日表 (mkt schema)
CREATE TABLE mkt.commodity_prices_daily (
    product_id VARCHAR(32) NOT NULL,
    trade_date DATE NOT NULL,
    close_price DECIMAL(20,4) NOT NULL,
    PRIMARY KEY (product_id, trade_date)
);
CREATE INDEX idx_cpd_product_date ON mkt.commodity_prices_daily(product_id, trade_date);

-- 动态评分排名表 (alpha schema)
CREATE TABLE alpha.commodity_daily_rank (
    calc_date DATE NOT NULL,
    product_id VARCHAR(32) NOT NULL,
    rank_num INT NOT NULL,
    score NUMERIC(10,4) NOT NULL,
    PRIMARY KEY (calc_date, rank_num)
);

## 三、C++ 实现

### 3.1 Params

```cpp
struct SupplyChainFactor::Params : CommonParams {
    bool dynamicMode = true;          // 动态切换 Top-N
    std::string fixedProductId;       // 固定模式
    int lookbackWindow = 20;          // 动量窗口
    int maxHoldings = 3;              // Top-N
};
```

### 3.2 calculate() 关键逻辑

```cpp
CalculationResult SupplyChainFactor::calculate(const CalculationContext& context) {
    // 1. 查询 Top 池
    auto topProducts = m_repo->queryTopProducts(context.date, params_.maxHoldings);

    // 2-3. 查价格 → 算动量
    std::unordered_map<std::string, double> productMomentum;
    for (auto& p : topProducts) {
        auto prices = m_repo->queryPriceSeries(p.productId, context.date, params_.lookbackWindow);
        if (prices.size() >= 2)
            productMomentum[p.productId] = prices.back() / prices.front() - 1.0;
    }

    // 4-5. 查映射 → 赋值
    std::unordered_map<std::string, double> values;
    for (auto& [pid, momentum] : productMomentum) {
        auto mappings = m_repo->queryStockMappings(pid, context.date);
        for (auto& m : mappings)
            values[m.symbol] = momentum * m.weight;
    }

    // 6. 返回裸值，标记标准化已跳过
    CalculationResult result;
    result.date = context.date;
    result.values = std::move(values);
    result.dataStatus.availability = DataAvailability::AVAILABLE;
    result.metadata.set("skipStandardization", json_helper::toJsonValue(true));
    result.metadata.set("reason", json_helper::toJsonValue("同组股票值相同，标准化会抹平信号"));
    return result;  // 不经过 executeWithCommonParams
}
```

### 3.3 FactorEngine 适配

```cpp
// FactorEngine::computeOneDay 中增加判断
auto cr = factor.calculate(ctx);
if (cr.metadata.has("skipStandardization") && cr.metadata.get("skipStandardization").asBool()) {

```

## 四.五、MultiFactorStrategy 适配

### 4.5.1 问题

传导链因子的值按商品分组：同组股票因子值完全相同。MultiFactorStrategy 的 `normalizeCrossSectional()` 做全市场 Z-score：

```
传导链原始值: 锂矿股×30全=0.05, 铜矿股×15全=0.03, 石油股×8全=0.08
Z-score 后:   锂矿≈0, 铜矿≈0, 石油≈+1
              → 30只锂矿股因数量多被压到均值附近, 信号丢失
```

### 4.5.2 方案

`MultiFactorConfig` 新增按因子跳过归一化的配置：

```cpp
// MultiFactorConfig 新增字段
std::unordered_set<std::string> skipNormalizeFactorIds;  // 不做 Z-score 的因子 ID
```

`normalizeCrossSectional()` 中跳过这些因子：

```cpp
// 只对需要归一化的因子计算统计量
if (m_config.skipNormalizeFactorIds.count(snap.factorId)) {
    // 直接使用原始值, 不计算 mean/stdev
    valuesBySymbol[snap.symbolId][snap.factorId] = snap.factorValue;
    continue;
}
// 否则走正常 Z-score 流程...
```

`computeCompositeScores()` 中原始值直接参与加权：

```cpp
// 对 skip 因子, 原始值直接乘权重, 不做 Z-score
if (m_config.skipNormalizeFactorIds.count(fid)) {
    composite += weight * zScore;  // zScore 此处是原始值
} else {
    composite += weight * zScore;  // zScore 是归一化后的值
}
```

### 4.5.3 配置传递

`fromDb()` 中根据因子类型自动标记：

```cpp
// 读取 factor_overlay.allocations 中的每个因子
// 如果因子类型是 SUPPLY_CHAIN (18), 自动加入 skipNormalizeFactorIds
for (const auto& fw : params.factorWeights) {
    auto factorType = resolveFactorType(fw.factorId);
    if (factorType == FactorType::SUPPLY_CHAIN)
        mfConfig.skipNormalizeFactorIds.insert(fw.factorId);
}
```

### 4.5.4 改动文件

| 文件 | 改动 |
|------|------|
| `MultiFactorStrategy.h` | `MultiFactorConfig` 加 `skipNormalizeFactorIds` |
| `MultiFactorStrategy.cpp` | `normalizeCrossSectional` 和 `computeCompositeScores` 各加 skip 判断 |
| `StrategyEngineFacade.cpp` | `fromDb()` 中按因子类型填 skipNormalizeFactorIds |

## 五、Python 评分器

### 5.1 三维打分 (首期简化)

| 维度 | 权重 | 数据来源 | 首期方案 |
|------|------|---------|---------|
| 价格动量 | 0.5 | `commodity_prices_daily` | ✅ 可用 |
| 库存偏离 | 0.3 | 百川/生意社 (外部) | ⚠️ 暂用常量 0.5 |
| 产业链景气 | 0.2 | 下游行业数据 (外部) | ⚠️ 暂用常量 0.5 |

首期 Score = 0.5 × momentum + 0.5 × 常量 → 纯价格动量驱动。验证通过后接入真实库存/景气数据。

### 5.2 运行模式

```bash
# 历史回填 (回测前必须执行)
python commodity_ranker.py --mode backfill --start 2020-01-01 --end 2026-07-27

# 每日更新价格
python commodity_ranker.py --mode update_prices

# 每周排名
python commodity_ranker.py --mode compute_rank --top-n 5
```

组合因子中使用 SupplyChainFactor 时，该子因子必须配置 `standardization: 0` (None)。

`import_mapping.py` 中必须审计 `effective_date`，禁止一刀切设为 `2020-01-01`。每条映射需标注真实生效日期（财报发布日）。
