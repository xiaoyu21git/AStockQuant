# 因子回测公共功能模块拆分与性能优化方案（无 Qt 约束）

## 1. 文档目标

本方案用于将当前因子回测中的可复用能力沉淀为公共功能模块，供后续实盘与策略回测共用，避免重复造轮子。

目标明确如下：

1. 拆分后的模块只表达业务能力，不关心调用方。
2. 公共模块中禁止使用任何 Qt 类型、Qt 容器、Qt 线程与 Qt I/O。
3. 模块之间通过强类型合同协同，禁止字符串语义漂移与隐式兜底。
4. 所有关键路径默认 fail-fast，不做兼容回退。
5. 在同等功能下优先提升吞吐、降低延迟、降低内存占用。

## 2. 硬性约束

1. 公共模块禁止出现以下依赖：
   - QString, QVariant, QVariantMap, QVariantList
   - QDate, QDateTime
   - QJsonDocument, QJsonObject, QJsonParseError
   - QThread, QTimer, QPointer, QObject
2. 公共模块接口仅允许标准 C++ 类型与项目领域类型：
   - std::string_view, std::string, std::vector, std::span, std::optional
   - std::chrono::sys_days 或等价日期强类型
   - 领域枚举、结构体、错误码
3. 任何输入缺失、窗口非法、覆盖不足、元信息不完整时必须直接失败。
4. 不保留旧合同兼容字段，不做双口径并存。

## 3. 公共功能模块拆分（职责清晰）

### 3.1 参数归一与窗口决议模块

职责：

1. 输入参数归一化（数据源模式、因子列表、股票池列表）。
2. 回测开始/结束窗口决议。
3. 去重、空值剔除、非法值校验。

输入：

- 原始运行参数对象
- 数据集窗口元信息

输出：

- 归一化后的运行参数对象（强类型）

失败条件：

- 起止日期缺失或非法
- 数据源模式非法

### 3.2 基准与指数语义解析模块

职责：

1. 解析 benchmark/index 的多源元信息为统一符号语义。
2. 决议最终基准符号。

输入：

- 运行参数中的 benchmark 配置
- 数据集 benchmark 元信息

输出：

- BenchmarkSymbol（强类型）
- IndexSymbol（强类型，可选）

失败条件：

- 需要指数上下文但缺少可用指数标识

### 3.3 运行时需求推导模块

职责：

1. 推导 required fields。
2. 推导 warmup trading days。
3. 判定是否允许 daily-bar warmup 路径。

输入：

- 因子定义与边界规则
- 运行参数覆盖项

输出：

- RuntimeRequirements 结构体

失败条件：

- 因子需求与配置冲突
- 关键字段无法确定

### 3.4 历史成分股与动态股票池模块

职责：

1. 查询并构建指数历史成分区间。
2. 生成按日期的 allowed symbols 映射。
3. 对目标回测窗口进行覆盖性硬校验。

输入：

- IndexSymbol
- 回测日期范围
- 成分股历史数据源接口

输出：

- AllowedSymbolsByDate
- 成分股并集

失败条件：

- 任一交易日无覆盖
- 历史成分为空

### 3.5 Warmup 历史补齐模块

职责：

1. 计算 warmup 起始交易日。
2. 拉取 warmup 行情。
3. 生成可供执行层直接消费的连续市场数据片段。

输入：

- 回测锚点日期
- warmup 天数
- 标的集合

输出：

- WarmupDataChunk

失败条件：

- 交易日不足
- 查询结果为空
- 数据转换失败

### 3.6 预检规则与组合草稿校验模块

职责：

1. 组合草稿结构、参数范围、子因子集合合法性校验。
2. 预检失败分类与原因归因。
3. 输出统一预检结果对象。

输入：

- 组合草稿
- 支持性检测结果

输出：

- PreflightReport

失败条件：

- 子因子重复
- 权重非法
- normalizeMode 或 combineMode 非法

### 3.7 回测配置装配模块

职责：

1. 装配完整 BacktestConfig。
2. 合并参数归一结果、运行时需求、动态股票池、warmup 结果。
3. 输出执行层可直接消费的不可变配置。

输入：

- 已归一参数
- RuntimeRequirements
- AllowedSymbolsByDate
- WarmupDataChunk

输出：

- BacktestConfig（无 Qt）

失败条件：

- 配置关键字段缺失
- 数据依赖未满足

### 3.8 结果合同组装模块

职责：

1. 将执行结果组装为统一结果合同。
2. 支持单因子结果与批量聚合结果。
3. 输出用于后续展示与落库的稳定结构。

输入：

- 执行结果原始结构

输出：

- StandardBacktestResult
- StandardBacktestAggregate

失败条件：

- 结果状态非成功
- 必要指标缺失

## 4. 模块协同方式（相互协同）

协同主链：

1. 参数归一与窗口决议
2. 基准与指数语义解析
3. 运行时需求推导
4. 历史成分股与动态股票池
5. Warmup 历史补齐
6. 回测配置装配
7. 执行层（现有执行器）
8. 结果合同组装

协同规则：

1. 每个模块只依赖上游输出合同，不跨层读写隐式状态。
2. 禁止模块内部读取 UI 状态、线程状态、计时器状态。
3. 禁止模块间通过字符串 key 约定隐式字段，必须强类型字段名。
4. 上游失败立即返回，不进入下游。

## 5. 当前模块最佳性能提升方案（重点）

### 5.1 最高优先级优化（立即收益最大）

1. 日期循环全量扫描改为区间事件线扫描：
   - 当前按日循环并逐区间判断，复杂度偏高。
   - 改为对区间起止事件排序后做 sweep line，减少重复判断。
2. warmup + baseRows 合并时避免重复拷贝：
   - 预分配一次性缓冲区。
   - 使用 move 或 append_range 风格拼接。
3. 字符串日期键改为整数交易日索引：
   - AllowedSymbolsByDate 使用 int32 交易日序号或 YYYYMMDD 整数。
   - 减少 string 构造与哈希开销。
4. 构建 symbol 并集时避免多次排序与去重：
   - 使用一次哈希聚合后再排序输出。

### 5.2 数据结构优化

1. 哈希容器替换：
   - std::unordered_map / unordered_set 在热点路径可替换为更高性能实现。
2. 推荐开源库：
   - martin.ankerl::unordered_dense（高性能哈希表）
   - tsl::robin_map / robin_set（robin hood hashing）
3. 大对象传递：
   - 统一采用 const 引用、span、string_view，避免复制。

### 5.3 序列化与解析优化

1. JSON 解析与序列化热点可替换为 simdjson + nlohmann/json（或仅 simdjson DOM/ondemand）。
2. 高速格式化建议使用 fmt。

### 5.4 并行与任务调度优化

1. 将独立步骤并行化：
   - 历史成分查询后，按日期映射构建与并集构建可并行。
   - warmup 查询与部分校验并行。
2. 推荐开源库：
   - oneTBB（任务并行与并发容器）
   - cpp-taskflow（轻量任务图编排）
3. 线程策略：
   - 统一线程池，禁止临时线程频繁创建。

### 5.5 列式与向量化优化

1. 对 warmup 数据转换、过滤、拼接优先列式批处理。
2. 推荐库：
   - Apache Arrow（已在项目中，可继续深化）
   - Eigen（复杂数值计算）

### 5.6 数据访问与缓存优化

1. 交易日历查询引入只读内存缓存，避免重复 DB 往返。
2. 历史成分股按 index+date range 做分段缓存（不可回退策略下可直接命中失败）。
3. marketDataCacheKey 改为结构化哈希键（xxHash 或 HighwayHash）。

推荐库：

- xxHash（高速哈希）
- HighwayHash（高质量哈希，可按安全要求评估）

## 6. 效率提升方案（研发效率与可维护性）

1. 统一错误模型：
   - error_code + message + category，替代散落异常文本。
2. 统一合同测试：
   - 每个模块建立输入输出契约测试与边界测试。
3. 性能基线：
   - 基准测试覆盖 3 类场景：小样本、中样本、全市场大样本。
4. 回归门禁：
   - 新增性能回归门槛（吞吐、延迟、内存峰值）。

## 7. 迁移落地顺序（建议）

1. 结果合同组装模块
2. 参数归一与窗口决议模块
3. 基准与指数语义解析模块
4. 运行时需求推导模块
5. 历史成分股与动态股票池模块
6. Warmup 历史补齐模块
7. 预检规则与组合草稿校验模块
8. 回测配置装配模块

该顺序原因：先拆低耦合模块建立合同，再拆高耦合配置与数据路径，风险最低。

## 8. 量化验收指标

1. 公共模块 Qt 依赖数 = 0。
2. 回测关键路径 P95 延迟降低 >= 30%。
3. 峰值内存降低 >= 25%。
4. 全市场批量回测吞吐提升 >= 1.5x。
5. 公共模块单元测试覆盖率 >= 85%。

## 9. 现阶段结论

当前 FactorBacktestController 中已具备完整可拆分基础，建议按本文件八个功能模块推进。
公共模块化后可以在不改业务语义的前提下，实现实盘与策略回测共享核心能力，并显著提升性能与研发效率。
