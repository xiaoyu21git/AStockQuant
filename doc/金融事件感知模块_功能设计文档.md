### 2.2 核心原则

1. **事件总线是不可变中枢** — 所有新组件通过 `EventBus::publish()` / `EventBus::subscribe()` 接入，不修改 EventBus 本身
2. **Python 负责采集+NLP，C++ 负责消费+决策** — 利用 Python 生态做数据抓取和 NLP，利用 C++ 做低延迟因子计算和风控
3. **通过现有 FactorInstanceManager 注册新因子** — 不新增因子注册机制，走 `kFactorCreators[]` 分发表
4. **通过现有 RiskManager::setRiskConfig() 推送风控变更** — 不修改风控引擎内部逻辑

## 三、新增组件详细设计

### 3.1 金融事件类型定义（C++ 侧）

在 `EventFormat.hpp` 的 `EventTypes` namespace 中新增事件类型字符串常量：

```cpp
// 新增: 金融事件类型 (news.*)
namespace EventTypes {
    // ... 现有 ~60 种类型 ...
    inline constexpr const char* NEWS_EARNINGS    = "news.earnings";     // 业绩预告/快报
    inline constexpr const char* NEWS_POLICY      = "news.policy";       // 政策/监管
    inline constexpr const char* NEWS_MATERIAL    = "news.material";     // 重大事项(重组/增减持)
    inline constexpr const char* NEWS_SOCIAL      = "news.social";       // 社交媒体情绪异动
    inline constexpr const char* NEWS_QUOTE_ALERT = "news.quote_alert";  // 行情异动(放量/涨跌停)
    inline constexpr const char* NEWS_ALERT       = "news.alert";        // 突发/快讯
}
```

### 3.2 金融事件数据结构（Python 侧，C++ EventFormat 映射）

Python 侧用 dict 表示，通过 pybind11 转换为 C++ `EventFormat`：

```python
@dataclass
class FinancialEvent:
    source: str              # "eastmoney" | "cninfo" | "xueqiu" | "cls"
    title: str               # 新闻标题
    summary: str             # 摘要(前200字)
    symbols: list[str]       # 关联标的 ["000001","600000"]
    sentiment_score: float   # -1.0 ~ 1.0
    event_type: str          # "earnings" | "policy" | "material" | "social" | "quote_alert"
    confidence: float        # 0.0 ~ 1.0
    tags: dict               # {"超预期": True, "问询函": False, ...}
    timestamp: int           # Unix 毫秒
```

C++ 侧 `EventFormat` 映射：

| Python 字段 | EventFormat 字段 | EventValue 类型 |
|-------------|-----------------|-----------------|
| source | data["source"] | string |
| title | data["title"] | string |
| summary | data["summary"] | string |
| symbols | data["symbols"] | vector\<string\> |
| sentiment_score | data["sentiment_score"] | double |
| event_type | type (后缀) | string (如"news.earnings") |
| confidence | data["confidence"] | double |
| tags | metadata (前缀"tag.") | string→string |
| timestamp | metadata["timestamp"] | string |

### 3.3 新增因子: `EventDrivenFactor`（C++）

**文件位置**: `src/domain/factor/include/EventDrivenFactor.h` + `src/domain/factor/src/EventDrivenFactor.cpp`

```
继承: BaseFactor
FactorType: EVENT_DRIVEN (新增枚举值 14)
注册: kFactorCreators[] 新增 {FactorType::EVENT_DRIVEN, &createEventDrivenFactorEntry}
```

**核心逻辑**:

```cpp
// EventDrivenFactor::calculate(CalculationContext)
// 1. 从 EventBus 获取当日累积的该标的关联事件
//    通过订阅 EventFormat 事件在内存中维护事件缓存
// 2. 对每个 symbol:
//    a. 取最新关联事件的情感分 sentiment_score
//    b. 若 tags 含 "超预期" → 额外加分
//    c. 若 event_type == "policy" 且 sentiment_score < -0.5 → 额外减分
//    d. 输出: finalScore = baseScore + sentiment_score * weight
// 3. 调用 applyCommonStandardization() 标准化
```

**与现有因子的差异**:
- 数据源不是行情/财务数据库，而是 EventBus 上的实时事件
- 需要维护一个**事件缓存** (`std::unordered_map<std::string, std::vector<EventRecord>>`)
- 通过 `FactorEngine` 的 compute() 流程被策略引擎消费，与现有因子完全一致的接口

**DataRequirements**:
```cpp
DataRequirements getDataRequirements() const override {
    DataRequirements req;
    // 不需要传统行情字段 — 数据来自 EventBus
    req.sourceTable = SourceTable::NONE; // 或新增 SourceTable::EVENT_BUS
    return req;
}
```

### 3.4 新增风控订阅器: `EventRiskSubscriber`（C++）

**文件位置**: `src/domain/strategy/include/EventRiskSubscriber.h` + `src/domain/strategy/src/EventRiskSubscriber.cpp`

**职责**: 订阅 EventBus 上的 `news.*` 事件，根据事件内容动态调整风控参数。

```cpp
class EventRiskSubscriber {
public:
    // 从 GlobalEventBusRegistry 获取总线并订阅
    void start();
    void stop();

private:
    // 订阅回调: 处理 news.alert / news.policy 事件
    void onFinancialEvent(const engine::EventFormat& event);

    // 事件类型 → 风控动作映射
    void applyEventToRisk(const std::string& symbol,
                          const std::string& eventType,
                          const std::unordered_map<std::string, std::string>& tags);

    engine::EventBus* m_bus = nullptr;
    engine::Uuid m_subscriptionId;
};
```

**风控动作映射表**:

| 事件条件 | 风控动作 | 实现方式 |
|---------|---------|---------|
| `event_type=="alert"` + 置信度<0.5 | 临时禁止该标的开仓 | `m_liquidationBlocklist.insert(symbol)` |
| tags 含 "立案调查" | 止损线从 -10% 收紧到 -5% | 调整 `RiskConfig::stopLossPercent` (per-symbol) |
| tags 含 "ST风险警示" | 仓位上限从 10% 降到 2% | 调整 `RiskConfig::maxPositionPercent` (per-symbol) |
| `event_type=="policy"` + sentiment<-0.7 | 总敞口从 100% 降到 80% | 调整 `RiskConfig::maxTotalExposurePercent` (全局) |

**接入时机**: 在 `StrategyEngine::startLiveLoop()` 中初始化，与 DailyEodScheduler 并行：

```cpp
// StrategyEngine 中新增:
void StrategyEngine::startLiveLoop() {
    if (m_isDailyFrequency) {
        // ... 现有 DailyEodScheduler 逻辑 ...
    }
    // 新增: 启动事件风控订阅器
    if (!m_eventRiskSubscriber) {
        m_eventRiskSubscriber = std::make_unique<EventRiskSubscriber>();
        m_eventRiskSubscriber->start();
    }
}
```

## 四、时序设计

### 4.1 盘前新闻采集 → EOD 策略决策

```
08:00  Python NewsAdapter 启动, 抓取当日新闻
08:05  NLP Service 分析情感, 实体识别
08:10  Publisher 发布 EventFormat("news.earnings", ...) → C++ EventBus
       ├─ EventDrivenFactor 收到事件, 更新事件缓存
       └─ EventRiskSubscriber 收到事件, 调整 RiskConfig

14:50  DailyEodScheduler 触发 evaluateEndOfDay()
       ├─ Phase 0: 清空 m_liquidationBlocklist
       ├─ Phase 1: 收集策略信号
       ├─ Phase 2: 先卖(含风控止损 → 加入 blocklist)
       ├─ Phase 3: 后买(跳过 blocklist 中标的)
       │
       ├─ StrategyEngine 调用 FactorEngine::compute()
       │   └─ EventDrivenFactor::calculate() 消费事件缓存中的情感数据
       │       └─ 输出因子值：受影响标的加权/降权
       │
       └─ 风控检查使用 EventRiskSubscriber 调整后的 RiskConfig
```

### 4.2 盘中突发新闻 → 实时响应

```
10:30  Python NewsAdapter 收到突发新闻推送
10:30  NLP Service 分析 → sentiment=-0.9, tags={"立案调查"}
10:30  Publisher → EventBus.publish("news.alert")

       C++ EventBus 分发:
       ├─ EventRiskSubscriber::onFinancialEvent()
       │   ├─ 识别 "立案调查" 标签
       │   ├─ 将 symbol 加入 m_liquidationBlocklist (盘中已有持仓不会卖出,
       │   │   但盘后 EOD Phase 3 不会再买入)
       │   └─ 临时收紧该标的止损线 RiskConfig
       │
       └─ EventDrivenFactor 更新缓存 (下次 compute() 生效)
```

#### 淘汰分析

| 库 | 淘汰理由 |
|----|---------|
| **snownlp** | 2022 年停更。情感模型是朴素贝叶斯训练于酒店评论数据，对金融文本严重误判。"业绩预亏但环比改善"→负分(实际中性偏正) |
| **cnsenti** | 本质是情感词典匹配，无法理解语境。"公告: 公司被立案调查"—可能因"立案"出现在正面语境中被漏判。无实体识别。 |
| **jieba** | 2022 年停更。分词可用但无 NER 和情感。且自定义词典需要重启进程才能生效，不适合盘中动态添加标的。 |
| **FinBERT (单体)** | 仅做情感分析。NER/分类/关键词全部需要额外库。且 2024 年后社区版本冻结，不再跟随 BERT 新架构更新。 |

#### 最终选择: HanLP 2.x 作为核心引擎

**理由**:
1. **单一库覆盖全部 6 项能力** — 分词/NER/情感/分类/关键词，不需要多个库拼凑
2. **多后端架构** — 轻量模型(50MB)快速部署 → 生产稳定后切 Transformer 后端提升精度，**同一套 API 不变**
3. **自定义词典热更新** — 标的名单变化无需重启服务，盘中可动态注入
4. **REST API 模式** — Python 独立进程部署，C++ 通过 `foundation::net::HttpClient` 调用，或直接在 Python event publisher 中 import
5. **生态最大** — 33k+ stars，中文 NLP 事实标准，遇到问题社区解答及时
6. **维护风险可控** — 虽为单人项目但已持续维护 8 年(2018-2026)，且 API 稳定、文档完善

**唯一短板**: 通用情感模型对金融领域精度不够(约 72%)。解决方案见 5.2。

#### 补充: PaddleNLP 作为备选

PaddleNLP 的 SKEP 模型是百度专为金融情感训练的，精度 ~86%。但需要 PaddlePaddle 框架（约 1GB 额外依赖），且 Windows 支持不如 HanLP。如果未来 HanLP 维护停滞或金融情感精度无法满足，可以迁移到 PaddleNLP——但当前不推荐作为首选，因为:

- 与现有 C++ 生态交互需要额外适配层
- PaddlePaddle Windows 版本长期滞后于 Linux
- 部署复杂度显著增加

### 5.2 金融情感增强方案

HanLP 通用情感模型对金融文本的典型误判:

| 文本 | HanLP通用 | 正确判断 | 问题 |
|------|----------|---------|------|
| "公司预计亏损 5000 万" | -0.3(偏负) | -0.8(强负) | 亏损程度低估 |
| "亏损大幅收窄 60%" | -0.2(偏负) | +0.4(偏正) | 方向错误 |
| "收到深交所问询函" | 0.0(中性) | -0.6(偏负) | 金融语境缺失 |
| "拟10转10派5元" | 0.0(中性) | +0.5(偏正) | 金融术语不理解 |

**增强方案: 金融情感词典 + HanLP 分词（参考 BosonNLP 情感词典思路）**

```
流程:
  1. HanLP 金融分词 → 得到词组序列
  2. 每组查询金融情感词典 → 得到分词组情感值
     词典结构: {"预增": 0.6, "超预期": 0.8, "立案调查": -0.9, "问询函": -0.6, ...}
  3. 程度副词加权: "大幅预增" > "小幅预增"
  4. 否定词翻转: "未能扭亏" → 扭亏(0.5) → 未能(-0.5)
  5. 加权求和 → 最终情感分
  6. (可选) 作为 HanLP 情感模型的 prior，两者加权融合
```

金融情感词典来源:
- **自建**(推荐): 从巨潮/东方财富历史公告中提取高频金融术语，人工标注情感值。初期 500 词，持续扩充
- **BosonNLP 情感词典**(参考): 开源但停更，作为基础种子词
- **先用词典保底，HanLP 情感模型做补充** — 词典覆盖 >90% 的规则性判断，HanLP 处理长尾语境

这种方案:
- 零额外依赖（HanLP 已含分词）
- 金融领域精度 80-85%（词典主导 + HanLP 辅助）
- 可解释性强（每组分词的情感值可追溯）
- 词典可渐进式扩充，上线后持续优化

### 5.3 最终技术栈

```
+-------------------------------------------+
|           NLP Pipeline                     |
|                                            |
|  raw_text                                  |
|    |                                       |
|  HanLP 2.x REST API / Python SDK          |
|  +-- tok.COARSE_ELECTRA_SMALL_ZH  (分词)   |
|  +-- ner.MSRA_ELECTRA_SMALL_ZH   (NER)    |
|  +-- custom_dict: 标的名单+金融术语        |
|    |                                       |
|  金融情感词典 (自建 .json)                 |
|  +-- 词组查询 -> 基础情感值                |
|  +-- 程度副词加权                          |
|  +-- 否定词翻转                            |
|  +-- HanLP 情感模型 加权融合(可选)         |
|    |                                       |
|  HanLP text_classification (事件分类)      |
|  +-- 训练集: 历史标注的金融事件            |
|  +-- 输出: earnings/policy/material/...    |
|    |                                       |
|  关键词规则引擎 (tags)                     |
|  +-- 正则 + 词典: 超预期/ST/立案/...       |
|    |                                       |
|  FinancialEvent dict -> EventBus.publish() |
+-------------------------------------------+
```

| 层 | 库 | 用途 | 许可证 |
|----|----|------|--------|
| NLP 引擎 | **HanLP 2.x** | 分词 + NER + 文本分类 + 关键词提取 | Apache 2.0 |
| 金融情感 | **自建词典** + HanLP 分词 | 金融领域情感分析 | — |
| 数据采集 | **akshare** | 东方财富/巨潮资讯/雪球 API | MIT |
| 异步抓取 | **aiohttp** | 并发 HTTP 请求 | Apache 2.0 |
| HTML 解析 | **BeautifulSoup** | 网页正文提取 | MIT |
| 去重缓存 | **hiredis / RedisCacheManager** | URL/内容指纹去重 | 已在项目中 |

**不需要的库（明确排除）**:
- `snownlp` — 停更 + 无金融适配
- `cnsenti` — 纯词典，无法理解语境
- `FinBERT` — 仅情感，需 PyTorch，需 GPU，社区已冻结
- `PaddleNLP` — Windows 支持不足，PaddlePaddle 依赖过重
- `transformers` — FinBERT 依赖，单体不上
