## 1. 架构概览

策略回测引擎采用**分层漏斗 + 事件驱动 + 接口注入**架构。核心 `BacktestEngine` 只负责驱动决策流程和状态管理，所有外部依赖通过纯虚接口注入。

```text
+------------------+
| ApplicationService |
+---------+--------+
          | execute(request)
          v
+-----------------------------+
|       BacktestEngine        |
|  - validate(request)        |
|  - runLoop()                |
|  - assembleResult()         |
+---+--------+--------+-------+
    |        |        |
    v        v        v
IMarketDataCache  IRuleChecker  IExecutionSimulator
         |             |              |
         +-------------+--------------+
                       |
               IPortfolioOptimizer
                       |
                   IAnalyzer
```

## 4. 性能基础设计（已冻结）

| 策略 | 具体措施 |
| :--- | :--- |
| **列式存储** | 各字段独立连续存储，`const double*` 指针遍历，利用 CPU 缓存和 SIMD。 |
| **整数索引** | 全部股票分配固定 `int id`，数组下标访问，无哈希查找。 |
| **预分配内存** | 结果容器在初始化时 `reserve` 足够容量，循环内无动态分配。 |
| **惰性求值** | 上层池不变时不重复计算下层；非调仓日跳过低频层。 |
| **无全局状态** | 引擎实例自包含，支持多线程并行。 |
| **性能门禁** | 基准测试（10年日频/5000股/单层overlay <5秒）纳入 CI。 |

## 5. 执行模式

通过 `ExecutionSpec` 控制执行行为：

- `executionKind`：日终执行 / 日内连续执行。
- `enableShortSelling`：暂预留，初版仅支持多头。
- `rebalanceFrequencyDays`：低频再平衡周期。
- `useMarketOnClose`：是否使用收盘价成交。
- `intradayTiming`：是否启用分钟子循环。

## 6. 诊断与输出

`Diagnostics` 结构记录：

- 简化假设列表（如“假设全部成交于 VWAP”）
- 性能统计（总耗时、日均耗时、内存峰值）
- 潜在数据缺失或异常告警
