## 一、流程图设计 -> 抽象表示

### 1. 类抽象

| 抽象类 | 说明 |
|--------|------|
| `BacktestOrchestrator` | 主流程控制，负责校验、初始化、主循环调度和结果封装。 |
| `LayerExecutor` | 单层决策执行器，封装因子获取、域隔离、标准化、得分计算、规则过滤。 |
| `EventLoop` | 事件循环抽象，支持日频主循环和分钟子循环切换。 |
| `DiagnosticsRecorder` | 诊断记录器，用于收集运行假设和性能数据。 |

### 2. 流程抽象

- **初始化链**：校验 -> 加载数据 -> 建立索引 -> 注入组件。
- **主循环迭代**：逐日推进，按调仓周期触发 L1，每日触发 L2，可选分钟级 L3。
- **单层处理管道**：输入池 -> 因子值获取 -> 域校验 -> 标准化 -> 加权求和 -> 阈值截断 -> 规则阻断过滤 -> 输出池。
- **结果生成**：循环结束后计算综合指标，封装 DTO，可选后处理分析。

### 3. 关键字段

`BacktestRequest` 中的 `window`（回测区间）、`benchmarkSymbol`；`DecisionLayer` 中的 `type`、`inputUniverseId`、`targetPositionCount`；循环控制标志 `intradayTiming`、调仓日标志。

### 4. 框架抽象

整体采用**分层漏斗 + 管道-过滤器**模式：每一决策层是一个独立的处理管道，层与层之间通过候选池传递，引擎负责管道调度和时间推进。

## 二、时序图设计 -> 抽象表示

### 1. 类抽象

| 抽象类 | 角色 |
|--------|------|
| `ApplicationService` | 调用方，发起回测并接收结果。 |
| `BacktestEngine` | 核心调度者，管理整个回测生命周期。 |
| `IMarketDataCache` | 数据提供者，返回列式数据切片。 |
| `IRuleChecker` | 规则判断服务，返回阻断/强退结果。 |
| `IExecutionSimulator` | 交易执行服务，返回成交回报。 |
| `IPortfolioOptimizer` | 权重计算服务，生成目标持仓比例。 |
| `IAnalyzer` | 结果后处理服务（可选）。 |

### 2. 交互流程抽象

- **启动阶段**：`ApplicationService` 调用 `execute(request)`，引擎验证并加载数据。
- **每日决策**：引擎依次询问 `RuleChecker`、`PortfolioOptimizer`、`ExecutionSimulator`，构成“检查 -> 优化 -> 执行”的闭环。
- **日内高频**：分钟循环内复用相同交互链，但候选池受上层约束。
- **收尾**：生成 DTO，可选传 `IAnalyzer` 补充诊断，最终返回给调用方。

### 3. 关键字段

`RuleCheckResult`（`blocked`、`forceExit`、`reason`），`Order`（标的、数量、类型），`Fill`（成交价、量、费用），`ProgressInfo`（百分比、当前时间）。

### 4. 框架抽象

采用**依赖注入 + 消息驱动**模式：外部服务通过接口注入，引擎内部通过顺序调用模拟消息传递，确保职责清晰、时序确定。

## 三、规则与边界文档 -> 抽象表示

### 1. 类抽象

| 抽象类 | 职责 |
|--------|------|
| `RuleEngineAdapter` | 外部规则引擎的适配层，实现 `IRuleChecker` 接口（非引擎内部类）。 |
| `HardBoundaryValidator` | 引擎内部校验器，执行域隔离、合同完整性、内存分配等硬边界检查。 |
| `AssumptionRecorder` | 诊断组件，负责记录所有引擎简化假设。 |

### 2. 流程抽象

- **规则消费流程**：引擎在指定决策点统一调用 `IRuleChecker.checkRules()`，根据返回结果执行阻断或强退，不介入规则计算。
- **边界守卫流程**：在因子合成前强制校验 `universeId` 和时间戳；在内存分配点检查是否处于热路径；在结果输出阶段收集假设列表。

### 3. 关键字段

`StrategyContext`（包含持仓、资金、市场状态等，供规则判断使用），`Diagnostics.assumptions` 数组。

### 4. 框架抽象

定义了**引擎-外部模块的清晰边界**：引擎是“不可变计算核心”，外部模块通过“纯虚契约”提供可变行为。硬边界通过编译期和运行期断言双重保障，确保引擎不越界。

## 四、详细设计文档 -> 抽象表示

### 1. 类抽象

| 抽象类/接口 | 说明 |
|-------------|------|
| `BacktestEngine` | 核心类，组合所有扩展点，实现主循环。 |
| `DecisionLayer` (struct) | 策略分层配置的数据载体。 |
| `FactorOverlayConfig` (struct) | 因子合成规则的数据载体。 |
| `BacktestRequest` / `BacktestResultDto` (struct) | 强类型合同，定义完整输入输出。 |
| `IMarketDataCache` / `IRuleChecker` / `IExecutionSimulator` / `IPortfolioOptimizer` / `IAnalyzer` | 五大扩展接口。 |
| `FastExecutionSimulator` / `EqualWeightOptimizer` | V1.0 默认实现。 |
| `PerformanceBenchmark` | 性能门禁用的基准测试类。 |

### 2. 流程抽象

- **配置驱动装配**：`ApplicationService` 将 `StrategyAggregate` 和运行覆盖参数通过 `BacktestRequestFactory` 组装为 `BacktestRequest`。
- **分层执行管道**：每层 `DecisionLayer` 经过“数据获取 -> 域校验 -> 标准化 -> 加权 -> 截断 -> 规则过滤”的标准化管道。
- **事件循环推进**：日循环为骨架，分钟循环为可选嵌入，通过 `ExecutionSpec` 控制。
- **结果组装**：从预分配的容器中提取数据，结合实时计算的统计量，生成 `BacktestResultDto`。

### 3. 关键字段

- **配置侧**：`DecisionLayer.id/type/inputUniverseId`，`FactorOverlayConfig.factorIds/weights/minimumCompositeScore`。
- **状态侧**：持仓账本 `PositionBook`，现金余额 `CashAmount`，权益曲线 `EquityCurve`。
- **结果侧**：`PerformanceSummary`（夏普、回撤等），`LayerAttribution`（分层收益），`RuleTemplateSummary`（阻断/强退计数）。

### 4. 框架抽象

系统基于**分层架构**：

- **应用层**：`ApplicationService` 负责任务调度。
- **领域层**：`BacktestEngine` 作为核心领域服务，通过配置对象驱动行为。
- **基础设施层**：数据缓存、规则检查、执行模拟等均作为可插拔的基础设施组件。
- **共享内核**：`BacktestRequest` / `BacktestResultDto` 及各类 Spec 定义作为跨层通信的共享合同。

整体设计遵循**六边形架构**思想，引擎核心不依赖任何外部细节，所有 I/O 和算法细节都通过接口隔离。性能方面采用**面向数据设计 (DOD)**，将数据布局和计算模式对齐到硬件缓存特性。

## 五、顶层总括

以上抽象可直接用于架构评审、概要设计文档或团队 onboarding。四份最终版文档分别从**流程视图、交互视图、边界视图、实现视图**描述了同一个引擎，而本文件将它们进一步收敛为一套统一的顶层抽象模型：

1. **流程层**：由 `BacktestOrchestrator` 与 `EventLoop` 驱动时间推进。
2. **执行层**：由 `LayerExecutor` 串联各层 Overlay 管道。
3. **边界层**：由 `HardBoundaryValidator` 与 `RuleEngineAdapter` 把引擎核心和外部能力隔离开。
4. **实现层**：由 `BacktestEngine + Request/Result + 五大接口` 形成最终可开发的代码骨架。

该抽象视图与 V1.0 最终冻结方案保持一致，可直接作为后续概要设计、类图设计和代码骨架搭建的上层依据。
