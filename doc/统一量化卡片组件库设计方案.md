# 统一量化卡片组件库设计方案

## 一、设计目标

1. **复用性**：因子库卡片组件能够复用到策略上
2. **集成性**：策略控制参数和状态集成到卡片上，减少页面占用
3. **一致性**：因子和策略卡片保持统一的视觉风格和交互体验
4. **可扩展性**：支持未来其他量化实体（如组合、信号等）的卡片扩展

## 二、整体架构

### 组件层级结构
```
BaseQuantCard.qml (基础卡片组件)
├── FactorCard.qml (因子卡片，继承BaseQuantCard)
└── StrategyCard.qml (策略卡片，继承BaseQuantCard)
```

### 共享功能模块
1. **视觉框架**：统一的颜色、尺寸、边距、圆角、阴影
2. **性能指标显示**：统一的指标布局和格式化
3. **迷你图表**：统一的图表绘制和交互
4. **标签系统**：统一的标签样式和布局
5. **操作按钮**：统一的操作按钮样式和动画
6. **状态指示**：统一的状态颜色和图标系统

### 6.2 策略数据映射
```javascript
// StrategyDataAdapter.js
function mapStrategyToCardData(strategy) {
    return {
        entityId: strategy.strategyId,
        displayName: strategy.strategyName || strategy.name,
        category: strategy.strategyType || "通用策略",
        description: strategy.description,
        creator: strategy.creator || "系统",
        createDate: strategy.createDate,
        status: mapStrategyStatus(strategy.status),
        isFavorite: strategy.isFavorite || false,
        tags: strategy.tags || [],
        categoryColor: getStrategyTypeColor(strategy.strategyType),
        
        // 策略性能指标
        returns: strategy.returns || 0,
        sharpeRatio: strategy.sharpeRatio || 0,
        maxDrawdown: strategy.maxDrawdown || 0,
        winRate: strategy.winRate || 0,
        
        // 实时状态
        runningDays: strategy.runningDays || 0,
        tradesCount: strategy.tradesCount || 0,
        dailyPnL: strategy.dailyPnL || 0,
        position: strategy.position || 0,
        
        // 控制参数
        controlParameters: strategy.parameters || getDefaultStrategyParameters(strategy.strategyType)
    };
}

function mapStrategyStatus(status) {
    const statusMap = {
        "ACTIVE": "RUNNING",
        "INACTIVE": "STOPPED",
        "PAUSED": "PAUSED",
        "running": "RUNNING",
        "stopped": "STOPPED",
        "paused": "PAUSED"
    };
    return statusMap[status] || "STOPPED";
}
```

## 九、预期效果

### 9.1 空间节省
- 垂直空间减少约40-50%
- 原分散的控制面板、参数面板、详情卡片合并
- 页面信息密度提升

### 9.2 操作效率
- 所有相关操作集中在卡片上
- 减少鼠标移动距离
- 直观的状态反馈

### 9.3 一致性
- 因子和策略卡片视觉风格统一
- 相同的交互模式和反馈机制
- 统一的数据展示格式

### 9.4 可维护性
- 通用功能集中在基类
- 专用功能隔离在子类
- 易于添加新的量化实体卡片

## 十、风险与缓解

### 风险1：性能问题
- **缓解**：优化图表渲染，使用Canvas而非Item组件
- **缓解**：实现虚拟滚动，只渲染可见卡片

### 风险2：兼容性问题
- **缓解**：保持向后兼容，逐步迁移
- **缓解**：提供数据适配层，兼容新旧数据格式

### 风险3：用户体验变化
- **缓解**：保留核心功能，优化而非颠覆
- **缓解**：提供用户引导，解释新功能

**总结**：通过创建统一的量化卡片组件库，不仅解决了因子卡片复用到策略的需求，还实现了策略控制参数和状态的高度集成，显著减少了页面空间占用，同时提供了更一致、更高效的用户体验。
