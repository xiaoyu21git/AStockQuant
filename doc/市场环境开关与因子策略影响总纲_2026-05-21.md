# 市场环境开关与因子策略影响总纲

> 说明：本文中的旧 `StrategyBacktestConfig` 表述已不再对应当前代码。当前策略回测主合同已经切到 typed `BacktestRequest`，但市场环境仍未收口成唯一顶层输入字段。

## 1. 目标

本文先定义一个统一前提：后续系统不能再默认只有 A 股语境，也不能把市场制度差异散落在因子、策略、风控、执行、结果展示各处单独处理。

后续必须引入统一的市场环境开关，由它决定交易制度、执行口径、收益归因口径和风险约束口径。

本文先回答两件事：

1. 市场环境不同，会怎样影响因子分析和策略回测。
2. 后续逐模块对齐时，应该围绕哪些共同维度推进。

本文不展开到每个模块的代码改造细节；模块级对齐清单放到后续文档单独细化。

## 2. 当前状态

当前工程已经有三块相关基础，但还没有形成统一的市场环境合同：

1. 因子回测配置 `BacktestConfig` 只有 `forwardDays`、`rebalanceDays`、`transactionCost`、`slippageRate`、`benchmarkSymbol` 等字段，没有正式的市场环境字段，见 [src/domain/factor/include/FactorBacktestExecutor.h](../src/domain/factor/include/FactorBacktestExecutor.h)。
2. 当前策略回测 typed 请求虽然已经把成本、风险、执行和数据源拆成独立结构，但仍没有把市场环境收口成唯一顶层字段，见 [src/domain/backtest/include/BacktestRequest.h](../src/domain/backtest/include/BacktestRequest.h) 和 [src/domain/strategy/include/StrategySnapshotTypes.h](../src/domain/strategy/include/StrategySnapshotTypes.h)。
3. 策略运行时规则里已经出现了 `marketEnvironmentGate`，但它当前更接近运行时门禁，不是统一的研究/回测/执行环境真源，见 [src/ui/bridge/src/StrategyRuntimeRuleEvaluator.cpp](../src/ui/bridge/src/StrategyRuntimeRuleEvaluator.cpp)。

这意味着当前系统仍然处于“局部有环境判断，但没有统一环境合同”的状态。

## 3. 为什么必须有市场环境开关

如果没有市场环境开关，系统会长期出现下面四类混乱：

1. 同一个因子，在不同市场下的可交易性被混成一个口径。
2. 同一个策略，在不同市场下的成交假设、换手约束、卖空约束、税费约束不一致。
3. 回测指标表面一致，但背后的收益起点、风险边界、执行路径不一致。
4. QML、桥接层、回测引擎、风险规则各自维护一套隐含市场假设，后续很难验证。

所以后续设计必须从“单一默认市场”改成“统一环境配置驱动”。

## 4. 统一开关定义

建议后续把市场环境定义为单一枚举配置，而不是字符串散落判断。

建议的概念模型：

```text
MarketEnvironmentProfile
    - CN_A_SHARE
    - HK_EQUITY
    - US_EQUITY
    - GENERIC_EQUITY
```

这个开关不只是“市场标签”，而是一个制度配置入口。它至少要绑定下面这些制度维度：

1. 收益起点规则：信号日生效还是下一交易日生效。
2. 买卖约束：是否允许 T+0，是否存在买入后次日才能卖出的限制。
3. 卖空约束：是否允许裸卖空、是否允许融资融券替代、是否默认只能多头。
4. 成交口径：收盘成交、下一日开盘成交、VWAP 近似成交还是仅 close-to-close 研究口径。
5. 交易成本结构：佣金、印花税、平台费、最低收费、双边/单边税费。
6. 可交易性限制：停牌、涨跌停、一字板、临停、价格带、最小价格步长。
7. 调仓日历：本地交易日、跨时区、半日市、节假日规则。
8. 基准与无风险利率口径：市场默认基准、年化无风险利率和年化换算规则。

## 5. 五层影响框架

市场环境开关一旦成为正式合同，影响不会只停留在“因子收益是不是 T+1”这一个点，而会向下穿透整个系统。

建议统一按下面五层理解它的影响范围：

1. 市场制度层：交易制度、做空约束、涨跌停、时段、税费、结算与可交易规则。
2. 数据与研究层：数据可用时点、样本池、公司行为、因子研究和收益归因。
3. 组合与策略层：调仓频率、持仓结构、容量、组合约束和策略适用边界。
4. 执行与风控层：成交模型、风险退出可执行性、批次执行、门禁与恢复链。
5. 系统与合同层：配置字段、缓存键、结果合同、页面展示、测试矩阵与回归基线。

后续逐模块对齐时，必须保证每个模块都能落到这五层中的至少一层，不允许只改局部收益公式就宣称“市场环境已支持”。

### 5.1 市场制度层

这是最上游的一层，决定“这个市场到底允许什么”。

它至少包括：

1. T+0 / T+1 交易限制。
2. 裸卖空、融资融券或完全多头限制。
3. 涨跌停、价格带、一字板、临停和停牌制度。
4. 交易时段、盘前盘后、半日市与跨时区日历。
5. 印花税、佣金、平台费、最低收费和双边/单边费用结构。

这一层如果没有先定义清楚，下面所有层都会漂移。

### 5.2 数据与研究层

这一层回答的不是“能不能下单”，而是“研究结果是不是站在正确的市场语境上”。

除了前面已经写到的 IC、分组收益、多空语义，还必须再纳入下面几类影响：

1. 数据可用时点。
   财报、分红、回购、指数调样、成分股权重变更，不只是有没有数据，而是市场在什么时点才能合法使用这份信息。
2. 样本池定义。
   不同市场下，可交易样本筛选规则不同。A 股要重点处理停牌、ST、退市整理、涨跌停和一字板；其他市场则可能更强调流动性、借券、盘前盘后和双重上市问题。
3. 公司行为处理。
   除权除息、拆股、送转、配股、现金分红、回购注销会直接影响价格序列、收益序列和因子解释。
4. 基准与无风险利率口径。
   不同市场的默认 benchmark、risk free rate 和年化换算口径不能继续混用。

### 5.3 组合与策略层

这一层回答“即便研究上成立，策略层应该怎么构建”。

它至少会影响：

1. 最优调仓频率和持仓周期。
2. 组合允许的换手上限和仓位释放节奏。
3. 多头、对冲、多空、日内、隔夜等策略类型的适用边界。
4. 容量上限与市场冲击成本承受能力。
5. 行业约束、持仓数、单票权重和现金管理方式。

同一个因子在不同市场环境里，可能研究上都有效，但最优策略形态完全不同。

### 5.4 执行与风控层

这一层回答“规则触发后，到底能不能真的执行”。

它至少包括：

1. 成交价模型：open、close、VWAP、TWAP 还是仅研究近似。
2. 风险退出可执行性：止损、止盈、强平、减仓是否可能被停牌或涨跌停阻断。
3. 批次执行与现金释放节奏。
4. 市场环境门禁、交易时段门禁、价格偏离门禁。
5. 异常拒单、部分成交、暂停与恢复链条。

如果这一层不纳入市场环境，很多风险控制都只会变成“统计上触发过”，而不是“真实可执行”。

### 5.5 系统与合同层

这一层最容易被忽略，但它决定功能能不能真正长期稳定存在。

它至少会影响：

1. 因子回测和策略回测配置合同是否包含市场环境字段。
2. 缓存键是否区分不同市场环境。
3. 结果合同是否显式区分研究口径和执行口径。
4. QML 页面是否把环境开关作为显式参数，而不是隐含默认值。
5. 回归测试矩阵是否覆盖不同市场环境。

如果系统层不跟着一起变，后续最典型的问题就是：同一组参数切换市场环境后仍命中旧缓存、页面展示沿用旧解释、测试只在一个市场环境下成立。

## 6. 对因子的影响

市场环境对因子的影响，核心不是“公式能不能写”，而是“因子研究结果能不能落到可执行收益”。

### 5.1 因子定义层

多数因子公式本身与市场环境无关，例如价值、质量、动量、低波、成长等定义并不因为市场切换就自动失效。

真正会变的是：

1. 因子的可交易半衰期解释。
2. 因子信号到收益实现之间的延迟损耗。
3. 因子在多头约束下的表现解释方式。
4. 因子横截面样本的有效可交易集合。

### 5.2 因子研究层

市场环境至少会影响下面几类因子研究结果：

1. IC/RankIC 的解释口径。
   A 股 T+1 环境下，`f_t` 更合理地对应 `R_{t+1,...}`，不能默认拿信号日当天起算收益。
2. 分组收益的可实现性。
   如果市场不允许同日成交，分组收益必须按执行日重排，而不是按信号日直接起算。
3. 多空结果的业务意义。
   在 A 股现货语境里，多空 spread 可以保留研究价值，但不能直接当作可实现策略收益；更适合补多头超额收益视角，这一点现有合同文档已经明确提到 A 股做空受限时的替代指标，见 [doc/因子回测结果指标接口合同.md](./因子回测结果指标接口合同.md)。
4. 换手率和衰减速度的真实解释。
   快衰减因子在 T+1 市场下通常会更受伤；慢因子更多体现为收益钝化，而不是完全失效。

### 5.3 A 股语境下最直接的因子影响

如果市场环境是 `CN_A_SHARE`，至少要强调下面几点：

1. 信号不能默认同日成交。
2. 超短周期因子会因 T+1 明显受损。
3. 多空结果偏研究口径，多头超额结果更接近实战口径。
4. 停牌、涨跌停、一字板会导致横截面样本名义可选但实际上不可交易。

## 7. 对策略的影响

市场环境对策略的影响更直接，因为策略面对的是“订单能否下、何时成交、能否退出、成本怎么算”。

### 6.1 交易层影响

市场环境会直接决定：

1. 何时能买。
2. 何时能卖。
3. 是否允许反手。
4. 是否允许做空。
5. 交易成本是否单边或双边收取。
6. 是否存在涨跌停或价格带导致的不可成交。

### 6.2 组合层影响

市场环境也会改变策略组合构建的约束：

1. 调仓频率的上限。
2. 仓位释放节奏。
3. 组合换手承受能力。
4. 预期收益和回撤分布。
5. 风险控制规则的触发条件。

### 6.3 A 股语境下最直接的策略影响

如果市场环境是 `CN_A_SHARE`，策略层至少会新增或放大下面几类问题：

1. 日内撤退能力受限，买入当日不能卖出。
2. 涨跌停和一字板会让止损、调仓、风险出清并不总是可执行。
3. 多头默认语义更重要，很多多空策略只能保留研究价值。
4. 高频和超高换手策略会因为 T+1 和制度摩擦显著失真。

### 6.4 现有系统里的直接信号

当前规则系统文档已经明确了一个事实：很多执行相关参数只停留在回测或预览层，还没有进入真实执行规则链，见 [doc/规则系统现状分析与设计方案.md](./规则系统现状分析与设计方案.md)。

这意味着后续如果要把市场环境开关做实，不能只改回测，也必须统一策略执行和风险规则的环境语义。

## 8. 影响方向补充

除了因子和策略本身，市场环境还会继续向外围扩散。后续对齐时不应漏掉下面这些方向：

1. 数据源接入层。
   同一类数据在不同市场的字段、时点、补齐方式和校验规则并不相同。
2. 样本准入与可交易过滤层。
   “研究样本可见”不等于“交易样本可下单”，这两层必须拆开。
3. 指数与基准管理层。
   不同市场的默认基准、指数成分变更频率和基准收益可得性不同。
4. 回测缓存与结果复用层。
   切换市场环境后，旧的回测结果、benchmark 缓存和明细缓存不能继续复用。
5. 页面解释层。
   用户在页面里看到的收益、风险、换手和 alpha，必须明确是哪个市场制度下解释出来的。
6. 跨市场基础设施层。
   时区、货币、节假日、交易日历和半日市等问题，当前单市场下不突出，但一旦支持多市场就会进入主链。

## 9. 因子与策略的共同对齐维度

后续不管是因子模块还是策略模块，都要围绕同一组维度对齐，而不是各自发明一套市场假设。

建议统一按下面 8 个维度推进：

1. 信号日与执行日关系。
2. 收益起点与持有区间定义。
3. 可交易样本过滤规则。
4. 卖空和多头语义。
5. 成交价模型。
6. 成本与税费模型。
7. 风险退出是否可执行。
8. 指标展示是研究口径还是执行口径。

这 8 个维度后续必须成为模块对齐清单的共同骨架。

## 10. 建议的环境档案

为了避免以后继续把市场差异写死在代码和页面里，建议后续每个市场环境都提供一份清晰的制度档案。

### 10.1 `CN_A_SHARE`

建议默认包含：

1. 因子研究默认按下一交易日起算收益。
2. 现货默认不允许裸卖空。
3. 买入后当日不可卖出。
4. 需要显式考虑涨跌停、停牌、一字板不可成交。
5. 默认更强调多头超额收益，不把多空收益直接当实盘代理。

### 10.2 `HK_EQUITY`

建议关注：

1. 不同于 A 股的卖空和交易机制。
2. 更灵活的日内交易语义。
3. 价格带、手续费结构和交易时段差异。

### 10.3 `US_EQUITY`

建议关注：

1. T+0 交易假设通常更合理。
2. 卖空可行性和借券限制要单独建模。
3. 市场时段、盘前盘后和滑点特征与 A 股明显不同。

### 10.4 `GENERIC_EQUITY`

这是一个过渡环境，只适合在制度未完全建模时作为研究默认档案，不能长期承担正式产品语义。

## 11. 当前系统最需要先统一的事情

从现状看，后续应先统一下面三件事：

1. 因子回测、策略回测、运行时规则都要接同一个 `MarketEnvironmentProfile`。
2. 结果合同必须显式区分研究口径和执行口径，不能再靠隐含市场假设混用。
3. A 股、港股、美股这类环境差异必须由环境档案驱动，不允许在单个模块里私自写死。

## 12. 后续模块级对齐索引

在这份总纲基础上，后续模块级对齐建议按下面顺序展开：

1. 市场制度层：先定义 `MarketEnvironmentProfile` 及其制度字段。
2. 数据与研究层：统一 signalDate、executionDate、forwardDays、benchmark 和数据可用时点口径。
3. 组合与策略层：统一策略回测配置、调仓语义、卖空开关、容量与组合约束。
4. 执行与风控层：统一成交模型、停牌涨跌停可执行性、环境门禁和恢复链。
5. 系统与合同层：统一配置字段、缓存键、结果合同、QML 参数和测试矩阵。

## 13. 结论

后续不能把“改成 A 股 T+1”当成一个孤立修补点处理。

正确的方向是：

1. 先建立统一的市场环境开关。
2. 再让 A 股、港股、美股等环境以制度档案形式落地。
3. 然后让因子、策略、风控、执行、结果合同共同服从这个开关。

只有这样，后续逐模块对齐时才不会再次出现“因子一套口径、策略一套口径、页面又一套口径”的分裂问题。
