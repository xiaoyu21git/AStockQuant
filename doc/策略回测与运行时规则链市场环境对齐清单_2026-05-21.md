# 策略回测与运行时规则链市场环境对齐清单

> 说明：本文中的 `StrategyBacktestConfig` / `StrategyBacktestService` 语义已变成历史背景。当前策略回测现状应以 `BacktestRequest`、`StrategySnapshotTypes`、`BacktestRequestFactory` 和 `BacktestApplicationService` 为准；`StrategyBacktestController` 现阶段仅保留显式失败入口。

## 1. 目标

本文覆盖两条紧密相关的链路：

1. 策略回测链
2. 运行时规则链

目标是明确市场环境开关在这两条链里的单一合同、字段归属和模块改造入口，避免后续实现时出现同语义重复字段和隐含默认市场假设。

## 2. 当前锚点

当前策略相关链路的关键锚点有四个：

1. typed 回测请求主合同 `BacktestRequest`，见 [src/domain/backtest/include/BacktestRequest.h](../src/domain/backtest/include/BacktestRequest.h)。
2. 策略快照结构与请求装配边界，见 [src/domain/strategy/include/StrategySnapshotTypes.h](../src/domain/strategy/include/StrategySnapshotTypes.h) 和 [src/application/backtest/src/CanonicalBacktestRequestFactory.cpp](../src/application/backtest/src/CanonicalBacktestRequestFactory.cpp)。
3. `StrategyRuntimeRuleEvaluator::MarketContext`，见 [src/ui/bridge/include/StrategyRuntimeRuleEvaluator.h](../src/ui/bridge/include/StrategyRuntimeRuleEvaluator.h)。
4. `StrategyRuntimeRuleEvaluator::applyMarketEnvironmentGate` 及其输出字段，见 [src/ui/bridge/src/StrategyRuntimeRuleEvaluator.cpp](../src/ui/bridge/src/StrategyRuntimeRuleEvaluator.cpp#L194)。

## 3. 当前问题

当前策略相关链路存在五类问题：

1. 当前 typed 策略回测请求还没有把 `marketEnvironmentProfile` 收成唯一顶层输入。
2. 配置里已经存在 `enableShortSelling`、`useMarketOnClose`、`taxRate` 等执行相关字段，但它们没有明确从市场环境解析而来。
3. 四类 snapshot 里没有统一的市场环境字段归属。
4. `marketEnvironmentGate` 现在表示的是门禁结果，不是环境配置真源。
5. 运行时门禁仍然主要基于价格和时段，不包含完整市场制度语义。

## 4. 硬约束

后续实现必须遵守下面这些硬约束：

1. 不允许同时引入 `marketType`、`marketEnvironment`、`marketEnvironmentProfile` 这类重复语义字段。
2. 不允许把市场环境真源放成字符串。
3. 不允许继续让 `enableShortSelling` 直接承担“市场制度 + 用户策略偏好”双重语义。
4. 不允许把 `marketEnvironmentGate` 既当配置字段又当门禁结果字段。
5. 不允许为了兼容旧快照继续保留一套隐含默认市场字段。

## 5. 目标合同

### 5.1 顶层开关

策略链第一阶段只允许一个统一市场环境输入：

1. `marketEnvironmentProfile`

它必须作为枚举值进入策略回测配置和运行时上下文。

### 5.2 解析后的内部语义

后续策略链内部必须由 `marketEnvironmentProfile` 解析出一份结构化语义，而不是到处 scattered 判断。

最少应解析出：

1. `executionLagTradingDays`
2. `allowSameDaySellAfterBuy`
3. `shortSellingMode`
4. `executionPriceModel`
5. `returnAttributionMode`
6. `priceLimitMode`
7. `calendarProfile`
8. `costProfile`

## 6. 策略回测配置层对齐

### 6.1 `BacktestRequest` / `StrategySpec`

后续应在 typed 策略回测请求主链中新增：

1. `marketEnvironmentProfile`

同时应重新解释现有字段：

1. `enableShortSelling` 不再是市场制度真源，而只能表示“在当前市场制度允许范围内，策略是否启用卖空”。
2. `useMarketOnClose` 不能再长期承担执行价格模型的唯一入口，后续应收口到环境解析后的 `executionPriceModel`。
3. `taxRate`、`commissionRate`、`slippageRate` 必须允许由环境档案给出默认值。

### 6.2 禁止的配置演进方式

禁止：

1. 新增 `isAShareStrategy` 之类布尔位。
2. 新增 `useTPlusOne` 和 `marketEnvironmentProfile` 并存。
3. 继续让 `enableShortSelling` 在不同市场里被解释成不同层级的语义而不显式拆分。

## 7. 四类 snapshot 的归属

当前策略结果配置会产出四类 snapshot：

1. `ruleProfileSnapshot`
2. `executionPolicySnapshot`
3. `backtestAssumptionsSnapshot`
4. `strategyScopeContextSnapshot`

后续市场环境字段应按下面方式归属。

### 7.1 `strategyScopeContextSnapshot`

放顶层环境选择：

1. `marketEnvironmentProfile`

职责：

- 表示当前策略/回测是在什么市场环境下解释。

### 7.2 `executionPolicySnapshot`

放执行制度派生字段：

1. `executionLagTradingDays`
2. `allowSameDaySellAfterBuy`
3. `shortSellingMode`
4. `executionPriceModel`
5. `priceLimitMode`

职责：

- 表示订单执行和成交边界。

### 7.3 `backtestAssumptionsSnapshot`

放研究和回测假设：

1. `returnAttributionMode`
2. `benchmarkProfile`
3. `riskFreeRateProfile`
4. `calendarProfile`
5. `costProfile`

职责：

- 表示回测收益解释和统计假设。

### 7.4 `ruleProfileSnapshot`

继续只放组合和风险规则，不放市场环境真源。

原因：

- 市场制度不是某条风控规则，而是所有规则运行的上位前提。

## 8. 运行时规则链对齐

### 8.1 `MarketContext`

当前 `MarketContext` 只有价格、时段、会话等信息。

后续建议新增：

1. `marketEnvironmentProfile`
2. `resolvedMarketEnvironmentSnapshot`

职责：

- 让运行时门禁知道自己处于哪种制度环境。

### 8.2 `marketEnvironmentGate`

当前 `marketEnvironmentGate` 是 `pending / blocked / live / shadow` 这类结果，不能表达环境配置本身。

后续必须拆分：

1. `marketEnvironmentProfile`：配置值。
2. `marketEnvironmentGate`：门禁结果。
3. `marketEnvironmentReason`：门禁失败原因。

禁止：

1. 继续只保留 `marketEnvironmentGate` 一个字段，让调用方自行猜测当前环境。

### 8.3 运行时门禁能力补齐方向

后续运行时门禁应逐步从“价格/时段门禁”扩成“市场制度门禁”，至少要覆盖：

1. 当前市场是否允许该方向的交易。
2. 当前市场环境下是否允许同日买卖。
3. 当前价格状态下是否受到涨跌停或价格带限制。
4. 当前时段下是否允许执行该类订单。

## 9. 结果合同对齐

后续策略回测和运行时规则结果里都应显式暴露：

1. `marketEnvironmentProfile`
2. `executionPriceModel`
3. `returnAttributionMode`

至少应保证：

1. 用户能知道当前策略收益是在什么市场制度下解释的。
2. 用户能区分“环境配置”与“环境门禁结果”。
3. 页面不需要依赖隐含默认市场假设来解释结果。

## 10. 缓存与测试对齐

### 10.1 缓存

策略回测缓存后续必须纳入：

1. `marketEnvironmentProfile`
2. `executionPriceModel`
3. `returnAttributionMode`

否则不同市场环境下的策略结果会错误复用。

### 10.2 测试

至少应新增下面几类测试：

1. `StrategyBacktestConfig` 对 `marketEnvironmentProfile` 的序列化和反序列化。
2. 四类 snapshot 对市场环境字段的归属正确性。
3. `StrategyRuntimeRuleEvaluator` 在不同市场环境下的门禁差异。
4. 策略回测在不同市场环境下的执行限制差异。
5. 缓存键在不同市场环境下不复用。

## 11. QML 与桥接层对齐

### 11.1 页面输入

策略回测页和风险/规则相关页面后续应新增统一市场环境选择器。

约束：

1. 页面只传枚举值。
2. 页面不自行维护 `isAShare` 这类布尔逻辑。
3. 页面布局要保持美观，不通过放大控件承载新功能。

### 11.2 桥接职责

桥接层只负责：

1. 把页面枚举值写入顶层配置和 snapshot。
2. 把枚举值映射成展示标签。

桥接层不负责：

1. 猜测市场环境。
2. 继续用旧字段兼容推断环境。

## 12. 推荐实施顺序

建议按下面顺序推进：

1. 先在 `StrategyBacktestConfig` 和四类 snapshot 中加入 `marketEnvironmentProfile`。
2. 再补 `ResolvedMarketEnvironment` 解析结构。
3. 然后把 `StrategyRuntimeRuleEvaluator` 改成读取同一环境配置。
4. 最后补结果合同、缓存键和测试矩阵。

## 13. 结论

策略回测链和运行时规则链的市场环境支持，关键不是零散增加几个 A 股特判，而是建立单一的环境合同，并把它分别落到：

1. 顶层配置
2. 四类 snapshot
3. 运行时上下文
4. 门禁输出
5. 缓存和测试

后续实现必须坚持同一原则：

1. 不保留同语义兼容字段。
2. 不保留歧义字段。
3. 严格按单一合同执行。
