# 策略规则服务 Python 端真实场景全面测试报告（2026-05-31）

> 版本声明：本文件为唯一生效的最终报告版本；同主题其他报告文件已下线。

## 1. 最终结论

- Python 端规则服务已实现，且在真实场景下可运行。
- 若采用“每次请求拉起 Python 进程”的子进程模式，高频场景稳定性不足：
  - 单信号场景 3/3 失败。
  - 批量（size=64）场景 3 轮中 1 轮失败，存在显著抖动风险。
- 若采用“常驻 Python worker”模式：
  - 批量与单信号场景 3/3 全部通过。
  - 延迟和吞吐显著优于子进程模式，且稳定性明显更好。
- 本地 C++ 路径仍是性能上限基线；Python worker 满足当前阈值目标，但不追求与本地 C++ 同级时延。

## 2. 真实场景测试定义

本报告中的“真实场景”按以下约束执行，不做理想化简化：

1. 使用 Release 构建产物（非仅 Debug）。
2. 同一代码快照下执行全部测试，避免跨版本比对偏差。
3. 每类性能基准连续执行 3 轮，考察稳定性与波动。
4. 保留 Python 进程创建成本：
- 子进程模式按原实现每请求启动 Python。
- worker 模式按常驻进程 + stdin 行协议。
5. 增加功能回归验证，确认性能优化未破坏行为正确性。

## 9. 风险评估与落地建议

1. 风险
- 若线上路径误回退到子进程模式，将在高频单信号场景发生明显退化，且存在批量波动超阈值风险。

2. 建议
- 生产默认策略：Python worker 或本地 C++，禁止高频路径使用子进程模式。
- 将“3 轮稳定性检查”纳入可选 CI 性能档位，作为回归门禁。

## 11. 构建告警审计（本轮实测补充）

本轮 Release 构建完成（exit code 0），但存在两类编译告警：

1. 第三方头文件编码告警（大量 C4828）
- 来源：thirdparty/gmsdk/gmdef.h
- 现象：文件中若干字符在当前源字符集下无效（代码页 65001）
- 影响评估：
  - 当前为 Warning，不阻断构建；
  - 来源于第三方头文件，短期不建议直接改 vendor 文件。

2. 自有代码枚举范围告警（C4369）
- 来源：src/engine/include/Event/topic/EventType.hpp
- 现象：EventSource 的底层类型为 uint8_t，但 CUSTOM 枚举值定义为 1000，发生截断告警（1000 -> 232）
- 影响评估：
  - 该告警不是纯噪音，属于潜在语义风险；
  - 如果业务依赖 CUSTOM=1000 语义，当前定义会在底层存储层面失真。

处置建议（按优先级）：

1. 立即纳入待修复项（高优先级）
- 处理 EventSource::CUSTOM 的类型和值一致性问题（要么调整底层类型，要么调整取值范围）。

2. 第三方编码告警治理（中优先级）
- 通过构建参数或告警策略对 thirdparty 目录单独处理，避免污染主项目告警视图；
- 不直接修改 vendor 源，除非后续确认可维护补丁策略。
