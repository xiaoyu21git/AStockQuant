# 因子回测数据字段与表映射分析

## 1. 当前库内因子类型分布

基于 `factors` 表当前统计：

- 价值因子：3
- 动量因子：2
- 低波因子：1
- 技术因子：1
- 流动性因子：1
- 红利因子：1
- 规模因子：1
- 活跃实例总数：10

这说明当前回测入口最核心的数据保障应优先覆盖：

- 价值因子
- 动量因子
- 规模因子
- 低波因子
- 质量因子

其中价值/动量/规模/低波直接强依赖日线主表，质量/成长依赖财务表。

## 2. 当前运行时真实支持情况

### 2.1 已有独立运行时实现，可直接进入因子回测

- 动量因子
- 价值因子
- 规模因子
- 质量因子
- 低波因子

对应实现位置：

- `src/domain/factor/src/MomentumFactor.cpp`

### 2.2 已在配置层声明字段需求，但当前运行时未完整接入

- 因此它们不能等同看作“已经可稳定回测”

## 3. 因子类型 -> 依赖字段 -> 来源表

### 3.1 动量因子

来源实现：`MomentumFactor::getDataRequirements()`

必需字段：

- `close`

可选字段：

- `adj_factor`
- `volume`（仅 `useVolume=true`）

主来源表：

- `daily_bar`

备注：

- 当前动量回测桥接路径里还会用到 `cleaned_daily_bar` 计算某些批量值
- 但缓存回测场景下，本质还是依赖日线价格序列

### 3.2 价值因子

来源实现：`ValueFactor::selectedColumn()`

按参数分支依赖：

- `pe_ratio`
- `pb_ratio`
- `market_cap`

主来源表：

- `daily_bar`

备注：

- 这是当前最容易暴露“字段存在但值全为 0”的类型
- 所以日线主表必须保证估值列不是只建了字段名而没有有效值

### 3.3 规模因子

来源实现：`SizeFactor::selectedColumn()`

依赖字段：

- `market_cap`
- `circulating_market_cap`

主来源表：

- `daily_bar`

### 3.4 低波因子

来源实现：`LowVolFactor::getDataRequirements()`

依赖字段：

- `close`

主来源表：

- `daily_bar`

备注：

- 低波因子不是只要当天 `close`，而是要一个窗口期内连续 `close` 序列
- 因此它对历史连续性要求高

### 3.5 质量因子

来源实现：`QualityFactor::getDataRequirements()`

按参数分支依赖：

- `roe`
- `roa`
- `profit_margin`
- `net_profit`
- `equity`

主来源表：

- `financial_indicator`

### 3.6 成长因子（配置层已声明）

来源：`FactorService::buildDataRequirementsConfig()`

依赖字段：

- `total_revenue`
- `net_profit`
- `eps`

主来源表：

- `financial_indicator`

备注：

- 配置层和桥接层已经按财务表设计
- 但当前域模型回测运行时未完成独立 GrowthFactor 实现

### 3.7 红利因子（配置层已声明，但当前底层字段未接通）

来源：`FactorService::buildDataRequirementsConfig()`

依赖字段：

- `dividend_yield`
- `payout_ratio`
- `dividend_stability`（可选）

理论来源表：

- `daily_bar / financial_indicator` 之外的分红数据来源

当前状态：

- 运行时明确提示未接入实际底层字段
- 不能作为当前稳定回测类型

### 3.8 技术因子（配置层已声明）

## 7. 当前最重要的工程结论

### 7.1 日线主表不应该只“有字段名”

当前回测真正需要的，不只是返回字段名，还包括这些字段在最近交易日有有效值：

- `close`
- `volume`
- `turnover`
- `turnover_rate`
- `pe_ratio`
- `pb_ratio`
- `market_cap`
- `circulating_market_cap`

尤其：

- 价值因子依赖 `pe_ratio/pb_ratio/market_cap`
- 规模因子依赖 `market_cap/circulating_market_cap`

如果这些列最近全为 0，字段虽然“返回了”，但回测仍然不可用。

### 7.2 对“日线返回哪些字段”的明确要求

对因子回测而言，`daily_bar` 建议固定返回以下有用字段，不要再做缩减：

- `symbol`
- `trade_date`
- `open`
- `high`
- `low`
- `close`
- `pre_close`
- `volume`
- `turnover`
- `change_pct`
- `change_amt`
- `amplitude`
- `turnover_rate`
- `pe_ratio`
- `pb_ratio`
- `market_cap`
- `circulating_market_cap`
- `data_source`

这套字段已经基本覆盖当前可回测因子和已规划因子的主需求。

### 7.3 哪些因子当前主要由日线支持

仅从字段层和运行时层综合判断，`daily_bar` 当前直接支撑：

- 动量因子
- 价值因子
- 规模因子
- 低波因子

`daily_bar` 对以下类型提供主要字段基础，但运行时仍待补完：

- 技术因子
- 流动性因子

`financial_indicator` 当前直接支撑：

- 质量因子

`financial_indicator` 对以下类型提供字段基础，但运行时仍待补完：

- 成长因子

当前仍缺底层数据接入：

- 红利因子

## 8. 建议的下一步

### 8.1 数据返回侧

保持 `DataService::fetchPriceTableData()` 对 `daily_bar` 使用 `SELECT *`，不要裁剪为少数字段。

### 8.2 数据质量侧

重点修复最近交易日 `daily_bar` 中下列字段的有效值覆盖：

- `pe_ratio`
- `pb_ratio`
- `market_cap`
- `circulating_market_cap`

### 8.3 回测入口侧

前置检查不应只判断“字段存在”，还应判断最近交易日这些关键字段是否有有效值。当前已开始补这层诊断。
