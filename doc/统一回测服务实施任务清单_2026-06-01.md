# 统一回测服务实施任务清单（10分钟目标，2026-06-01）

## 0. 使用说明

- 本清单用于直接创建开发工单与阶段验收。
- 全部任务遵循三条红线：
  - 零 Qt 下沉（Qt 仅允许出现在 QML 入口桥接层）
  - 零兼容回退（不保留旧口径兜底链路）
  - 零字符串业务合同（核心判断仅用强类型/枚举）
- 性能总目标：全市场 5 年日频回测在 10 分钟内完成。

---

## 0.5 Phase 0 - 旧链路拆除（只删除，不新增）

### P0-T1 删除重复执行链路入口
- 目标：先删除因子回测旧执行链入口，避免双主链并存。
- 输入：现有 bridge/controller 调用路径。
- 输出：旧入口断链，保留单链迁移空间。
- 验收标准：
  - 不再直接调用旧因子批执行入口。
  - 不再存在“预览链 + 主执行链”并行执行路径。
- 阻断条件：删除后仍可从 controller 进入旧执行器主链。

### P0-T2 删除旧预览适配链
- 目标：删除不符合统一回测服务目标的因子预览适配链。
- 输入：application/trading 因子预览与适配器文件。
- 输出：预览链路文件、构建入口、调用点移除。
- 验收标准：
  - 旧预览服务和因子适配器源码已移除。
  - bridge 不再依赖旧预览服务头文件。
- 阻断条件：旧预览服务仍参与构建或仍被 bridge include。

### P0-T3 删除不符合新合同的回退路径
- 目标：删除核心流程中与新合同冲突的兼容/回退分支。
- 输入：controller/service 中旧兼容逻辑。
- 输出：相关回退逻辑删除。
- 验收标准：
  - 关键流程不再依赖旧兼容字段回退。
  - 缺失关键字段时直接失败。
- 阻断条件：仍存在旧字段兜底继续执行。

### P0 阶段 DoD
- 重复链路已拆除，旧执行入口不可达。
- 旧预览适配链已从构建与调用点清除。
- 后续阶段可在单主链基础上推进。

### P0 附录 - 复用隔离清单（先隔离后重建）

可复用保留：
- domain/backtest 现有抽象能力模块（窗口、风控、构单、估值、指标、调度相关抽象）。
- domain/factor 内可复用因子计算能力（后续仅作为信号插件接入）。

待删除（不符合统一单服务目标）：
- application/trading 因子预览适配链（旧并行链）。
- bridge 层直接拼接旧预览诊断的路径。

本轮已执行删除：
- 从 application_trading 构建源移除旧因子预览适配链。
- 删除旧因子预览服务与因子适配器头/源文件。
- 删除 bridge 对旧预览链 include 与诊断调用。

## 1. Phase 1 - 合同与编排骨架

### P1-T1 纯类型合同落地
- 目标：建立统一 BacktestRunSpec、BacktestRunResult、SignalSet、OrderSet、FillSet typed 合同。
- 输入：现有回测请求字段、现有结果字段。
- 输出：统一 typed 合同头文件与基础校验。
- 验收标准：
  - 合同字段不包含字符串语义判断字段。
  - DateKey 仅接受交易日，非法输入返回枚举错误码。
- 阻断条件：发现字符串业务字段仍参与核心流程判断。

### P1-T2 统一编排器骨架
- 目标：落地 7 阶段统一流水线（ValidateSpec -> Done）。
- 输入：BacktestRunSpec。
- 输出：可执行的阶段框架、阶段状态机、错误码输出。
- 验收标准：
  - 阶段切换可观测，失败 fail-fast。
  - 返回结构包含 ProgressSnapshot。
- 阻断条件：出现因子路径/策略路径双主链。

### P1-T3 无 Qt 核心构建目标
- 目标：建立独立服务核心构建目标并禁止 Qt 链接。
- 输入：现有 CMake 目标结构。
- 输出：纯核心 target + 规则门禁。
- 验收标准：
  - Core target 不链接 Qt。
  - 核心目录 Qt include 扫描为 0。
- 阻断条件：核心模块中出现 Qt 类型。

### P1-T4 错误目录与展示映射
- 目标：建立 ErrorCode 到展示文案的单向映射目录。
- 输入：ServiceErrorCode 列表。
- 输出：ErrorCatalog（仅桥接层使用文本）。
- 验收标准：
  - 核心层不依赖展示文本。
  - 错误处理仅使用枚举。
- 阻断条件：核心层直接拼接字符串错误语义。

### P1 阶段 DoD
- Core 构建目标无 Qt 依赖。
- 合同纯 typed，流程可运行。
- 基础合同测试、状态机测试通过。

## 2. Phase 2 - 因子模块接入（复用）

### P2-T1 因子信号适配器
- 目标：将现有因子服务输出适配为统一 SignalSet。
- 输入：现有因子服务结果。
- 输出：FactorSignalAdapter。
- 验收标准：
  - 适配器仅做字段映射，不复制因子算法。
  - SignalSet 支持批量时间窗输出。
- 阻断条件：出现重复实现因子计算逻辑。

### P2-T2 统一后半链路打通
- 目标：因子信号接入统一构单、执行、指标链路。
- 输入：SignalSet。
- 输出：OrderSet、FillSet、MetricsSnapshot。
- 验收标准：
  - 后半链路仅有一套实现。
  - 无来源特判分支污染主流程。
- 阻断条件：因子专用执行分支重新出现。

### P2-T3 新旧一致性对比测试
- 目标：确保迁移不改变既有结果语义。
- 输入：固定回放数据集与固定参数。
- 输出：差异报告。
- 验收标准：
  - 订单序列一致。
  - 最终绩效一致。
  - 任一差异均有溯源结论和修复记录。
- 阻断条件：差异未闭环即推进下一阶段。

### P2 阶段 DoD
- 因子服务以插件形式接入成功。
- 新旧一致性通过。
- 回归套件通过。

## 3. Phase 3 - 策略信号接入

### P3-T1 策略信号批接口实现
- 目标：策略侧实现 evaluate_batch(time_window, instruments) 等价接口。
- 输入：策略规则引擎输出。
- 输出：StrategySignalEngine。
- 验收标准：
  - 批接口稳定，不走逐日回调主路径。
  - 输出为统一 SignalSet。
- 阻断条件：策略接口仍以逐条调用为主执行路径。

### P3-T2 统一链路接入
- 目标：策略信号接入同一后半链路。
- 输入：Strategy SignalSet。
- 输出：统一回测结果。
- 验收标准：
  - 无第二条执行主链。
  - 枚举错误码与阶段状态一致。
- 阻断条件：策略专用核心链路分叉。

### P3-T3 合同稳定性测试
- 目标：验证因子/策略双来源在统一合同下稳定运行。
- 输入：双来源样例任务。
- 输出：合同稳定性报告。
- 验收标准：
  - 合同字段无新增语义漂移。
  - 无字符串协议回流。
- 阻断条件：出现来源特化字段进入核心合同。

### P3 阶段 DoD
- 策略信号批接口上线。
- 因子与策略共用统一主链。
- 合同稳定性报告通过。

## 4. Phase 4 - 性能压测与收敛（10分钟）

### P4-T1 二维并行调度器落地
- 目标：实现日期块 × 标的块二维并行（核心必选）。
- 输入：交易日历与标的池。
- 输出：统一任务切分与调度组件。
- 验收标准：
  - 任务块划分可配置。
  - 支持动态窃取。
  - 窗口对齐正确。
- 阻断条件：仅保留单维并行或串行回退路径。

### P4-T2 列式 mmap 与零拷贝读路径
- 目标：强制列式文件读取与分块加载。
- 输入：标准化行情/因子文件。
- 输出：mmap 数据加载通道。
- 验收标准：
  - 无一次性全量无界加载。
  - 主路径无不必要拷贝。
- 阻断条件：落回行式全量读主路径。

### P4-T3 内存池化与零分配循环
- 目标：控制内存抖动并稳定尾延迟。
- 输入：Signal/Order/Fill 缓冲模型。
- 输出：池化分配器与容量上限策略。
- 验收标准：
  - 核心循环零动态分配。
  - 缓冲区有硬上限。
- 阻断条件：出现无界缓存或循环内反复分配。

### P4-T4 预算闸门与提前终止
- 目标：实现毫秒级预算检查与 PartialResult 返回。
- 输入：RuntimeBudget。
- 输出：阶段预算检查器与提前终止协议。
- 验收标准：
  - 阶段级预算检查生效。
  - 主循环增量检查生效。
  - 超限返回 RuntimeExceeded + PartialDiagnostics。
- 阻断条件：预算超限仍继续完整执行。

### P4-T5 优化器超时治理
- 目标：约束组合优化耗时波动。
- 输入：优化器参数。
- 输出：迭代上限、超时上限、降级策略。
- 验收标准：
  - 超时可返回次优可行解或跳过当次再平衡。
  - 诊断码可追踪。
- 阻断条件：求解超时无保护导致整体超时。

### P4-T6 异步无锁记录通道
- 目标：减少日志/序列化对计算线程干扰。
- 输入：运行时事件。
- 输出：异步无锁队列 + 双缓冲序列化。
- 验收标准：
  - 计算线程不阻塞落盘。
  - 记录链路可复盘。
- 阻断条件：同步 I/O 出现在核心计算线程。

### P4-T7 性能基线与抗退化门禁
- 目标：建立性能基线并纳入 CI 阻断。
- 输入：标准压测场景（5000 标的、5 年日频、20 因子）。
- 输出：基线报告与 CI 规则。
- 验收标准：
  - 总耗时 <= 10 分钟。
  - 核心链路性能退化 > 10% 自动阻断。
  - 阶段预算超限比例超过阈值自动阻断。
- 阻断条件：无基线直接合并性能相关 PR。

### P4 阶段 DoD
- 全市场 5 年日频任务在 10 分钟内完成。
- 二维并行、批接口、池化内存、预算提前终止全部验收通过。
- CI 抗退化门禁生效。

## 5. 跨阶段公共工单

### C-T1 CI Qt 下沉扫描
- 命令建议：

```bash
rg "#include\s*<Qt|\bQString\b|\bQDate\b|\bQVariant\b" src/domain/backtest src/application/trading
```

- 验收标准：扫描结果必须为空。

### C-T2 可复现性保障
- 目标：并行归约确定性，确保重复运行结果一致。
- 验收标准：固定输入多次运行得到一致结果。

### C-T3 文档与契约同步
- 目标：合同变更必须同步文档与测试。
- 验收标准：合同版本、测试用例、文档三者一致。

## 7. 评审通过后执行顺序

1. 先完成 Phase 0，执行“只删除，不新增”的旧链路拆除。
2. 再完成 Phase 1 全部任务并冻结合同。
3. 然后推进 Phase 2 与一致性对比，不通过不进入 Phase 3。
4. Phase 3 完成后立刻建立性能基线，再进入 Phase 4。
5. Phase 4 期间所有性能相关改动必须受 CI 抗退化门禁保护。
