## 4. 当前单一执行口径

### 4.1 分层口径

1. UI/QML 仅负责展示和输入收集。
2. Bridge 仅负责边界转换，不承载运行时主链。
3. Application 负责编排与任务生命周期。
4. Domain 负责策略、回测、规则等强类型语义。
5. Execution 负责回测循环、规则闸门、执行模拟、结果装配。
6. Persistence 负责持久化适配，不外泄数据库字段语义。

### 4.2 类型口径

1. 运行时主链使用强类型合同。
2. 禁止字符串键和动态 map 作为业务真源。
3. QVariantMap/QVariantList 仅允许停留在 QML 边界。
4. 缺失关键字段直接失败，不允许回退补写。

### 4.3 引擎口径

1. 保留策略回测执行器与因子研究执行器双上层。
2. 收敛为一套公共回测数据底座。
3. 禁止策略链继续扩写第二套 HistoricalView 或逐日股票池真源。

### 4.4 规则口径

1. overlay 是候选排序与截断规则，不是新股票池来源。
2. 规则模板承担入场阻断与强制退出。
3. 交易记录语义保持 side + positionEffect 拆分，不再压平为 direction。

## 5. 实施优先级（执行顺序）

1. 先按 `策略回测核心重构设计与旧链路清除方案` 完成旧链路清理。
2. 再按 `策略回测与因子回测公共底座收敛方案` 完成公共底座抽取与双链路收口。
3. 最后按 `策略回测引擎实现约束` 补齐策略回测新引擎生产依赖并接线。
