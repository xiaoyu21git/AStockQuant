### 4.2 TradingSystem.cpp

把 `StrategyOrderForwarder::onOrders()` 的逻辑下沉到这里，加上回调通知和返回值处理：

```cpp
void TradingSystem::onOrders(
    const std::vector<domain::strategy::OrderRequest>& orders)
{
    for (const auto& req : orders) {
        if (!req.isValid()) continue;

        // ── ① Symbol 解析（从 StrategyOrderForwarder 搬来）──
        char buf[16];
        std::snprintf(buf, sizeof(buf), "%06u",
                      req.instrumentId().value);
        const std::string symbol =
            foundation::market::AStockSymbol::fromCode(buf).fullSymbol();

        // ── ② OrderRequest → TradeOrder ──
        domain::trading::TradeOrder order;
        order.setSymbol(symbol);
        order.setSide(req.side() == domain::strategy::RuntimeOrderSide::Buy
                          ? domain::strategy::OrderDirection::Buy
                          : domain::strategy::OrderDirection::Sell);
        order.setQuantity(static_cast<std::int64_t>(req.quantity()));
        order.setStrategyId(std::to_string(req.strategyInstanceId()));
        order.setPrice(latestPrice(symbol));

        // ── ③ 回调：订单已产生（无论后续提交结果如何）──
        if (m_onOrderGenerated) {
            m_onOrderGenerated(order);
        }

        // ── ④ 无价格时通知 ──
        if (order.price() <= 0.0) {
            if (m_onOrderSubmitResult) {
                auto r = domain::trading::SubmitResult::rejected(
                    "no latest price");
                m_onOrderSubmitResult(order, r);
            }
            continue;
        }

        // ── ⑤ 提交并通知结果 ──
        auto result = submitOrder(order);
        if (m_onOrderSubmitResult) {
            m_onOrderSubmitResult(order, result);
        }
    }
}
```

**新增约 40 行**，逻辑来自 StrategyOrderForwarder 的平移 + 回调通知。


## 六、线程安全

```
drainQueue() 线程                    主线程
─────────────────                   ─────────
onOrders() 执行                       
  ├─ 只读 m_latestPrices (mutex)     
  ├─ m_onOrderGenerated(order)       → QMetaObject::invokeMethod
  │   (std::function, 线程安全)         └─ emit orderGenerated()
  ├─ submitOrder() (内部 mutex)
  └─ m_onOrderSubmitResult(...)      → QMetaObject::invokeMethod
      (std::function, 线程安全)         └─ emit orderSubmitResult()
```

- `onOrders` 在后台线程执行
- 回调中构造 `QVariantMap` 在后台线程
- `QMetaObject::invokeMethod(Qt::QueuedConnection)` 确保 `emit` 在主线程
- 回调在 `StrategyManager::startStrategy()` 注册（早于 `startLiveLoop()`），无竞争

## 九、回测兼容设计（关键）

### 9.1 核心论证：回测是否触发 IOrderListener

回测路径在 `StrategyEngine::backtest()` 中（[StrategyEngineFacade.cpp:817-968](src/domain/strategy/src/StrategyEngineFacade.cpp#L817-L968)）：

```cpp
// 回测逐日循环：
for (int r = 0; r < totalDays; ++r) {
    auto batch = dataSvc->loadBatch(0);
    // ... 构建 mdpBatch ...
    auto ordersOpt = stepBatch(mdpBatch);   // ← 直接调用，获取返回值
    if (ordersOpt.has_value()) {
        for (const auto& order : ordersOpt.value()) {
            // 风控检查 + BacktestFillSimulator 模拟成交
            // ...
        }
    }
    // 更新权益曲线...
}
```

**关键事实**：回测调用 `stepBatch()` 获取返回值后，用 `RiskEvaluator` + `BacktestFillSimulator` 在循环内直接模拟成交。**回测路径从不调用 `m_orderListener`**。

代码中 `m_orderListener->onOrders()` 唯一调用点在 [StrategyEngineFacade.cpp:578-579](src/domain/strategy/src/StrategyEngineFacade.cpp#L578-L579)，属于 `drainQueue()` 实盘后台线程：

```cpp
void StrategyEngine::drainQueue() {
    while (m_loopRunning) {
        // ...
        auto orders = step(mdp);
        if (orders.has_value() && m_orderListener) {
            m_orderListener->onOrders(*orders);  // ← 仅实盘路径
        }
    }
}
```

**结论**：将 `TradingSystem` 注册为全局 `IOrderListener` 不会导致回测订单误发到真实网关，因为：

| 路径 | 触发方式 | 是否调 IOrderListener | 订单去向 |
|------|---------|---------------------|---------|
| 实盘 `drainQueue()` | `m_orderListener->onOrders()` | ✅ 是 | TradingSystem → 网关 |
| 回测 `backtest()` | `stepBatch()` 返回值直接处理 | ❌ 否 | RiskEvaluator + FillSimulator 内联 |

### 9.2 双重保险

尽管当前代码已天然隔离，为防御未来改动在回测路径中引入 `m_orderListener` 调用，增加以下防护：

1. **`StrategyEngine` 增加回测模式标记**：`backtest()` 方法入口设置 `m_isBacktestMode = true`，出口还原。`onOrders()` 调用前判定此标记，回测模式下跳过监听器通知并打印 WARNING 日志。
2. **`TradingSystem::onOrders()` 判空保护**：即使被意外调用，内部 `submitOrder()` 判空 `m_tradeEngine`，未初始化时返回 rejected 而非崩溃。回调 `m_onOrderSubmitResult` 将通知 QML "交易引擎未初始化"。

```cpp
// StrategyEngineFacade.cpp drainQueue() 中增加一层防御：
if (orders.has_value() && m_orderListener && !m_isBacktestMode) {
    m_orderListener->onOrders(*orders);
}
```

### 9.3 strategyInstanceId 映射说明

`OrderRequest::strategyInstanceId()` 返回 `StrategyInstanceId`（`uint32_t` 内部索引）。当前 `StrategyOrderForwarder` 通过 `std::to_string()` 转为字符串存入 `TradeOrder::strategyId`。`StrategyManager` 维护 `instanceId → strategyId` 映射，但当前链路上未做此映射。这是**已有缺陷**，不是本次改动引入。后续可在 `TradingSystem::onOrders()` 或回调中补充，不在本次改动范围。

## 十一、线程安全前置条件（显式声明）

`TradingSystem::onOrders()` 在 `drainQueue()` 后台线程执行。其内部调用链线程安全性前置条件：

| 调用 | 保护机制 | 说明 |
|------|---------|------|
| `latestPrice(symbol)` | `TradingSystem::m_priceMutex` | [TradingSystem.cpp:174](src/app/system/TradingSystem.cpp#L174) — 已验证 |
| `submitOrder()` → `buildRiskInput()` | `PositionAccountEngine::m_mutex` | 读取持仓/账户有锁保护 |
| `submitOrder()` → `m_tradeEngine->submitOrder()` | `TradeExecutionEngine` 内部 mutex | 执行引擎自身线程安全 |
| `m_onOrderGenerated()` / `m_onOrderSubmitResult()` | `std::function` 可重入 | 调用方不持锁，回调内不回调 |

**事实**：当前 `StrategyOrderForwarder` 已在同一线程同一位置调用 `submitOrder()`，系统已运行在此假设之上。本次改动不改变调用线程，不引入新的线程安全风险。

## 十二、回调生命周期安全

| 风险点 | 处理方式 |
|--------|---------|
| 回调未注册时调用 | `if (m_onOrderGenerated)` / `if (m_onOrderSubmitResult)` 判空后调用 |

| `TradingSystem` 单例析构 | 单例在 `main()` 退出时析构，晚于所有线程停止 |

## 十三、接口依赖方向说明

`TradingSystem` 继承 `domain::strategy::IOrderListener` 的依赖方向：

```
domain::strategy::IOrderListener     ← 接口定义
         ↑
         │ 继承（依赖倒置——app 依赖 domain 接口，符合分层）
         │
app::system::TradingSystem           ← 实现
```

`TradingSystem` 已有 `#include "../../domain/strategy/include/RiskEvaluator.h"` 和 `#include "../../domain/trading/..."` ，新增 `IStrategyService.h` 不改变依赖方向。`app::system → domain` 是合法的自上而下依赖。
