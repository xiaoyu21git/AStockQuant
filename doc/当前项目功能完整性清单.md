# 当前项目功能完整性清单

更新日期：2026-05-06

## 口径说明

本文回答的是“从产品完整性角度看，当前工程还有哪些业务链没有闭环”。

- 它是项目级功能盘点，不等同于版本里程碑验收。
- [doc/0.10.x推进版必须完成清单.md](./0.10.x推进版必须完成清单.md) 关注的是推进版是否完成“因子链收口、清洗优化、迁移准备、稳定测试基线”。
- [doc/1.0.0正式版必须完成清单.md](./1.0.0正式版必须完成清单.md) 关注的是正式发布基线是否具备“主链闭环、真源统一、主库清晰、回归稳定”。
- 因此，本文里列出的“产品仍未完成能力”，不必然都是 0.10.x 或 1.0.0 的硬阻塞项；但它们仍然是项目走向完整产品前必须面对的缺口。

## 结论摘要

AStockQuantEngine 当前已经具备可运行的核心骨架，但尚未达到功能完整状态。

- 可用性较高的部分：事件系统、基础数据桥接、策略回测主链、数据管理主页面、因子回测主执行链
- 部分完成的部分：因子工作台、策略库、策略创建、风险配置、仪表盘展示
- 明显未完成的部分：组合构建真实业务化、策略优化闭环、第三方平台全面接入、风险引擎执行链

当前最准确的定位是：

一个已经具备核心量化底座和部分业务闭环的桌面量化终端雏形，而不是仅有界面的原型；但距离完整产品仍有明显缺口。

## 验证结果

### 1. 工程与测试状态

- 当前 src、tests、astock_engine 目录静态错误检查通过
- C++ 测试可执行文件可独立运行
- 已执行 build/tests/test_eventsystem.exe
- 测试结果：当前可独立运行的 C++ 主测试可执行文件已覆盖 EventBus、并发、压力、因子回归等主链；更细的测试口径以 [astock_engine/tests/TEST_SUMMARY.md](../astock_engine/tests/TEST_SUMMARY.md) 和 [astock_engine/tests/TEST_GUIDE.md](../astock_engine/tests/TEST_GUIDE.md) 为准

### 2. 当前判断标准

本清单按以下四档评估：

- 已完成：主业务链可运行，非演示数据驱动，有验证依据
- 部分完成：主体存在，但仍有缺失入口、占位逻辑或未接完整服务
- 演示页：页面结构完成，但主要依赖本地模拟数据或展示性逻辑
- 未完成：仅有入口、占位按钮或底层服务缺失

## 模块级清单

### 1. 事件系统

状态：已完成

判断依据：

- 现有测试覆盖最完整
- 包含基础、并发、压力、领域集成测试
- 当前是整个项目里工程质量最高、验证最充分的模块之一

### 2. 数据管理与缓存

状态：已完成

判断依据：

- DataFetchController、DataCleaningEngine、DataServiceCache、DataManager 等桥接与服务均存在
- 数据管理页已接真实查询和清洗入口
- 支持缓存数据清洗和多类型数据拉取

### 3. 因子系统

状态：部分完成

判断依据：

- 因子库、创建、调试、分析、回测五模式架构已搭建完成
- FactorService、FactorParamController、FactorMetaService、FactorViewModel 均已存在
- 公共参数主链、主要因子 runtime 和回测执行主链已基本打通
- 但个性化参数仍有少量“只解析、不改结果”的残留，旧字段兼容与运行时回退也还没有全部删除
- 因子回测结果页里的详细结果、对比分析、导出仍未完成

### 4. 策略回测系统

状态：已完成

判断依据：

- 存在真实策略回测控制器与服务链
- 已有回测回归测试通过
- 最近阶段已完成结果标准化、绩效回写和页面主链修复

限制说明：

- 高级股票池解析、过滤、参数组合生成仍有 TODO
- 因此“基础回测已完成”，但“高级优化能力未完成”

### 5. 策略管理系统

状态：部分完成

判断依据：

- 策略创建页、策略库页、策略回测页之间已经形成主链
- 策略卡片、表现图、历史回测展示已较完整
- 但策略优化入口仍未实现，策略库页近期仍在修运行时稳定性问题

### 6. 风险管理系统

状态：部分完成

判断依据：

- 风险配置元数据加载、动态参数配置、风险摘要显示已经落地
- 但保存和应用逻辑仍停留在页面层占位
- 尚无明确证据表明存在已接通的风险规则引擎、监控告警链和执行联动

### 7. 组合构建系统

状态：演示页

判断依据：

- 页面以模拟收益、静态因子池、静态行业暴露、静态通知驱动
- 尚无真实组合优化、权重求解、约束回测或持仓回写链路

### 8. 交易执行与第三方接入

状态：未完成

判断依据：

- ThirdPartyApi 工厂中，除掘金方向外，聚宽、米筐、TuShare、自定义平台均直接抛出“尚未实现”
- 仪表盘交易面板仍为固定展示值
- 没有看到完整下单、回报、成交、撤单的 UI 到服务闭环

## 当前可视为“能工作的主链”

目前较可信的主链是：

1. 数据准备与清洗
2. 因子库与因子编辑
3. 策略创建
4. 策略回测执行
5. 回测结果展示
6. 结果回写到策略库展示

这条链路已经具备产品雏形意义。

## 当前尚未闭环的链路

以下链路仍不能视为完成：

1. 因子回测详细分析与导出闭环
2. 策略优化闭环
3. 风险配置到风险引擎执行闭环
4. 组合构建到真实组合分析闭环
5. 仪表盘交易面板到真实交易执行闭环
6. 多第三方平台统一接入闭环

## 建议的优先级

如果接下来以“补项目完整性”为目标，而不是只做版本里程碑收口，建议按以下顺序推进：

1. 补齐因子回测缺失入口，并删除剩余个性化参数兼容/回退残留
2. 继续收口数据清洗主链、性能热点和质量链路
3. 明确 PostgreSQL 主库边界与迁移执行条件
4. 风险配置页接入真实保存、加载和应用逻辑
5. 组合构建页去演示化，接入真实数据和真实组合服务
6. 再推进策略优化链路与第三方平台接入

## 最终结论

当前项目不应再按“纯界面重构”优先处理，而应转向“功能收口”。

后续判断一项功能是否算完成，应以是否具备真实数据、真实服务调用、真实结果输出和可验证回归为标准，而不是以页面是否已经成型为标准。

如果是判断 0.10.x 或 1.0.0 是否可验收，应分别以 [doc/0.10.x推进版必须完成清单.md](./0.10.x推进版必须完成清单.md) 和 [doc/1.0.0正式版必须完成清单.md](./1.0.0正式版必须完成清单.md) 的版本口径为准，而不是直接拿本文中的“产品仍有缺口”逐条等同为版本阻塞项。
