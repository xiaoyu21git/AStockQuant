## 1. [HIGH] float32 数据类型迁移

### 目标

将因子信号矩阵从 double (8 字节) 迁移为 float32 (4 字节)，内存占用减半、缓存命中率提升、内存带宽翻倍。

### 当前状态

- SignalTensorBuffer::values 类型：std::vector<double>
- NumericConstMatrixView 底层数据类型：double
- 所有算子接口返回 std::vector<double>

### 实施步骤

**步骤 1：新增 Float32 类型别名**

在 FactorSignalTypes.h 中添加：

```cpp
using signal_value_t = float;   // 原为 double
static constexpr signal_value_t kDefaultSignalValue = 0.0f;
```

**步骤 2：迁移 SignalTensorBuffer**

```cpp
struct SignalTensorBuffer final {
    std::vector<float> values;   // 原 std::vector<double>
    std::vector<uint8_t> mask;   // 保持不变
    int32_t timeCount{0};
    int32_t instrumentCount{0};
    int32_t factorCount{0};
};
```

**步骤 3：迁移 NumericConstMatrixView**

```cpp
struct NumericConstMatrixView final {
    const float* data{nullptr};  // 原 const double*
    int32_t rowCount{0};
    int32_t columnCount{0};
};
```

**步骤 4：迁移 IMarketDataView 接口** — 所有返回 NumericConstMatrixView 的方法底层数据改为 float

**步骤 5：迁移 IFactorComputeDispatcher**

```cpp
FactorResult<std::vector<float>> evaluateOnClose(
    NumericConstMatrixView closeView,
    ComputeFunctionToken token);
```

**步骤 6：精度验证** — float32 与 double 结果差异 < 1e-6，分层收益方向一致无反转

### 受影响文件清单

| 文件 | 变更 |
|------|------|
| FactorSignalTypes.h | 添加 signal_value_t 别名 |
| IMarketDataView.h | NumericConstMatrixView 改为 float |
| SignalTensorBufferPool.h | 缓冲池类型改为 float |
| ParquetMarketDataView.cpp | Parquet 读取改为 float |
| FactorComputeEngine.cpp | 所有 double -> float |
| FactorComputeDispatcher.cpp | 算子返回值改为 float |
| CachedMarketDataView.cpp | 缓存值类型改为 float |

### 验收标准

- 相同入参下 float32 与 double 结果相关性 > 0.999
- 因子分层收益方向无反转
- 内存峰值降低 >= 45%
- 所有单元测试通过

## 2. [HIGH] SIMD 向量化加速

### 目标

在关键热点循环中引入 SIMD 指令，因子计算和信号生成吞吐量提升 2x-8x。

### 当前状态

- 无显式 SIMD intrinsic
- 无编译器向量化编译指示
- ParallelChunkScheduler 已设计 SIMD 对齐参数 kSimdAlignmentSize = 4 但未实际使用

### 实施步骤

**步骤 1：确定热点路径**（按耗时）

1. 因子计算路径 (FactorComputeDispatcher::evaluateOnClose)
2. 缺失值处理循环 (fillSingleFactorSlice)
3. 后处理 Pipeline (PostProcessingPipeline::run)

**步骤 2：封装 SIMD 适配层**

新增 SIMDAdapter.h，封装平台相关 intrinsic：

```cpp
namespace factor::compute::simd {

#if defined(__AVX2__)
    constexpr int kVectorWidth = 8;
    using VectorType = __m256;
    inline VectorType load(const float* p) { return _mm256_loadu_ps(p); }
    inline void store(float* p, VectorType v) { _mm256_storeu_ps(p, v); }
    inline VectorType add(VectorType a, VectorType b) { return _mm256_add_ps(a, b); }
    inline VectorType mul(VectorType a, VectorType b) { return _mm256_mul_ps(a, b); }
    inline VectorType fma(VectorType a, VectorType b, VectorType c) { return _mm256_fmadd_ps(a, b, c); }
#elif defined(__ARM_NEON)
    constexpr int kVectorWidth = 4;
    using VectorType = float32x4_t;
    inline VectorType load(const float* p) { return vld1q_f32(p); }
    inline void store(float* p, VectorType v) { vst1q_f32(p, v); }
    inline VectorType add(VectorType a, VectorType b) { return vaddq_f32(a, b); }
    inline VectorType mul(VectorType a, VectorType b) { return vmulq_f32(a, b); }
#else
    constexpr int kVectorWidth = 1;  // 标量 fallback
    using VectorType = float;
    inline VectorType load(const float* p) { return *p; }
    inline void store(float* p, VectorType v) { *p = v; }
    inline VectorType add(VectorType a, VectorType b) { return a + b; }
    inline VectorType mul(VectorType a, VectorType b) { return a * b; }
#endif

}
```

**步骤 3：改造热点循环**

```cpp
int32_t vi = 0;
for (; vi <= n - simd::kVectorWidth; vi += simd::kVectorWidth) {
    auto vec = simd::load(&data[vi]);
    auto alphaVec = simd::load(&alpha[vi]);
    auto result = simd::add(vec, simd::mul(vec, alphaVec));
    simd::store(&output[vi], result);
}
// 剩余元素标量 fallback
for (; vi < n; ++vi) {
    output[vi] = data[vi] + data[vi] * alpha[vi];
}
```

**步骤 4：数据对齐** — 使用 aligned_alloc 或 C++17 aligned new，对齐至 32 字节

**步骤 5：CMake 编译选项**

```cmake
check_cxx_compiler_flag("-mavx2" HAS_AVX2)
if(HAS_AVX2)
    target_compile_options(factor PRIVATE -mavx2 -mfma)
    target_compile_definitions(factor PRIVATE HAS_AVX2)
endif()
```

### 验收标准

- 因子计算循环吞吐量提升 >= 3x
- SIMD 路径与标量路径结果 < 1e-6 差异
- 编译期可选 fallback 路径 (x86 AVX2 与 ARM NEON)

## 3. [HIGH] 因子间并行调度

### 目标

将 fillRawTensor() 中按 factor 串行的计算改为并行，利用多核并行计算所有因子。

### 当前实现 (串行)

```cpp
for (int32_t factorIndex = 0; factorIndex < factorCount_; ++factorIndex) {
    auto factorMatrix = factorComputeDispatcher_.evaluateOnClose(closeView_, token);
    fillSingleFactorSlice(factorIndex, factorMatrix);
}
```

### 实施细节

**线程数量策略**
- 默认使用 hardware_concurrency() - 2 (保留给系统/UI)
- 通过 RuntimeBudget 可配置上限
- 若 factorCount < 4，退化回串行

**线程池方案 (推荐：std::async)**

```cpp
std::vector<std::future<FactorResult<std::vector<float>>>> futures;
for (int32_t fi = 0; fi < factorCount_; ++fi) {
    futures.push_back(std::async(std::launch::async,
        [this, fi]() {
            PerFactorWorkspace ws;
            ws.factorMatrix = factorComputeDispatcher_.evaluateOnClose(closeView_, node.token);
            return ws.factorMatrix;
        }));
}
for (int32_t fi = 0; fi < factorCount_; ++fi) {
    auto result = futures[fi].get();
    if (!result.hasValue()) return result.error();
    fillSingleFactorSlice(fi, result.value());
}
```

**同步边界**
- 进入并行前：prepareExecutionContext() 完成 (串行)
- 退出并行后：postProcessingPipeline_.run() (串行)
- 中间无锁竞争，每个 factor 写独立内存区域

**内存隔离** — 每个并行任务获得独立临时缓冲区，避免伪共享

### 验收标准

- 4 个因子时加速比 >= 3x
- 1 个因子时自动退化无性能损失
- 结果与串行版本位级一致

## 4. [MEDIUM] 回测引擎：矩阵一次性损益计算

### 目标

将阶段式回测 (signal->risk->order->fill 逐日迭代) 改为矩阵一次性损益计算。

### 当前状态

StagePipeline 执行：SignalProducer -> RiskApproval -> OrderGeneration -> FillEngine (逐日迭代)

### 实施细节

**新增 MatrixPnLEngine 纯矩阵路径**

```cpp
struct PnLSpec {
    SignalSet signals;
    Eigen::MatrixXf closePrices;    // T x N
    Eigen::MatrixXf highPrices;
    Eigen::MatrixXf lowPrices;
    Eigen::MatrixXf volumes;
    double slippageRate;            // 如 0.0001
    double commissionRate;          // 如 0.0003
    double initialCash;
};

struct PnLResult {
    Eigen::VectorXf dailyPnL;       // 每日损益
    Eigen::VectorXf cumulativePnL;  // 累计损益
    Eigen::MatrixXf positions;      // 每日持仓
    Eigen::VectorXf turnover;       // 每日换手率
    double sharpeRatio;
    double maxDrawdown;
    double annualizedReturn;
};
```

**核心矩阵运算**

```cpp
// 持仓矩阵: 信号归一化分配 (无逐行循环)
Eigen::MatrixXf position = signals.matrix().rowwise().normalized();

// 日收益率矩阵: (close[t+1] / close[t] - 1)
Eigen::MatrixXf dailyReturnMatrix = close.bottomRows(T-1).array()
    / close.topRows(T-1).array() - 1.0f;

// 每日损益 = sum(持仓 * 收益率)
Eigen::VectorXf dailyPnL = (position.leftCols(N).cwiseProduct(dailyReturnMatrix))
    .rowwise().sum();
```

**路径选择** — BacktestOrchestrator 根据 RunSpec.useMatrixPnL 标志选择路径：

| 路径 | 场景 | 性能 |
|------|------|------|
| StagePipeline (保留) | 复杂订单/风控/自定义撮合 | O(T x N x stages) |
| MatrixPnLEngine (新增) | 标准回测 (无复杂约束) | O(T x N) |

### 验收标准

- 矩阵路径与阶段式路径 PnL 序列相关系数 > 0.999
- 矩阵路径性能提升 >= 5x (1000 stocks x 1000 days)
- 滑点/手续费向量化计算准确

## 5. [MEDIUM] 策略引擎：向量化信号生成确认

### 目标

确认 IStrategySignalEngine 具体实现为向量化 (无逐行循环)，若发现迭代则重构。

### 审计要点

```cpp
// 错误模式 (逐行循环)：
for (auto date : dates) {
    for (auto inst : universe) {
        signal[date][inst] = computeSignal(date, inst);
    }
}

// 正确模式 (向量化)：
SignalMatrix signals = factor1 * alpha + factor2 * beta;
SignalMatrix rankSignal = rankColumns(signals);
SignalMatrix binarySignal = (rankSignal > threshold).cast<float>();
```

### 回退方案

方案 A：算子化重写 (推荐) — 条件逻辑封装为 IFactorOperatorLibrary 扩展，通过 IFactorComputeOperatorExtension 注册

方案 B：Eigen select() — 使用 (condition).select(then, else) 代替 if-else，保持向量流水线

### 验收标准

- 代码审查确认无逐行循环
- 重构前后回测 IC > 0.999
- 重构后性能提升 >= 3x

## 6. [LOW] 实盘：单线程低延迟增量更新

### 目标

提供增量因子计算模式：非全量重算，仅基于增量数据更新因子值。

### 实施细节

**新增 DeltaMarketData 和增量接口**

```cpp
struct DeltaMarketData final {
    DateKey date;
    std::vector<InstrumentId> instruments;
    NumericConstMatrixView close;   // 1 x N matrix
    NumericConstMatrixView high;
    NumericConstMatrixView low;
    NumericConstMatrixView volume;
};

class ISignalEngine {
    virtual FactorResult<SignalSet>
    incrementalUpdate(const SignalSet& base, const DeltaMarketData& delta) = 0;
};
```

**模式切换**

```cpp
enum class ComputeMode { Batch, Incremental };
void setComputeMode(ComputeMode mode);
```

**IncrementalFactorComputeEngine** (新增子类)
- 与 FactorComputeEngine 共享 ISignalEngine 接口
- incrementalUpdate() -> 增量计算
- generate() -> 回退到全量 (首次或缓存丢失)

**增量约束**
- 单线程 + 绑定专用核心 (避免上下文切换)
- 单次 < 1ms (1000 stocks)
- 保留前次中间结果，仅更新 tensor 最后一行
- 无内存分配 (pool 复用)
- 无锁竞争

### 验收标准

- 增量结果与全量重算差异 < 1e-6
- 单次增量更新延迟 < 1ms
- 增量路径无锁竞争

## 8. [LOW] CPU 亲和性与批次切片

### CPU 亲和性脚本

Windows PowerShell (tools/set_cpu_affinity.ps1)：
```powershell
param([string]$ProcessName = "AStockQuantEngine", [int]$ReservedCores = 2)
$totalCores = (Get-CimInstance Win32_Processor).NumberOfLogicalProcessors
$affinityMask = [math]::Pow(2, $totalCores - $ReservedCores) - 1
(Get-Process -Name $ProcessName).ProcessorAffinity = [int]$affinityMask
```

Linux Shell (tools/set_cpu_affinity.sh)：
```bash
#!/bin/bash
RESERVED_CORES=2
TOTAL_CORES=$(nproc)
MASK=$(( (1 << (TOTAL_CORES - RESERVED_CORES)) - 1 ))
taskset -p $MASK $(pgrep AStockQuantEngine)
```
