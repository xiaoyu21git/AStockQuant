# 因子 UI 参数对齐与兼容回退审计（2026-05-06）

## 口径

本文审计的是三件事：

1. UI 个性化参数是否已经传到 C++ 因子实现。
2. 这些参数是否真的参与结果生成，而不只是被解析或写入 metadata。
3. 当前仍然存在多少旧字段兼容、兜底、回退。

本文不重复统计 5 个公共参数是否已接通，公共参数的独立审计见 [doc/因子公共参数生效矩阵_2026-05-05.md](./因子公共参数生效矩阵_2026-05-05.md)。

## 先给结论

- 5 个公共参数已经进入经典因子和通用因子的实际计算链。
- 多数 UI 个性化参数已经对齐，但还不是“全对齐、无兼容、无回退”。
- 当前至少有 3 类“参数看起来存在，但不会改变结果”的问题：
  - Growth 和 Dividend 的 `timeframe` 仅解析，不参与运行时计算。
  - Sentiment 的 `sentimentWeight` 仅解析，不参与运行时计算。
  - LowVol 的 `volatilityType` 仅记录到 metadata，不参与运行时计算。
- 当前仍存在桥接层旧字段兼容，以及几处明确的运行时回退，不满足“只认新字段、不要兜底”的目标状态。

## 状态定义

- 对齐并生效：参数被解析，并进入计算或后处理，能改变最终因子值。
- 仅解析：参数能读到，但当前不会改变最终结果。
- 旧字段兼容：为了兼容历史字段名，当前仍保留旧入口。
- 运行时回退：不是旧字段兼容，而是运行时在缺省或非法输入下自动退回另一套行为。

## 回测执行器职责边界表

| 环节 | 负责内容 | 是否负责原始因子值公式 |
|---|---|---|
| 因子类 | 生成每个交易日的因子横截面。经典因子走 `calculate`，通用因子走 `calculateGrowth`、`calculateTechnical` 等分支 | 是 |
| `FactorBacktestExecutor` | 创建因子实例、组织交易日上下文、调用 `calculateBatch`、聚合 IC、分组收益、多空收益、风控、基准比较、最终摘要 | 否 |
| 回测缓存 | 命中后直接返回反序列化后的回测结果 | 会绕过重新计算 |

### 证据

- 执行器创建因子实例，见 [src/domain/factor/src/FactorBacktestExecutor.cpp](../src/domain/factor/src/FactorBacktestExecutor.cpp#L2171-L2175)。
- 执行器通过 `calculateBatch` 调用因子本身生成因子序列，见 [src/domain/factor/src/FactorBacktestExecutor.cpp](../src/domain/factor/src/FactorBacktestExecutor.cpp#L2178-L2286) 与 [src/domain/factor/src/FactorBacktestExecutor.cpp](../src/domain/factor/src/FactorBacktestExecutor.cpp#L2510-L2525)。
- 执行器在因子序列之后再做风控和基准比较，见 [src/domain/factor/src/FactorBacktestExecutor.cpp](../src/domain/factor/src/FactorBacktestExecutor.cpp#L2087-L2108)。
- 缓存命中时直接返回 `BacktestResult::fromJson`，见 [src/domain/factor/src/FactorBacktestExecutor.cpp](../src/domain/factor/src/FactorBacktestExecutor.cpp#L1411-L1416)。

### 结论

- 因子值由因子类负责生成。
- 回测结果摘要由执行器负责生成。
- 命中缓存时，执行器会直接返回缓存结果，不会重新跑因子计算。
