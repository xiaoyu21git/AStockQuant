# 因子回测结果指标接口合同

## 1. 目标

本文定义因子回测结果的唯一输出合同和唯一业务评估标准，解决三类问题：

- 当前 C++ 实际输出给 QML 的结果结构是什么
- 因子有效性评估指标的最终定义、公式和评判标准是什么
- 哪些指标当前已经实现，哪些还没有实现，禁止混用和偷换概念

本文固定三条单一口径：

1. 结果合同口径：以 `factor::BacktestResult -> FactorBacktestResultContract -> FactorBacktestController::buildResultMap` 为唯一来源。
2. 业务标准口径：核心标准必须按本文第 3 节定义执行，不再沿用旧版四指标评级口径。
3. 展示口径：QML 只能消费本文定义的当前合同字段，禁止把未实现指标伪装成已有字段。

## 2. 当前唯一结果合同

### 2.1 当前唯一出口

当前桥接层唯一出口是：

- `FactorBacktestResultContract::buildMetrics(const factor::BacktestResult&)`

当前 QML 实际消费结构是：

- `backtestResult.metrics.factorQuality`
- `backtestResult.metrics.research`
- `backtestResult.metrics.execution`
- `backtestResult.metrics.ic`
- `backtestResult.metrics.groups`

旧结构已经废止：

- `backtestResult.summary`
- `backtestResult.icirResult`
- `backtestResult.groups`

这些旧字段不再是当前页面真实合同，不允许再作为文档标准继续传播。

### 2.2 根结果对象 `backtestResult`

| 字段 | 类型 | 来源 | 说明 |
|---|---|---|---|
| `factorId` | string | `FactorBacktestController::buildResultMap` | 当前回测因子 ID |
| `taskId` | string | `result.resultId` | 回测任务 ID |
| `executionTime` | int | `result.executionTimeMs` | 执行耗时，单位 ms |
| `success` | bool | `result.status == "SUCCESS"` | 是否执行成功 |
| `status` | string | `result.status` | `SUCCESS` / `PARTIAL` / `FAILED` / `CANCELLED` |
| `config` | map | `buildConfigMap` | 回测参数快照 |
| `metrics` | map | `FactorBacktestResultContract::buildMetrics` | 当前唯一指标出口 |
| `results` | list | `FactorBacktestController::buildAggregatedResultMap` | 多因子统一结果列表；单因子时为空列表或聚合后列表 |
| `factorIds` | list | `FactorBacktestController::buildAggregatedResultMap` | 聚合结果中的因子 ID 列表 |
| `factorCount` | int | `FactorBacktestController::buildAggregatedResultMap` | 聚合结果数量 |
| `activeAnalysisFactorId` | string | `FactorBacktestPage.onBacktestCompleted` | 仅用于 QML 页面切换时显式标记当前展示结果，不属于 C++ 持久桥接合同 |

约束：

- 单因子和多因子必须复用同一结果合同。
- 展示层是否显示切换器，只能根据 `results.length > 1` 判断。
- 禁止恢复顶层 `summary` / `icirResult` / `groups` 兼容字段。
- `activeAnalysisFactorId` 只允许作为 QML 路由态字段存在，用来保证 AnalysisPage 与 BacktestPage 展示同一条结果；禁止拿它替代正式业务字段。

### 2.2.1 页面路由态字段 `activeAnalysisFactorId`

这个字段不是回测引擎或桥接层的业务产出，而是 Backtest 页面切到 Analysis 页面时的显式选择键。

约束：

- 产生位置：`FactorBacktestPage.onBacktestCompleted`，取 `currentDisplayedBacktestResult().factorId/config.factorId`。
- 消费顺序：`AnalysisPage.resolveActiveResult(report)` 必须先看 `report.activeAnalysisFactorId`，再看 `selectedFactorId`，最后才允许退回 `results[0]`。
- 允许范围：只允许附着在 `latestBacktestReport` 这类 QML 内存态对象上。
- 禁止行为：禁止把批量聚合 report 顶层 `config.factorId` 当成当前分析页的唯一结果选择键。

### 2.3.1 `config.backtestSymbolPool`

该字段是因子回测结果中唯一正式的股票池字段。

约束：

- 必须由 `FactorBacktestController::buildResultMap` 输出到 `config.backtestSymbolPool`。
- 语义是“本次因子回测真正使用的候选股票范围快照”，不是最终成交子集，也不是页面临时推导值。
- 因子页转策略页时，只允许消费该字段，不再读取 `symbol_pool`、`symbolPool`、`selectedSymbols` 等旧字段。
- 单因子、多因子、组合因子回测都必须输出同一字段名，禁止再引入第二套股票池结果字段。
- 若本字段为空，则表示当前结果合同不完整，不允许作为“因子转策略”的输入继续流转。

### 2.10 当前结果变量与页面产出路径

本节固定“回测完成后哪些变量被写入哪里、谁消费谁”的唯一路径。

#### 2.10.1 C++ 结果产出路径

1. `factor::BacktestResult`
2. `FactorBacktestResultContract::buildMetrics(const factor::BacktestResult&)`
3. `FactorBacktestController::buildResultMap(const QString&, const factor::BacktestResult&)`
4. `FactorBacktestController::buildAggregatedResultMap()`
5. QML 收到 `backtestResult` / 聚合 `backtestReport`

说明：

- `buildResultMap` 产出单条结果，`results` 为空列表。
- `buildAggregatedResultMap` 把多条单结果塞进顶层 `results[]`，并更新 `factorIds`、`factorCount`、`executionTime`。
- 顶层 `metrics` 在聚合 report 上只是首条结果的桥接镜像，AnalysisPage 不得把它当成“当前展示结果”的唯一来源。
- `config.backtestSymbolPool` 是结果出口上的正式股票池快照；后续比较、基线替换、转策略请求都必须以它为唯一来源。
- 2026-05-26 起，因子回测指标写回 factors 表时，必须同步持久化 `actualStartDate`、`effectiveStartDate`、`effectiveEndDate`、`warmupTrimmedTradingDays` 和 `backtestSymbolPool`；AnalysisPage 在没有内存态 `backtestReport` 时，允许只从这些已持久化字段恢复有效期/股票池卡片展示。

#### 2.10.1.1 股票池结果字段收口要求

因子回测结果后续只允许存在一个正式股票池字段：

- `backtestResult.config.backtestSymbolPool`

禁止继续在因子结果链使用或恢复：

- `backtestResult.config.symbol_pool`
- `backtestResult.config.symbolPool`
- `backtestResult.config.selectedSymbols`
- 页面侧从缓存集再次反推“当前股票池”并冒充回测结果股票池

#### 2.10.2 Backtest 页展示路径

1. `FactorBacktestPage.applyDisplayedBacktestResult(result)`
2. `currentDisplayedBacktestResult()` 选出当前正在展示的那条 result
3. 页面本地状态更新：
	- `groupResults`
	- `icMetrics`
	- `executionMetrics`
	- 其他 summary/图表状态

说明：

- Backtest 页日志里打印的 `executionMetrics.maxDrawdown`，来源是当前 displayed result 的 `metrics.execution.maxDrawdown`。
- 这里看到的值，必须和随后切到 AnalysisPage 看到的同一条 result 一致。

#### 2.10.3 Analysis 页产出路径

1. `FactorBacktestPage.onBacktestCompleted`
2. 克隆原始 `result` 为 `analysisReport`
3. 写入 `analysisReport.activeAnalysisFactorId = currentDisplayedBacktestResult().factorId`
4. 发出 `analysisReportRequested(analysisReport)`
5. `FactorWorkbench.onAnalysisReportRequested`
6. `latestBacktestReport = report`
7. `selectedFactorId = report.activeAnalysisFactorId`
8. `AnalysisPage.backtestReport = latestBacktestReport`
9. `AnalysisPage.resolveActiveResult(backtestReport)`
10. `activeResult.metrics.factorQuality / execution / ic / groups`

说明：

- AnalysisPage 的所有卡片、摘要、图表都必须从 `activeResult` 派生。
- 如果是批量结果，必须用 `activeAnalysisFactorId` 命中 `results[]` 里的当前条目；不能再默认拿 `results[0]` 冒充当前结果。
- `results[0]` 只能作为没有任何选择键时的最后兜底，不是正常路径。

#### 2.10.4 分析页写回产出路径

1. `AnalysisPage` 点击“写回指标”
2. `requestWriteBacktestMetrics(activeResult)`
3. `FactorWorkbench.handleWriteBacktestMetrics(report)`
4. 从 `report.metrics.ic / factorQuality / execution` 提取写回字段
5. `factorService.updateFactor(factorData)`

说明：

- 写回动作必须拿 `activeResult`，不能拿聚合 report 顶层对象。
- 否则批量回测时会把另一条 result 的指标写回当前因子。

## 3. 最终业务评估标准

本节是最终业务标准。

规则如下：

1. 核心标准必须按本节定义执行。
2. 当前代码里已有的旧评级门槛只能算展示辅助，不能替代本节标准。
3. 凡“当前状态”为“未实现”的指标，禁止在 QML 中伪造数值或借用相近字段替代。

### 3.1 核心指标体系

这组指标决定因子“有没有用”，是唯一核心门槛。

| 序号 | 指标 | 计算公式 | 合格 | 良好 | 优秀 | 当前结果字段 | 当前状态 | 核心作用 |
|---|---|---|---|---|---|---|---|---|
| 1 | Rank IC均值 | $IC_t = Corr(rank(f_t), rank(R_{t+1}))$；$IC_{mean} = \frac{1}{T}\sum_{t=1}^{T} IC_t$ | > 0.02（月频） | > 0.03（月频） | > 0.05（月频） | `metrics.factorQuality.rankIcMean` | 已实现 | 预测能力 |
| 2 | IC p值 | $t = \frac{IC_{mean}}{\sigma_{IC} / \sqrt{T}} = IR \times \sqrt{T}$；$p = 2 \times (1 - F_t(|t|))$ | < 0.05 | < 0.01 | < 0.001 | `metrics.factorQuality.icPValue` | 已实现 | 统计显著性 |
| 3 | IR | $IR = \frac{IC_{mean}}{\sigma_{IC}}$；$\sigma_{IC} = \sqrt{\frac{1}{T-1}\sum(IC_t - IC_{mean})^2}$ | > 0.3 | > 0.5 | > 0.8 | `metrics.factorQuality.rankIcir` | 已实现 | 预测稳定性 |
| 4 | IC胜率 | $WinRate = \frac{Count(IC_t > 0)}{T} \times 100\%$ | > 55% | > 65% | > 75% | `metrics.factorQuality.icWinRate` | 已实现 | 方向稳定性 |
| 5 | 分组收益单调性 | $Monotonicity = Corr(GroupRank, GroupReturn_k)$；`GroupRank = 1,...,K` | $|r| > 0.7$ 且 Top > Bottom | $|r| > 0.85$ 且严格单调 | $|r| > 0.95$ 且严格单调 | `metrics.research.monotonicity` | 已实现 | 逻辑一致性 |

核心评判规则：

- 核心评级只允许由上述 5 项指标决定。
- 任一核心指标未实现或无有效样本时，不得输出“优秀 / 良好 / 合格”业务评级。
- 当前代码里的 `metrics.factorQuality.coreRating` 就是当前页面使用的核心业务评级字段。

### 3.2 辅助指标体系

这组指标用于判断因子“怎么用”。

#### 3.2.1 实战可行性

| 序号 | 指标 | 计算公式 | 合格 | 良好 | 优秀 | 当前结果字段 | 当前状态 | 使用场景 |
|---|---|---|---|---|---|---|---|---|
| 6 | 多空组合年化收益 | $R_{LS,mean} = \frac{1}{T}\sum(R_{top,t} - R_{bottom,t})$；$AnnRet = R_{LS,mean} \times \frac{252}{forwardDays}$ | > 5% | > 10% | > 20% | `metrics.research.annualizedSpreadReturn` | 已实现 | 评估获利空间 |
| 7 | 多头超额收益 | $R_{excess} = R_{top} - R_{benchmark}$；$AnnAlpha = (1 + \bar{R}_{excess})^{252} - 1$ | > 3% | > 8% | > 15% | 无 | 未实现 | A股做空受限时替代多空 |
| 8 | 换手率 | $Turnover_t = \frac{|P_t \setminus P_{t-1}| + |P_{t-1} \setminus P_t|}{|P_t| + |P_{t-1}|}$；$AnnTurnover = Turnover_{avg} \times \frac{252}{forwardDays}$ | < 200%/年 | < 100%/年 | < 50%/年 | `metrics.factorQuality.annualTurnover` | 已实现 | 评估交易成本侵蚀 |
| 9 | 最大回撤 | $NAV_0 = 1$；$NAV_t = NAV_{t-1}(1+r_t)$；$MDD = \max_t \frac{Peak_t - NAV_t}{Peak_t}$；若 $NAV_t \le 0$ 则记为 100% | < 25% | < 15% | < 10% | `metrics.execution.maxDrawdown` | 已实现 | 风险评估 |
| 10 | IC波动率 | $\sigma_{IC} = \sqrt{\frac{1}{T-1}\sum(IC_t - IC_{mean})^2}$ | < 0.10 | < 0.08 | < 0.05 | `metrics.factorQuality.rankIcStd` | 已实现 | IC稳定性辅助判断 |

#### 3.2.2 深入诊断

| 序号 | 指标 | 计算公式 | 合格 | 良好 | 优秀 | 当前结果字段 | 当前状态 | 使用场景 |
|---|---|---|---|---|---|---|---|---|
| 11 | IC偏度 | $Skew = \frac{\frac{1}{T}\sum(IC_t - IC_{mean})^3}{\sigma_{IC}^3}$ | -1 到 1 | -0.5 到 0.5 | 约等于 0 | 无 | 未实现 | 诊断分布对称性 |

## 4. 交集去重后的唯一解释规则

本节用于消除重名、近义词和镜像字段带来的歧义。

### 4.1 IR 的唯一解释

- 业务标准中的 IR，指 IC 序列的 `IC_mean / IC_std`。
- 当前合同中对应字段是 `metrics.factorQuality.rankIcir`。
- 当前合同中的 `metrics.ic.ir` 是同一底层序列的基础统计镜像。
- 页面做因子质量评级时，优先使用 `metrics.factorQuality.rankIcir`；做 IC 基础展示时，使用 `metrics.ic.ir`。

### 4.2 单调性的唯一解释

- 业务标准中的“分组收益单调性”是数值型相关系数，唯一标准字段是 `metrics.research.monotonicity`。
- `metrics.factorQuality.monotonicityScore` 是质量子图中同一数值口径的镜像字段，可直接用于核心评级与卡片展示。
- 当前分组顺序固定为 `G1 ... GK`，其中 `G1` 是最高分组、`GK` 是最低分组；因此“严格单调”指当前顺序下收益从 `G1` 到 `GK` 严格递减，同时满足 `Top > Bottom`。

### 4.3 多空年化收益的唯一解释

- 研究口径原始值使用 `metrics.research.spreadReturn` 与 `metrics.research.annualizedSpreadReturn`，都对应第一组减最后一组的原始多空价差，不扣交易成本。
- `metrics.factorQuality.longShortAnnualReturn` 是同一研究口径的镜像摘要字段。
- 三者语义必须一致，不允许把其中任一字段切成成本后或风控后收益。
- 研究口径这里的“年化”仍是线性年化：$AnnRet = R_{LS,mean} \times \frac{252}{forwardDays}$，它不是执行净值路径的复合年化。

### 4.4 换手率的唯一解释

- 业务标准里的“换手率”优先对应 `metrics.factorQuality.annualTurnover`。
- `metrics.execution.turnoverRate` 是执行结果子图中的镜像字段。
- 两者在结果合同中都使用比例口径，例如 `1.37` 表示 `137%/年`。

### 4.5 执行年化收益的唯一解释

- `metrics.execution.annualReturn` 基于风控后执行收益序列计算。
- 先按 $NAV_0 = 1$、$NAV_t = NAV_{t-1}(1+r_t)$ 生成执行净值。
- 若有效收益期数为 $T$，则执行年化收益为 $AnnualReturn = NAV_T^{\frac{252 / forwardDays}{T}} - 1$。
- 若执行净值在路径中降到 0 或以下，则执行年化收益记为 `-100%`。
- `metrics.execution.benchmarkAnnualReturn` 使用同一复合年化逻辑计算对齐后的基准收益路径。
- `metrics.execution.excessAnnualReturn` 定义为执行复合年化减基准复合年化。
- 因此，`metrics.research.annualizedSpreadReturn` / `metrics.factorQuality.longShortAnnualReturn` 与 `metrics.execution.annualReturn` 不允许再被解释成同一类“年化收益”。

### 4.6 最大回撤的唯一解释

- 执行口径最大回撤使用 `metrics.execution.maxDrawdown`。
- 当前结果合同不再向 QML 暴露 research long-short drawdown 镜像字段。
- 页面显示与业务标准中的“最大回撤”一律只认 `metrics.execution.maxDrawdown`。

### 4.7 禁止偷换的字段

以下替代一律禁止：

- 禁止用 `icTStat` 代替 `IC p值`
- 禁止用 `alpha` 代替 `多头超额收益`
- 禁止用任何已实现字段伪装 `IC偏度`、`IC峰度`、`|IC|>0.05 占比`、`因子相关性`、`Fama-MacBeth t值`、`中性化后 IC衰减`、`滚动IC稳定性`

## 5. 最终评级规则

最终业务评级只允许使用核心 5 项指标。

### 5.1 核心评级表

| 评级 | Rank IC均值 | IC p值 | IR | IC胜率 | 分组收益单调性 | 结论 |
|---|---|---|---|---|---|---|
| 优秀 | > 0.05 | < 0.001 | > 0.8 | > 75% | $|r| > 0.95$ 且各组递增 | 核心因子，可重点使用 |
| 良好 | > 0.03 | < 0.01 | > 0.5 | > 65% | $|r| > 0.85$ 且严格单调 | 合格因子，可纳入组合 |
| 合格 | > 0.02 | < 0.05 | > 0.3 | > 55% | $|r| > 0.7$ 且 Top > Bottom | 边缘因子，谨慎使用 |
| 不合格 | 任一项不达标 | 任一项不达标 | 任一项不达标 | 任一项不达标 | 任一项不达标 | 建议放弃或仅作辅助 |

### 5.2 当前代码内置评级的解释

当前代码中的：

- `metrics.factorQuality.coreRating`
- `metrics.factorQuality.coreRatingLabel`
- `metrics.factorQuality.coreRatingSummary`
- `metrics.factorQuality.coreRatingChecks`

已经直接基于新的 5 项核心指标门槛：

- Rank IC均值
- IC p值
- Rank ICIR
- IC 胜率
- 分组单调相关系数

这里不再保留旧版四指标评级合同，也不再使用多空夏普参与核心业务评级。

### 5.3 写回指标规则

当前因子写回链路 `FactorBacktestController::syncBacktestMetricsToFactor` 的唯一准入条件是：

- `result.factorMetrics.coreRating >= PASS`

这意味着：

- 只要核心 5 项中任一项不达标，就不允许把回测指标写回因子记录。
- 不再使用旧的 `|IC|`、`IR`、`profitFactor` 独立阈值做写回判定。
- 不再接受旧的持久化阈值配置接口覆盖这条规则。

## 6. 显示规则

### 6.1 `N/A` 规则

唯一规则：

- `N/A` 只能在没有因子上下文时显示。

具体定义：

- `FactorBacktestPage.qml`：`selectedFactorIds.length === 0`
- `BacktestPage.qml`：`selectedFactorId` 为空
- `BacktestResultView.qml`：`backtestResult.factorId` 或 `backtestResult.config.factorId` 为空

禁止规则：

- 不允许因为数值为 `0` 显示 `N/A`
- 不允许因为已有因子上下文但字段缺失就显示 `N/A`

### 6.2 未实现指标的显示规则

- 凡第 3 节标记为“未实现”的指标，页面必须显示“未实现”或直接不展示。
- 禁止把未实现指标格式化成 `0` 后冒充真实结果。
- 禁止借用相近字段顶替未实现指标。

## 7. 修改要求

后续新增或调整因子回测结果时，必须同时满足：

1. 先在 `factor::BacktestResult` 或 `FactorBacktestMetrics` 中补齐底层数据。
2. 再在 `FactorBacktestResultContract` 中显式新增字段。
3. 再更新本文，把“当前结果字段”和“业务标准状态”同时写清楚。
4. 最后由 QML 按本文字段名消费。

禁止行为：

- 直接在 `FactorBacktestController.cpp` 或 QML 页面临时拼接新指标
- 恢复旧版 `summary` / `icirResult` / `groups` 顶层兼容口径
- 用展示辅助字段替代业务标准字段
- 用未实现字段的默认值冒充真实指标
