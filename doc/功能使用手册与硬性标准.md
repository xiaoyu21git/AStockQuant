# 功能使用手册与硬性标准

> 本文档记录各功能的使用方法（怎么触发/怎么用）与硬性标准（设计契约）。
> 用途：防止把**正确的设计**误判为缺陷。分析者（含 AI）在分析某功能行为前，必须先读本文档对应章节。

---

## 0. 使用规则（对分析者/AI 生效）

1. **先查后断**：分析某功能行为、怀疑某逻辑是 bug 之前，先查本文档对应章节。
2. **契约优先**：分析结论与本文档 ✅"已确认"条目冲突 → 以本文档为准，是分析者理解错了，代码没有错。
3. **不许擅改**：即使认为某条已确认标准有误，也必须先与用户确认，禁止直接改代码或改文档。
4. **准入规则**：任何条目的正式内容（使用方法/硬性标准）**必须经用户确认**后才能进入文档。未经确认的内容一律标 📝，不视为有效契约。
5. **条目状态图例**：
   - ✅ 已确认 —— 用户确认过的设计契约，最高优先级，不得违背。
   - 📝 待确认 —— 从代码梳理的事实性初稿，**尚未经用户确认**，仅作讨论底稿，不得作为判断依据。
6. **功能分区**：各功能按分区+编号组织（见 §1 总览）；**关联功能在章节内显式标注**，分析某个功能时必须同时阅读其标注的关联章节。

### A1. EOD 评估窗口（14:50）　📝 待确认

#### 使用方法（初稿，待确认）

| 项 | 内容 |
|---|---|
| 触发方式 | ① 30s 轮询：命中 `[triggerMinute, triggerMinute+triggerWindowMinutes)`（14:50–15:00）② gmsdk EOD 回调兜底：仅回调窗口 `[eodCallbackStartTime, eodCallbackEndTime)` 内接受 |
| 去重 | `evalDay <= lastEvalDay` → 跳过（防轮询/回调重复触发） |
| 持久化 | `Submitted/NoSignal/AllRejected/Skipped` 均写 lastEvalDay（AllRejected 是最终决定）；`Error` 不写，等待补单重试 |
| 窗口语义 | 已过窗口当日不再评估（低频等待）；当日已评估 → 低频等待 |

#### 硬性标准（初稿，待确认）

1. **时间零兜底**：调度时间必须从 trading_connection.json 读取；任一键缺失/非法 → 调度器**拒绝启动**，禁止硬编码时间顶替。
2. **盘中价格回退链 = tickCache → LiveData**：DB **不参与**盘中当日价格兜底（数据库唯一职责=回看数据；盘中全空 = P4 Error 截断）。
3. **当日日K未入库是 14:50 常态**（同步 15:01 才开始）：因子策略视图由 LiveViewPreparer 注入当日合成行（锚点行值不进入模型输入）；非因子策略无合成行。
4. **非交易日不触发** EOD 评估（交易日历判断）。

#### 关联功能
→ A2 补单（失败后由补单接手）、↔ D1 同步屏蔽窗口、→ B 评估管道

### A2. 补单（次日补偿评估）

#### 使用方法（初稿，待确认）

| 项 | 内容 |
|---|---|
| 触发时机 | 引擎**启动时**处于补单窗口：交易日 0:00–09:30（`compensationEndTime`，配置 [trading_connection.json](../config/trading_connection.json)） |
| 触发条件 | 上一交易日未评估：`previousTradingDay(today) > lastEvalDay`（昨日 14:50 失败或引擎当日未运行） |
| 评估内容 | 以被补交易日为基准，完整重跑评估管道（preflight → DB 取价 → 闸门 → 信号 → 提交），正常下单 |
| 价格源 | DB 日线单级（`mkt.daily_bar`，含 `pre_close` 支持涨跌停过滤）；不接 tickCache/LiveData 回退链 |
| 幂等 | 被补日当日已提交（`lastBasket` 记录存在）→ 跳过，不再二次下单 |
| 持久化 | 补单仅 `Submitted` 写 `lastEvalDay`；`Error` 不写，等待下次启动窗口重试 |
| 数据前提 | 被补交易日的 daily_bar 已同步入库（15:01 后 PostMarketSyncService 同步）；未同步 → P2/P4 Error 截断（不伪装 NoSignal） |

关键代码：[EvaluationScheduler.cpp start() 补单分支](../src/domain/strategy/src/EvaluationScheduler.cpp)、[PriceProviderFactory 补单分支](../src/domain/strategy/src/PriceProviders.cpp)、[SubmissionFinalizer 幂等去重](../src/domain/strategy/src/SubmissionFinalizer.cpp)

#### 硬性标准

| # | 内容 | 状态 |
|---|---|---|
| 1 | **非交易日不触发补单**：周六/周日/节假日启动引擎，不发生任何补单评估（`currentTradingDay()` 返回最近交易日）。周五失败的单由**下一个交易日（周一）的补单窗口**补偿。这是正确逻辑。 | ✅ 已确认 |
| 2 | **补单触发路径唯一**：仅引擎启动（`start()`）时检测窗口；运行中的引擎**不轮询补单**。补单服务"引擎离线/宕机后重启"场景；引擎在线期间的评估由正常 EOD 路径负责。运维恢复手段 = 次日 09:30 前重启引擎。轮询循环中**没有也不需要**补单分支。 | ✅ 已确认 |
| 3 | 补单仅针对上一交易日，不做多日回放。 | 📝 |
| 4 | 补单价格源 = DB 单级，盘中回退链不参与；DB 全空 → Error 截断。 | 📝 |
| 5 | 幂等优先：防重复成交优先于"再试一次"；已提交被补日 → 跳过。 | 📝 |
| 6 | TriggerPolicy 以被补交易日重新计算（澄清 C5），纯函数结果与当日 14:50 一致。 | 📝 |
| 7 | 非调仓日补单（interval>1 策略）走同一管道，仅 `Submitted` 写 lastEvalDay。 | 📝 |

#### 常见误判（曾把正确设计误判为缺陷）

| # | 误判 | 正确逻辑 | 状态 |
|---|---|---|---|
| 1 | "周六重启不补周五是缺陷/周末边界问题" | 周六不是交易日，本就不该触发任何评估。周五的单由下一交易日（周一）0:00–09:30 补单窗口补偿。 | ✅ 已确认 |
| 2 | "补单只在 start() 触发、轮询循环无补单分支是最大缺口" | 单一路径是设计。补单只服务引擎离线/宕机后重启场景；引擎在线时由正常 EOD 路径负责当日。 | ✅ 已确认 |

#### 关联功能
→ A1 EOD 评估窗口（同一管道，模式互斥）、→ D2 数据同步（数据前提）、→ C1 提交幂等去重（防重复下单）

### C1. 提交幂等去重（ADR-006）　📝 待确认

#### 使用方法（初稿，待确认）

`SubmissionFinalizer::submit()` 在 `OrderGenerator::generate()` **之前**检查幂等键：`lastBasket.<strategyId>.<period>` 的 `{day, basketId}`（存 app_state.json）。命中 → `skipped` 直接返回，不下单。

#### 硬性标准（初稿，待确认）

1. **去重键绑定 `(strategyId, BarPeriod, 交易日)`**，日频与未来分钟频互不覆盖。
2. **先投递后落盘**：幂等键在 `dispatchFn` 成功后写入；投递异常不落。
3. **当日已提交 → Skipped**：日志 `[Eval] 提交跳过: 当日已提交 basketId=...`，显式说明避免运维误判。该跳过与入口模式无关，EOD 与补单共用同一拦截。
4. **防重复成交优先**：投递即写键。SemiAuto 被拒/部分成交**不重试**（视为已提交，刻意行为变化）。

#### 关联功能
← A2 补单（依赖其防重复）、↔ C2 簿记校验 P5、→ B 评估管道（提交阶段）

### D1. 同步屏蔽窗口（PostMarketSyncService）　📝 待确认

#### 使用方法（初稿，待确认）

- **屏蔽**：`syncBlockStart`(09:25) → `eodTriggerTime`(14:50) 之间禁止同步（"下单前禁止同步"）。
- **触发**：`syncTriggerTime`(15:01) 起自动同步（取 `max(syncTriggerTime, eodTriggerTime)`）。
- DB 已有当日日线 → 只更新 dataSyncDay，不重复同步。

#### 硬性标准（初稿，待确认）

1. **EOD 下单未触发前禁止同步**：屏蔽窗口内同步是错误行为（会污染当日实时取价链路；GM SDK 交易时段日线/分钟线 API 调用有崩溃风险）。"下单前不同步"是设计，不是缺陷。
2. **屏蔽截止 = eodTriggerTime**（唯一来源，不写死）。
3. **时间键缺失/非法 → 拒绝启动**（零兜底）。
4. 同步在独立线程执行，与 GM SDK 调用互斥（`gmSdkMutex`）。

#### 关联功能
↔ A1 EOD 评估窗口（屏蔽截止绑定其触发时间）、→ D2 数据同步

### E1. B股禁买（四层防线）　📝 待确认

#### 使用方法（初稿，待确认）

- **判定唯一源**：`AStockSymbol::isBShare() / isBShareSymbol()` —— 沪B 900xxx、深B 200xxx/201xxx 前缀 → `Board::BShare`。`inferExchange` 锁定不改。
- **防线（5 处代码点，4 个层次）**：

| 层次 | 位置 | 行为 |
|---|---|---|
| 因子层 | [SignalBlendCompositor](../src/domain/strategy/src/SignalBlendCompositor.cpp)（候选池+补位） | B股禁入候选池，不占名额不进补位 |
| 因子层 | [RuntimeFactorSvc](../src/domain/strategy/src/RuntimeFactorSvc.cpp)（截面快照×2/全截面/预热缓存） | B股不进截面快照与 Z-score 全截面计算（统计零污染），不进预热缓存 |
| 信号层 | [SignalEvaluationPipeline collectSignals](../src/domain/strategy/src/SignalEvaluationPipeline.cpp) | 未持仓 B 股整标的跳过；已持仓 B 股买单拒绝（卖单放行） |
| 回测层 | [StrategyEngineFacade runBacktestLoop](../src/domain/strategy/src/StrategyEngineFacade.cpp#L2190-L2200) | 全局硬过滤买单（置顶于 `symbolToCol.at` 之前，视图外符号不触发异常） |
| 执行层 | [TradeExecutionEngine](../src/domain/trading/TradeExecutionEngine.cpp) | 下单执行前拦截 |

#### 硬性标准（初稿，待确认）

1. **判定唯一事实源 = AStockSymbol**；禁止在别处重新实现 900/200/201 前缀判断。
2. **`inferExchange` 锁定不改**（历史判定逻辑有外部依赖）。
3. **只拦买入，卖出路径不动**：已持仓 B 股允许卖出离场。
4. **计数与归因语义**：B股买单拒绝置于涨跌停过滤**之前**（一字涨停 B 股的拒绝原因归为"B股禁买"而非"涨停"），计入 `bShareFiltered`；B股整标的跳过计入 `bShareSymbolsSkipped`。规则闸门审核分母 = 总生成 − 涨跌停过滤 − B股拦截。

#### 关联功能
→ B3 信号收集（拦截发生点）、→ B2 规则闸门（审核分母口径）

## 4. 文档维护流程

1. 每个功能的正式说明（使用方法 + 硬性标准 + 关联标注）**必须先经用户逐条确认**，确认后将状态从 📝 改为 ✅。
2. 新功能进入文档：先在"候选功能池"登记 → 梳理初稿（📝）→ 用户确认 → 转正式（✅）。
3. 发现代码行为与 ✅ 条目不一致时：先与用户确认是"文档错了"还是"代码错了"，禁止单方面修改任何一方。
