# 1.0.0 正式版必须完成清单

> **ℹ️**: 本文档中提到的 MySQL→PostgreSQL 迁移已于 2026-07 完成。MySQL 已退役，PostgreSQL 为当前主库。

## 1. 版本目标

口径说明：本文是 1.0.0 正式发布基线的验收清单，不等同于“所有产品能力都必须在 1.0.0 前全部做完”。项目整体仍有哪些业务能力未闭环，应以 [doc/当前项目功能完整性清单.md](./当前项目功能完整性清单.md) 为总览；其中一部分能力可以放到 1.1.x 或后续版本继续推进。

1.0.0 的定位不是“把所有想做的功能全做完”，而是把项目的核心主链收束成一个稳定、可交付、可追溯的正式基线。

这一版必须满足：

- 主链闭环。
- 真源统一。
- 主库结构明确。
- 回归稳定。
- 能作为正式发布基线。

## 2. 1.0.0 必须完成的功能

### 2.1 数据管理闭环

必须完成：

- 数据源管理、查询、预览、清洗完整可用。
- 主行情、财务、缓存集三类数据链路稳定。
- 数据管理页面和底层服务之间没有断链。

验收标准：

- 数据管理主链可以稳定反复执行。
- 常用数据操作不依赖临时兼容逻辑。
- 数据结果可追踪、可回放。

### 2.2 因子分析闭环

必须完成：

- 因子工作台可正常完成创建、编辑、选择、验证、查看。
- 因子支持判断、字段需求和 runtime 执行一致。
- 因子回测结果可稳定展示。

验收标准：

- 因子从配置到执行不再出现真源分裂。
- 可执行、可回测、可解释。
- 因子结果能和配置一一对应。

### 2.3 策略回测闭环

必须完成：

- 策略回测完整可跑。
- 回测结果、摘要、绩效数据可稳定回写。
- 回测主链与因子主链互不干扰。

验收标准：

- 策略回测是独立稳定链路。
- 结果可重复、可验证。
- 页面和服务状态一致。

### 2.4 数据清洗与质量闭环

必须完成：

- 清洗规则、清洗任务、清洗结果可稳定执行。
- 数据质量报告可产出。
- 清洗结果和原始数据关系可追溯。

验收标准：

- 清洗不再是临时脚本式链路。
- 质量问题能被识别和记录。
- 清洗结果可用于正式分析与回测。

### 2.5 主库与迁移闭环

必须完成：

- PostgreSQL 目标 schema 已冻结。
- 主要主数据和核心时序数据已完成迁移。
- `factor_instance.full_config` 作为唯一因子参数真源。
- 旧 MySQL 不再参与产品主链路写入。

验收标准：

- 主库边界明确。
- 表职责清晰。
- 迁移可回归、可对账、可解释。

## 3. 1.0.0 允许继续推进的内容

以下能力可以存在，但不应成为 1.0.0 的硬阻塞：

- 风险管理进一步完善。
- 交易执行进一步完善。
- 组合构建进一步完善。
- 更多第三方数据源接入。
- 更多扩展因子和分析报表。

这些内容可以作为 1.1.x 或后续版本继续推进。

## 4. 1.0.0 不应再做的事情

- 不应继续保留多套主真源。
- 不应继续让 bridge 兼容逻辑承担核心执行。
- 不应继续让稳定版和推进版的职责混杂。
- 不应继续把迁移窗口逻辑当成长期主链。
