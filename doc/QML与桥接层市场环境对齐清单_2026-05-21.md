# QML 与桥接层市场环境对齐清单

## 1. 目标

本文只覆盖 QML 与桥接层，不讨论底层执行器和回测算法。

目标是明确：

1. 市场环境开关在页面上应该出现在哪里。
2. 页面和桥接层各自承担什么职责。
3. 哪些页面字段、展示方式和布局做法必须禁止。
4. 后续实现时如何在不破坏当前界面美观的前提下接入统一市场环境选择器。

## 2. 当前锚点

当前与市场环境最相关的 QML 和桥接锚点有六个：

1. 因子回测运行参数入口在 [src/app/Qml/components/FactorWorkbench/Backtest/FactorBacktestPage.qml](../src/app/Qml/components/FactorWorkbench/Backtest/FactorBacktestPage.qml)。
2. 因子回测桥接参数入口在 [src/ui/bridge/src/FactorBacktestController.cpp](../src/ui/bridge/src/FactorBacktestController.cpp)。
3. 策略回测页面入口在 [src/app/Qml/page/backtest/StrategyBacktestPage.qml](../src/app/Qml/page/backtest/StrategyBacktestPage.qml)。
4. 运行时环境展示点当前在 [src/app/Qml/components/Trading/RuntimeRuleObserverPanel.qml](../src/app/Qml/components/Trading/RuntimeRuleObserverPanel.qml)。
5. 运行时环境门禁输出来自 [src/ui/bridge/src/StrategyRuntimeRuleEvaluator.cpp](../src/ui/bridge/src/StrategyRuntimeRuleEvaluator.cpp#L194)。
6. QML 类型注册入口在 [src/ui/bridge/src/registerQmlTypes.cpp](../src/ui/bridge/src/registerQmlTypes.cpp)。

## 3. 当前问题

当前 QML 与桥接层存在六类直接问题：

1. 因子回测页没有正式的市场环境输入。
2. 策略回测页没有正式的市场环境输入。
3. 页面现在更容易直接传散乱运行参数，而不是单一环境开关。
4. 运行时观察面板当前展示的是 `marketEnvironmentGate`，但这个字段只是门禁状态，不是环境配置值。
5. QML 尚无统一的市场环境标签映射来源。
6. 如果直接在现有页面里硬塞一排新控件，很容易破坏当前布局美观。

## 4. 硬约束

后续实现必须遵守下面这些硬约束：

1. 页面层只允许一个统一市场环境输入：`marketEnvironmentProfile`。
2. 不允许在 QML 层新增 `isAShare`、`useTPlusOne`、`allowSameDaySell` 这类重复制度布尔项。
3. 不允许把市场环境真源放成自由输入字符串。
4. 不允许为了加功能而简单放大控件、拉高面板、破坏当前信息密度和视觉平衡。
5. 不允许在桥接层额外保留一套字符串兼容字段与枚举字段并存。

## 5. 页面入口设计

### 5.1 因子回测页

当前因子回测运行参数已经通过运行参数对话框集中管理，见 [src/app/Qml/components/FactorWorkbench/Backtest/FactorBacktestPage.qml](../src/app/Qml/components/FactorWorkbench/Backtest/FactorBacktestPage.qml#L217)。

建议落点：

1. 把市场环境选择器放进现有运行参数对话框。
2. 与 `forwardDays`、`rebalanceDays`、`benchmarkSymbol` 保持同一层级。
3. 使用紧凑型单行选择器，不新增大块说明面板。

原因：

- 因子回测的市场环境本质上就是运行参数，不应该游离到页面其他区域。

### 5.2 策略回测页

当前策略回测页的主要参数入口是参数面板 `BacktestParameterPanel`，见 [src/app/Qml/page/backtest/StrategyBacktestPage.qml](../src/app/Qml/page/backtest/StrategyBacktestPage.qml)。

建议落点：

1. 把市场环境选择器纳入策略回测核心参数区。
2. 放在数据源、股票池、日期区间同一层级的紧凑参数组内。
3. 不单独新增一个大卡片。

原因：

- 市场环境和回测区间、数据源一样，属于全局上下文参数。

### 5.3 运行时观察面板

当前运行时观察面板展示的是：

1. `marketEnvironmentGate`

后续应改为同时展示：

1. `marketEnvironmentProfileLabel`
2. `marketEnvironmentGate`
3. `marketEnvironmentReason`

约束：

- 配置值和门禁结果必须分开展示。

## 6. 布局与视觉约束

后续新增市场环境选择器时，必须遵守下面这些布局原则：

1. 优先复用现有参数行和现有对话框，不新开大块区域。
2. 优先使用现有 `ComboBox`、分段选择器或紧凑型参数组件风格。
3. 控件宽度只在局部微调，不通过整体放大面板来容纳新字段。
4. 标签文案保持简短，优先使用“市场环境”而不是长句说明。
5. 如果需要帮助说明，优先使用 tooltip、帮助文案或折叠说明，不在主界面堆大段文字。

禁止做法：

1. 直接把运行参数对话框整体拉高一截来塞字段。
2. 在策略回测页主面板上额外插入一个大尺寸说明卡片。
3. 为了显示环境差异，在页面同时摆出一组布尔开关。

## 7. 页面层职责

QML 页面层只负责三件事：

1. 展示可选市场环境列表。
2. 把选中的枚举值传给桥接层。
3. 展示桥接层返回的环境标签和解释结果。

QML 页面层不负责：

1. 自己推断当前是不是 A 股。
2. 自己把市场环境拆成多个制度布尔项。
3. 根据页面逻辑自行决定 T+1 或 T+0。

## 8. 桥接层职责

桥接层只负责四件事：

1. 接收 QML 传入的 `marketEnvironmentProfile` 枚举值。
2. 把该枚举值写入因子回测或策略回测配置合同。
3. 把结果中的枚举值映射成展示 label。
4. 把环境配置和门禁结果拆分后返回给 QML。

桥接层不负责：

1. 保留字符串兼容字段。
2. 在没有字段时猜测默认市场并静默兜底。
3. 用旧页面字段反推出市场环境。

## 9. QML 注册与共享映射

后续若需要给 QML 提供统一的市场环境标签、选项和说明，建议走单一共享桥接入口。

推荐方向：

1. 由桥接层提供统一枚举映射接口或单例 helper。
2. QML 各页都复用同一组选项源。

禁止方向：

1. 因子回测页写一套 `[{value: 1, label: "A股"}]`。
2. 策略回测页再手写另一套值和标签。
3. 运行时观察面板再单独拼第三套环境文本。

如果出现三套页面各自维护一套标签，后续必然漂移。

## 10. 显示合同建议

后续 QML 至少应能拿到下面这些展示字段：

1. `marketEnvironmentProfile`
2. `marketEnvironmentProfileLabel`
3. `marketEnvironmentGate`
4. `marketEnvironmentReason`

约束：

1. `marketEnvironmentProfile` 是配置值。
2. `marketEnvironmentProfileLabel` 是展示文本。
3. `marketEnvironmentGate` 是门禁状态。
4. `marketEnvironmentReason` 是门禁失败原因。

禁止：

1. 继续只展示 `marketEnvironmentGate`，让用户以为那就是市场环境本身。

## 11. 推荐实施顺序

建议按下面顺序推进：

1. 先定义统一的 QML 选项源和桥接枚举映射。
2. 再把因子回测页的运行参数对话框接入 `marketEnvironmentProfile`。
3. 然后把策略回测页参数面板接入同一字段。
4. 最后把运行时观察面板拆成“环境配置值 + 门禁结果”双展示。

## 12. 测试与验收建议

QML 与桥接层至少应验证下面几项：

1. 因子回测页能稳定回显已选市场环境。
2. 策略回测页能稳定提交并回显已选市场环境。
3. 运行时观察面板能同时区分环境配置值和门禁结果。
4. 页面布局在桌面常见宽度下不发生明显挤压和控件变形。

## 13. 结论

QML 与桥接层的核心任务不是“多加一个下拉框”，而是把市场环境开关作为统一页面入口和统一展示合同落下来。

后续实现必须同时满足两件事：

1. 单一合同：页面只认一个 `marketEnvironmentProfile`。
2. 单一审美约束：不通过放大控件和破坏版式来容纳新功能。

只有这样，市场环境开关接入页面之后，才不会把前面文档里已经收口的合同再次打散。

## 14. 补充规则

1. 不允许使用 QString 做类型判断，QString 仅允许用于调试输出。
2. QVariantMap 仅允许作为 QML 输入参数和返回到 QML 的输出载荷，桥接输出对象名统一为 StrategyManage。
