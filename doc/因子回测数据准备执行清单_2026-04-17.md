# 因子回测数据准备执行清单

> **ℹ️ (2026-07)**: MySQL 已退役，PostgreSQL 为当前主库。文中 `pymysql` 命令请改用 `psycopg2` 或 PG 客户端。

## 一键执行

仓库内已新增可直接运行的 PowerShell 编排脚本：

    powershell -ExecutionPolicy Bypass -File .\tools\prepare_factor_backtest_data.ps1

建议先做一次干跑，只检查路径和命令编排：

    powershell -ExecutionPolicy Bypass -File .\tools\prepare_factor_backtest_data.ps1 -DryRun

脚本默认会串联以下步骤：

1. 创建数据库。
2. 导入 astock_init.sql。
3. 导入 astock_init_enhanced.sql。
4. 安装 astock_engine/requirements.txt。
5. 执行 tools/import_from_juejin.py。
6. 执行 tools/check_db_status.py。
7. 执行 tools/run_daily_update_pipeline.py --daily-close-profile --with-financial --include-history-gaps。
8. 执行 tools/verify_daily_update.py。
9. 执行 tools/validate_backtest_data_fields.py。

脚本支持按步骤跳过，例如：

    powershell -ExecutionPolicy Bypass -File .\tools\prepare_factor_backtest_data.ps1 -SkipInstallPythonDeps -SkipFullImport

运行产物默认写入：

- build/factor_backtest_data_prep/logs
- build/factor_backtest_data_prep/daily_update_report.json
- build/factor_backtest_data_prep/run_summary.json

## 目标

把数据库从空库准备到“日线因子 + 财务因子可回测”的可用状态。

当前清单覆盖：

- symbol_info
- daily_bar
- money_flow_daily
- dragon_tiger_list
- financial_indicator
- cleaning_tasks
- cleaning_results

当前未覆盖统一入库：

- news_sentiment
- stock_news
- news_data
- news

上面这些舆情表目前只有读取兼容逻辑，没有同级别的一键正式入库流水线。

## 前置条件

1. MySQL 已启动，且可连接到本机 3306。
2. Python 环境可用。
3. 已安装 [astock_engine/requirements.txt](../astock_engine/requirements.txt) 中依赖。
4. 如需跑掘金全量导入，需额外安装并配置 gm.api 对应 SDK。
5. 如需导入财务数据，需准备聚宽账号。

注意：当前多个脚本直接写死了数据库连接为 127.0.0.1:3306 / root / 123456a / astock_quant。如本地配置不同，需要先调整脚本中的 MYSQL_CONFIG。

## 第 1 步：创建数据库与核心表

PowerShell 中执行：

    mysql -uroot -p -e "CREATE DATABASE IF NOT EXISTS astock_quant CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
    mysql -uroot -p astock_quant < astock_init.sql

如果你还要把清洗结果持久化到库里，再执行：

    mysql -uroot -p astock_quant < astock_init_enhanced.sql

对应表定义：

- [astock_init.sql](../astock_init.sql)
- [astock_init_enhanced.sql](../astock_init_enhanced.sql)

## 第 2 步：安装 Python 依赖

    python -m pip install -r astock_engine/requirements.txt

如果掘金 SDK 未安装，单独补装后再继续跑 [tools/import_from_juejin.py](../tools/import_from_juejin.py)。

## 第 3 步：准备外部凭证

### 掘金全量导入所需

[tools/import_from_juejin.py](../tools/import_from_juejin.py) 会从以下位置之一取 token：

- MyQuantBroker 默认 token
- 环境变量 GM_TOKEN
- 环境变量 ASTOCK_GM_TOKEN
- config/trading_connection.json

### 聚宽财务导入所需

[tools/import_financial_from_jq.py](../tools/import_financial_from_jq.py) 默认读取：

- 环境变量 JQ_USERNAME
- 环境变量 JQ_PASSWORD

## 第 4 步：先做一次全量基础数据导入

执行：

    python tools/import_from_juejin.py

说明：

- 当前脚本主入口默认导入 2023-01-01 到今天，见 [tools/import_from_juejin.py](../tools/import_from_juejin.py#L54) 和 [tools/import_from_juejin.py](../tools/import_from_juejin.py#L701)
- 这一步会先写 symbol_info，再写 daily_bar、money_flow_daily、dragon_tiger_list，见 [tools/import_from_juejin.py](../tools/import_from_juejin.py#L473) 和 [tools/import_from_juejin.py](../tools/import_from_juejin.py#L649)

如果你要更长历史，当前脚本没有命令行参数，直接改 [tools/import_from_juejin.py](../tools/import_from_juejin.py#L54) 的默认起始日期即可。

## 第 5 步：做一次数据库基础检查

执行：

    python tools/check_db_status.py

这个脚本会打印：

- symbol_info 记录数
- daily_bar 记录数
- daily_bar 最新样本

如果这一步没有数据，不要继续跑回测。

## 第 6 步：跑一遍日更总流水线，把财务和缺失字段补齐

推荐直接执行：

    python tools/run_daily_update_pipeline.py --daily-close-profile --with-financial --include-history-gaps --report-file build/daily_update_report.json

说明：

- 这个入口会串联最新日线更新、历史缺口补齐、财务补数、估值回填、换手率回填和校验，入口在 [tools/run_daily_update_pipeline.py](../tools/run_daily_update_pipeline.py)
- 财务导入命令编排在 [tools/run_daily_update_pipeline.py](../tools/run_daily_update_pipeline.py#L345)
- 估值回填命令编排在 [tools/run_daily_update_pipeline.py](../tools/run_daily_update_pipeline.py#L365)

如果你希望可选步骤失败后继续跑完整条链，可以追加：

    --continue-on-step-failure

## 第 7 步：确认 daily_bar 已经对齐到最近交易日

执行：

    python tools/verify_daily_update.py --sample-limit 20

如果返回普通落后样本，先修 daily_bar，不要进入回测。

脚本入口：

- [tools/verify_daily_update.py](../tools/verify_daily_update.py#L173)

## 第 8 步：确认回测字段完整

执行：

    python tools/validate_backtest_data_fields.py --daily-window 180 --financial-window 3650

这一步主要确认：

- 日线字段是否齐全
- 周/月聚合后的字段是否齐全
- financial_indicator 查询字段是否齐全

脚本入口：

- [tools/validate_backtest_data_fields.py](../tools/validate_backtest_data_fields.py#L209)

## 第 9 步：最少检查 SQL

至少执行下面这些 SQL：

    SELECT COUNT(*) FROM symbol_info;
    SELECT COUNT(*) FROM daily_bar;
    SELECT COUNT(*) FROM financial_indicator;
    SELECT MAX(trade_date) FROM daily_bar;
    SELECT MAX(report_date) FROM financial_indicator;

建议补看：

    SELECT symbol, trade_date, close, pe_ratio, pb_ratio, turnover_rate
    FROM daily_bar
    ORDER BY trade_date DESC
    LIMIT 20;

## 第 10 步：舆情因子当前怎么处理

当前代码读取舆情表时，会在下列候选表中寻找一个已存在表：

- news_sentiment
- stock_news
- news_data
- news

读取侧位置：

- [src/ui/bridge/src/DataService.cpp](../src/ui/bridge/src/DataService.cpp#L1326)
- [src/ui/bridge/src/DataService.cpp](../src/ui/bridge/src/DataService.cpp#L1410)

因此当前如果要回测舆情因子，你需要自己先把其中一个表建好并导入数据。否则功能层面虽已支持读取，实际仍会因为无表或无数据而不可用。

## 最短执行顺序

按顺序执行下面 6 条即可：

    mysql -uroot -p -e "CREATE DATABASE IF NOT EXISTS astock_quant CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
    mysql -uroot -p astock_quant < astock_init.sql
    mysql -uroot -p astock_quant < astock_init_enhanced.sql
    python tools/import_from_juejin.py
    python tools/run_daily_update_pipeline.py --daily-close-profile --with-financial --include-history-gaps --report-file build/daily_update_report.json
    python tools/verify_daily_update.py --sample-limit 20

如果上面 6 条都通过，再执行：

    python tools/validate_backtest_data_fields.py --daily-window 180 --financial-window 3650

## 当前结论

对因子回测来说，daily_bar 和 financial_indicator 已经有正式入库链路，且可以直接被回测读取。

对舆情因子来说，读取兼容已经有，但统一入库链路还没有补齐。
