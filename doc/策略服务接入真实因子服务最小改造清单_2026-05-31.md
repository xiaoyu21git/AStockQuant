# 策略服务接入真实因子服务最小改造清单（不含订单服务）

## 1. 结论先行

- 项目存在完整因子服务实现（domain/factor + bridge/FactorService）。
- 当前策略运行时已删除默认 pseudo 回退，必须显式注入因子服务。
- 因此本清单目标是：在不改订单服务前提下，把策略运行时因子来源显式接到真实因子实现。

## 2. 当前状态证据

1. 策略运行时因子接口
- IRuntimeFactorService 定义在 src/domain/strategy/include/IStrategyService.h。

2. 当前注入入口
- StrategyEngine::Builder 支持 withFactorService(...) 与 withFactorCallbacks(...)，位于 src/domain/strategy/include/IStrategyService.h。
- StrategyEngine::Builder::build() 在未注入因子服务时直接失败，位于 src/domain/strategy/src/StrategyEngineFacade.cpp。

3. 策略运行时主链
- onMarketDataPoint/onMarketDataBatch 分别调用 factorService_.updateIncremental / updateBatch，位于 src/domain/strategy/src/StrategyServer.cpp。

4. 真实因子服务存在
- 完整因子实现位于 src/domain/factor（factor_system 目标）。
- 另有桥接层因子服务 src/ui/bridge/src/FactorService.cpp。

5. 构建依赖现状
- domain_strategy_runtime 当前已链接 foundation 与 domain_strategies，见 src/domain/strategy/CMakeLists.txt。
- factor_system 独立目标在 src/domain/factor/CMakeLists.txt。

## 3. 约束边界

- 不改订单服务接口与流程。
- 不引入 QVariantMap/QString 到运行时主链。
- 保持 StrategyService 的 IRuntimeFactorService 抽象边界稳定。

## 4. 最小改造步骤

### 步骤A：新增真实因子运行时适配器（策略域内）

目标：提供一个 IRuntimeFactorService 的真实实现包装层，不改变 StrategyService 调用方式。

建议新增文件：
- src/domain/strategy/src/StrategyRealFactorAdapter.cpp
- 可选头文件：src/domain/strategy/include/StrategyRealFactorAdapter.h

适配器职责：
1. 将 MarketDataPoint 批量/增量输入转换为真实因子引擎可消费的输入格式。
2. 管理真实因子实例与共享结果缓存。
3. 提供当前因子结果快照输出。
4. 出错时直接返回 StrategyServiceFlowCode，禁止回退与伪服务兜底。

### 步骤B：扩展 Builder 注入路径（不改订单）

目标：让 StrategyEngine::Builder 支持从组合根显式注入真实因子实现。

改造点：
- src/domain/strategy/include/IStrategyService.h（Builder 支持 withFactorService(...) / withFactorCallbacks(...)）
- src/domain/strategy/src/StrategyEngineFacade.cpp（build() 未注入时直接失败，不允许 pseudo 回退）

注意：
- 组合根必须显式提供真实因子服务或真实回调。
- 不再保留默认行为与兼容回退。

### 步骤C：补充构建依赖与链接

目标：让 domain_strategy_runtime 可编译真实因子适配器。

改造点：
- src/domain/strategy/CMakeLists.txt

方案二选一：
1. 直接链接 factor_system（最短路径）。
2. 若耦合过大，拆出轻量因子运行时接口库再链接（更干净，但改动更大）。

最小改造建议：先采用方案1，快速打通链路，再评估解耦。

### 步骤D：统一因子键映射（typed-only）

目标：解决运行时因子快照与真实因子输出的合同对齐。

现状：
- 运行时已改为消费共享 `FactorSnapshot` 合同，不再按 `FactorKey` / `factorValue(...)` 查询。

改造建议：
1. 由真实因子适配器直接输出共享 `FactorSnapshot` 列表。
2. 因子 ID 映射集中定义在适配器或组合根内，禁止散落字符串判断。
3. 若后续扩展快照字段，优先修改共享 `FactorSnapshot` 合同，不再新增运行时私有副本。

### 步骤E：保留规则服务现有合同，不联动订单

目标：本次仅替换因子来源，不触碰规则/订单边界。

要求：
- StrategyServer 的规则与下单流程保持不变。
- 所有变更限定在“因子更新与读取”路径。

## 5. 验收标准（必须满足）

1. 构建通过
- Debug/Release 均通过。

2. 策略链路行为
- 相同输入批次下，策略服务可稳定输出信号并进入规则服务。

3. 性能与稳定性
- 不出现每笔全量重算退化。
- 批量路径吞吐满足真实因子实现的可接受门槛（具体阈值另行约定）。

4. 边界约束
- 运行时主链不新增 QVariantMap/QString 类型判断。
- 订单服务代码无改动。

## 6. 回归测试建议（最小集合）

1. 现有规则高频基准保持可运行
- tests/run_strategy_rule_service_hf_benchmark.cpp
- tests/run_strategy_rule_service_py_hf_benchmark.cpp
- tests/run_strategy_rule_service_py_worker_hf_benchmark.cpp

2. 新增一组“真实因子适配器”回归
- 增量输入后可生成共享 `FactorSnapshot`。
- 批量输入后策略 evaluate 可重复。
- 缺失真实因子服务时直接失败，不回退 pseudo。

3. 功能回归
- test_eventsystem 中与策略/规则相关测试保持通过。

## 7. 风险与缓解

1. 风险：factor_system 依赖较重，直接链接可能扩大策略域编译时间。
- 缓解：先打通，再评估抽象成轻量接口库。

2. 风险：因子 ID 映射不一致导致策略读到错误快照。
- 缓解：映射表单点定义 + 启动时自检，不通过直接失败。

3. 风险：真实因子热路径延迟抖动。
- 缓解：批量路径优先、缓存复用、容量预留、压测回归门禁。

## 8. 实施优先级

1. P0：A/B/C（三步打通真实因子接入）
2. P1：D（键映射收敛与扩展策略）
3. P2：性能优化与解耦（按压测结果推进）
