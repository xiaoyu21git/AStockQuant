# 当前策略回测引擎已知规则与边界保留清单

日期：2026-05-26

## 1. 目的

这份文档只做一件事：

按当前代码，收口“策略回测引擎里真实存在、已经被执行链消费、并且值得保留到下一版重设计”的规则与边界。

这里不讨论：

1. QML 页面交互习惯。
2. 历史字符串兼容。
3. bridge 层为了喂旧执行器而做的 map 拼装噪音。
4. 尚未接入真实实现的批量回测、参数优化、策略对比占位能力。

## 3. 一句话结论

当前策略回测引擎里真正值得保留的，不是 controller 里的 `QVariantMap -> string map -> 旧 config` 这段遗留通路，而是下面六块主干：

1. 强类型回测请求合同 BacktestRequest。
2. 强类型回测结果合同 BacktestResultDto。
3. StrategyAggregate 加运行覆盖参数到 BacktestRequest 的单一装配边界。
4. 股票池、风险、执行、数据源、运行参数的显式分层。
5. 因子 overlay 作为“同池候选打分与截断入场”的运行时规则。
6. 规则模板作为“入场阻断/强制退出”的独立运行时边界与摘要输出。

这六块是下一版引擎可以直接继承的骨架。

补充说明：当前仓库中旧 `StrategyBacktestService` 已删除，旧共享 `BacktestEngine` 也已收紧替换为 factor/group 专用的 `FactorBacktestEngine`；[src/ui/bridge/src/StrategyBacktestController.cpp](../src/ui/bridge/src/StrategyBacktestController.cpp) 现阶段只保留显式失败入口，不再承载策略回测装配与执行。

## 4. 应保留的边界

### 4.1 唯一输入边界：BacktestRequest

当前代码已经把引擎主输入拆成明确子合同，见 [src/domain/backtest/include/BacktestRequest.h](../src/domain/backtest/include/BacktestRequest.h)。

应保留的边界是：

1. `strategyIdentity` 只承载策略身份、执行类型、行为类型。
2. `strategySpec` 承载规则快照、执行策略快照、回测假设、策略范围上下文、因子 overlay、规则模板绑定。
3. `universeSpec` 单独表达股票池来源与回测股票池快照。
4. `marketEnvironmentSpec` 单独表达市场制度环境。
5. `costSpec` 单独表达资金与交易成本。
6. `riskSpec` 单独表达头寸、回撤、止损边界。
7. `executionSpec` 单独表达执行制度。
8. `dataSourceSpec` 单独表达原始数据、清洗数据、缓存集选择。
9. `runtimeOptions` 单独表达线程和缓存。
10. `window` 单独表达日期区间。

这条边界的价值很高，因为它已经把“策略定义”和“一次回测运行覆盖参数”拆开了。

### 4.2 唯一输出边界：BacktestResultDto

当前结果主合同见 [src/domain/backtest/include/BacktestResultDto.h](../src/domain/backtest/include/BacktestResultDto.h)。

应保留的边界是：

1. `runMetadata` 表示一次运行的任务与状态事实。
2. `configSnapshot` 表示本次回测真实生效的请求快照。
3. `performanceSummary`、`tradeStatistics`、`riskMetrics` 作为三类结构化统计摘要。
4. `timeSeries`、`tradeRecords` 作为可追溯明细。
5. `universeResolutionSummary` 明确记录股票池解析结果，而不是只在页面文案里显示。
6. `ruleTemplateSummary`、`ruleTemplateEntryBlockCount`、`ruleTemplateForcedExitCount` 把模板规则的执行结果变成正式结果字段。
7. `diagnostics` 作为统一诊断出口。

其中 `tradeRecords` 的成交语义必须显式拆成 `side` 与 `positionEffect`；不得再退回 `direction="BUY/SELL"` 这类压平字段。`Buy/Open`、`Buy/Close`、`Sell/Open`、`Sell/Close` 四种语义必须唯一，不允许合并。

下一版结果合同不需要退回 JSON 拼字典模型，直接沿这个结构继续收紧即可。

### 4.3 单一装配边界：StrategyAggregate + Overrides -> BacktestRequest

当前这条边界已经存在，见 [src/application/backtest/include/BacktestRequestFactory.h](../src/application/backtest/include/BacktestRequestFactory.h) 和 [src/application/backtest/src/CanonicalBacktestRequestFactory.cpp](../src/application/backtest/src/CanonicalBacktestRequestFactory.cpp)。

应保留的原则是：

1. 策略定义来自 `StrategyAggregate`。
2. 本次运行覆盖来自 `BacktestRunOverrides`。
3. 工厂负责组装唯一请求对象。
4. 工厂在出口处做一次 `request.isValid()` 校验，失败直接报错。

这条边界很关键，因为它把“静态策略快照”和“本次运行参数”分层了。

### 4.4 引擎入口边界：ApplicationService / EngineGateway

当前接口边界已经很清晰：

1. [src/application/backtest/include/BacktestApplicationService.h](../src/application/backtest/include/BacktestApplicationService.h) 只认 `run(request)`、`runBatch(requests)`、`cancel(taskId)`。
2. [src/application/backtest/include/BacktestEngineGateway.h](../src/application/backtest/include/BacktestEngineGateway.h) 只认 `execute(request)`。

这说明下一版引擎完全可以把“应用服务”和“执行网关”保留下来作为固定层次。

## 5. 应保留的已知规则

### 5.1 股票池规则

股票池边界当前已经不再只是 UI 概念，而是被运行链真实消费。

保留规则如下：

1. 股票池是显式领域对象 `UniverseSpec`，不是字符串列表外挂字段，见 [src/domain/strategy/include/StrategySnapshotTypes.h](../src/domain/strategy/include/StrategySnapshotTypes.h)。
2. `UniverseSpec` 当前明确区分 `ExplicitSymbols`、`SavedUniverse`、`LinkedWatchlist`、`IndexConstituents` 模式，并有自己的 `isValid()` 规则。
3. `backtestSymbolPool` 是回测期正式股票池快照，`liveSymbolPool` 和 `linkedLiveSymbolPool` 是其他语义，不能混用。
4. 统一交易预览适配器当前的股票池优先级是：`backtestSymbolPool > resolvedSymbols > explicitSymbols`，见 [src/application/trading/src/DefaultStrategyBacktestTradingAdapter.cpp](../src/application/trading/src/DefaultStrategyBacktestTradingAdapter.cpp)。
5. `StrategyStructureAssembler` 当前已经把 `normalized.backtestSymbolPool` 填回 `UniverseSpec`，并在显式股票列表缺失时再回看其他来源，见 [src/domain/strategy/src/StrategyStructureAssembler.cpp](../src/domain/strategy/src/StrategyStructureAssembler.cpp)。

这组规则值得保留，因为它把“回测实际股票池”正式化了。

### 5.2 成本与风险规则

当前引擎已经把成本和风险从请求层拆开，且会进入 trading context，见 [src/application/trading/src/DefaultStrategyBacktestTradingAdapter.cpp](../src/application/trading/src/DefaultStrategyBacktestTradingAdapter.cpp)。

保留规则如下：

1. 初始资金、佣金、滑点、税率必须属于 `costSpec`。
2. 总仓位上限、单票上限、最大回撤、止损率必须属于 `riskSpec`。
3. 请求对象自身要能独立做有效性校验，非法请求不能进入执行层。
4. 风险与成本不应继续散落在策略参数 map 里由各处自行解释。

这里值得保留的是“显式成本/风险合同”，不是 bridge 里那些 alias key。

### 5.3 执行制度规则

当前执行制度已经有明确结构，见 [src/domain/backtest/include/BacktestRequest.h](../src/domain/backtest/include/BacktestRequest.h) 和 [src/application/trading/src/DefaultStrategyBacktestTradingAdapter.cpp](../src/application/trading/src/DefaultStrategyBacktestTradingAdapter.cpp)。

保留规则如下：

1. `executionKind` 必须是显式枚举边界，不允许再回到字符串执行类型。
2. `positionSizingMethod` 必须是显式策略字段。
3. `enableShortSelling`、`rebalanceFrequencyDays`、`useMarketOnClose` 应归属 `executionSpec`。
4. 统一交易上下文必须从 `executionSpec` 派生执行价格模型和执行能力。

也就是说，下一版应保留“执行制度是单独合同”这件事。

### 5.4 因子 overlay 规则

当前 overlay 不是 UI 伪概念，确实进入了运行时，见 [src/domain/strategy/include/StrategySnapshotTypes.h](../src/domain/strategy/include/StrategySnapshotTypes.h)、[src/domain/backtest/src/BacktestDecisionRuntime.cpp](../src/domain/backtest/src/BacktestDecisionRuntime.cpp)、[src/domain/backtest/src/BacktestExecutionRuntime.cpp](../src/domain/backtest/src/BacktestExecutionRuntime.cpp) 和 [src/domain/backtest/src/FactorBacktestEngine.cpp](../src/domain/backtest/src/FactorBacktestEngine.cpp)。

保留规则如下：

1. overlay 是“同一股票池内的候选排序与截断规则”，不是新的股票池来源。
2. overlay 只在 `enabled=true` 且已声明选中因子时才生效。
3. overlay 分配权重会先归一化，然后按交易日读取各因子的截面值。
4. overlay 当前的复合得分计算方式是截面 z-score 加权求和。
5. overlay 支持 `minimumCompositeScore` 作为入场阈值。
6. overlay 支持 `targetPositionCount` 作为持仓槽位上限。
7. overlay 的入场不是即时逐标的下单，而是“同时间批次收集候选，再按评分决定可进入的买入名额”。
8. overlay 不改变卖出规则；卖出仍由基础信号和规则模板退出共同决定。

这组规则非常值得保留，因为它是当前引擎里少数已经跑通的“组合选股层”。

### 5.5 规则模板规则

当前规则模板已经形成独立运行时边界，见 [src/domain/backtest/src/BacktestExecutionRuntime.cpp](../src/domain/backtest/src/BacktestExecutionRuntime.cpp) 和 [src/engine/include/BacktestResult.h](../src/engine/include/BacktestResult.h)。

保留规则如下：

1. 规则模板不是策略主信号本身，而是对候选买入和已有持仓的二次约束层。
2. 入场阶段支持 `entry_block`，即阻断本来成立的买入信号。
3. 持仓阶段支持 `forced_exit`，即强制退出本来未触发普通卖出信号的持仓。
4. 模板运行结果要进入正式结果摘要，不能只停留在日志。
5. 模板事件需要保留最近事件、组决策、阻断次数、强退次数这类结果事实。

这块值得保留，因为它天然适合作为新引擎里的独立 rule gating 层。

### 5.6 单标的信号与订单执行规则

当前运行时核心见 [src/domain/backtest/src/BacktestExecutionRuntime.cpp](../src/domain/backtest/src/BacktestExecutionRuntime.cpp)。

保留规则如下：

1. bar 驱动是当前执行主循环的真实粒度。
2. 先更新 symbol state、最新价和 mark-to-market，再做信号判断。
3. 买入前先经过规则模板入场判定；卖出前先经过规则模板强退判定。
4. 买入资金分配基于当前权益、单次目标仓位比例、现金可用性。
5. 下单数量按 100 股整手向下取整。
6. 成交后交易记录、现金、持仓、权益曲线同步更新。
7. 结束时对未平仓仓位做统一 final close，并重新刷新最终权益曲线。

这一组是引擎最核心的 bar execution 规则，应保留为下一版的最小执行内核。

### 5.7 统一交易预执行规则

当前策略回测已经接上统一交易预执行摘要，见 [src/application/trading/src/UnifiedStrategyBacktestPreviewService.cpp](../src/application/trading/src/UnifiedStrategyBacktestPreviewService.cpp)。

保留规则如下：

1. 预执行先从回测请求生成目标仓位批次和交易上下文。
2. 若存在起始日快照价格，则补充参考价和目标数量。
3. 再交给统一交易 core 生成风险决策、订单计划、成交摘要。
4. 预执行结果不替代回测结果，但必须进入 diagnostics。

这条边界很值得保留，因为它是未来回测与真实交易联动的连接点。

## 6. 当前已明确存在的硬边界

这些不是“未来设想”，而是当前代码已经体现出的硬边界：

1. 当前引擎真实支持的是“同池、日频 bar 驱动、股票多标的轮询/归并执行”。
2. 当前引擎真实支持的是“多因子排序选股 overlay”，不是多频率分层策略。
3. 当前引擎真实支持的是“规则模板 gating”，不是完整策略 DSL。
4. 当前 typed 主干真实支持的是“结构化请求/结果边界”；旧策略回测 bridge 已拆成显式失败壳，等待新策略引擎接入。
5. 当前引擎真实支持的是“长仓优先的现货型执行”，不是完整多空或衍生品执行。

这五条应在重建设计时直接当作现状边界，而不是继续误判成“已经支持更复杂抽象”。

## 7. 不应保留到新引擎主合同的部分

下面这些东西虽然出现在代码里，但不值得带进下一版主合同。

### 7.1 已清除的旧 bridge 噪音

旧策略回测 controller 中那层 `QVariantMap -> string map -> 旧 config` 的拼装辅助、alias 回看和结果整形噪音已经从当前实现中删除。

下一版引擎不应把这层旧 bridge 噪音重新引回主合同。

### 7.2 尚未接入真实实现的能力

当前下列能力只有接口或占位，不应被当成“已知引擎规则”：

1. `BacktestApplicationService` 目前只有接口，没有对应 cpp 落地。
2. 旧 `startBatchStrategyBacktest`、`optimizeStrategyParameters`、`compareStrategies` 公开接口已从 `StrategyBacktestController` 删除，不再对外暴露伪能力。
3. 新策略引擎接入前，策略回测对外只保留单次启动入口和显式失败状态反馈。

这些不属于可保留规则，只能算待建能力。

### 7.3 旧执行核里的硬编码限制

当前 `BacktestExecutionRuntime` 里仍有一些临时硬编码，不建议原样保留：

1. `buildUnifiedTradingContext` 把市场环境固定成 `GENERIC_EQUITY`。
2. 统一执行 helper 内把 `enableShortSelling` 固定为 false。
3. helper 内把 `rebalanceFrequencyDays` 固定为 1。
4. helper 内把税率固定为 0。
5. overlay 执行当前实质仍按等比例资金切块，不是完整组合优化器。

这些是当前实现限制，不是新引擎应该继承的规则。

## 8. 可直接作为新引擎基线的最小集合

如果只保留当前代码里最有价值的部分，建议新引擎第一版直接冻结为下面八项：

1. `BacktestRequest` 作为唯一输入合同。
2. `BacktestResultDto` 作为唯一输出合同。
3. `BacktestRequestFactory` 作为唯一装配入口。
4. `UniverseSpec` 作为唯一股票池合同，并保留 `backtestSymbolPool` 正式语义。
5. `RiskSpec`、`CostSpec`、`ExecutionSpec` 三分结构。
6. factor overlay 作为“同池打分筛选层”。
7. rule template 作为“入场阻断/强制退出层”。
8. bar 驱动执行内核加结构化 diagnostics/summary 输出。

## 9. 最终结论

按当前代码，下一版回测引擎不应该继承的，是 bridge 层的字符串拼装与旧 config 兼容链；下一版真正应该继承的，是已经存在的 typed request/result、股票池正式快照、成本风险执行三分、factor overlay 排序层、rule template gating 层，以及 bar 驱动执行内核。

如果后续你要重设计，建议直接把这份清单视为“可保留骨架”，其余遗留 map/string 通道全部作为迁移期噪音处理，而不是继续进入新合同。
