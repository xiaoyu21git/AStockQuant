## 1. 设计原则

| 原则                     | 说明                                                                                                     |
| ------------------------ | -------------------------------------------------------------------------------------------------------- |
| **引擎内核纯计算** | 只做回测模拟，消费“已准备好”的数据和规则检查结果，不负责数据清洗、规则解析、绩效归因、UI 交互。        |
| **强类型合同**     | 输入唯一为 `BacktestRequest`，输出唯一为 `BacktestResultDto`，均为强类型结构体，杜绝字符串字典拼装。 |
| **扩展点接口化**   | 所有可能替换的行为（数据源、规则检查、执行模拟、组合优化、分析）均定义为纯虚接口，引擎通过依赖注入使用。 |
| **配置驱动**       | 策略的分层结构、因子组合、规则绑定、执行参数均由 `BacktestRequest` 中的配置描述，引擎无硬编码行为。    |
| **分层漏斗模型**   | 策略可定义为 N 层决策链，每层使用不同频率的因子，候选池逐层收窄，硬约束下层不得越界选股。                |
| **硬边界显式化**   | 引擎内外部职责以接口契约严格分离，防止功能膨胀，禁止跨层信息泄露。                                       |
| **性能内建**       | 数据布局、内存策略、惰性求值在架构设计阶段即固化，不依赖事后优化。                                       |

## 2. 核心架构

### 2.1 组件依赖

```
ApplicationService  ──调用──>  BacktestEngine
                                   │
                   ┌───────────────┼───────────────┐
                   │               │               │
            IMarketDataCache   IRuleChecker   IExecutionSimulator
                   │               │               │
                   └───────────────┼───────────────┘
                                   │
                           IPortfolioOptimizer (可选)
                                   │
                               IAnalyzer (可选)
```

- **BacktestEngine**：主引擎，驱动分层漏斗、事件循环，管理持仓与现金，生成结果。
- **IMarketDataCache**：提供按时间、标的、频率的数据切片，数据已对齐、复权完毕。
- **IRuleChecker**：封装好的规则检查，返回入场是否阻断、强制退出与否。
- **IExecutionSimulator**：订单撮合与成本计算。
- **IPortfolioOptimizer**：将候选池转化为目标权重（默认等权）。
- **IAnalyzer**（可选）：对结果进行后处理，生成额外诊断或归因。

引擎本身不包含任何这些接口的具体实现，编译时仅依赖接口头文件。

### 2.2 数据流

1. **输入**：`ApplicationService` 根据策略快照与运行参数组装 `BacktestRequest`，调用 `engine.execute(request)`。
2. **初始化**：引擎校验请求，通过 `IMarketDataCache` 获取预热及回测区间所有所需列式数据，建立整数索引。
3. **主循环**：按交易日迭代，执行分层决策；需规则判断时调用 `IRuleChecker::checkRules()`；生成订单时调用 `IExecutionSimulator::execute()`；分配权重时调用 `IPortfolioOptimizer::computeWeights()`。
4. **结果封装**：每日更新权益、交易记录、基准对比，最终组装 `BacktestResultDto`，可选调 `IAnalyzer`。
5. **输出**：返回结构体，包含绩效、交易、风险指标、分层归因、诊断等。

## 4. 分层决策漏斗设计

### 4.1 决策层配置

策略由多个 `DecisionLayer` 组成，配置在 `StrategySpec` 中。

```cpp
struct DecisionLayer {
    LayerId id;
    LayerType type;                // STRATEGIC, TACTICAL, EXECUTION
    UniverseId inputUniverseId;    // 输入池来源（上一层输出或全局池）
    FactorOverlayConfig overlay;   // 因子合成规则
    RuleTemplateId ruleTemplateId; // 绑定的规则模板
    CandidateCount targetPositionCount;
};
```

### 4.2 分层职责与硬约束

| 层级 | 名称   | 典型频率  | 职责                                   | 输入池                 | 输出池       |
| ---- | ------ | --------- | -------------------------------------- | ---------------------- | ------------ |
| L1   | 战略层 | 月/季     | 定长期投资域、风格暴露、排除风险标的   | 全局池（UniverseSpec） | 战略池       |
| L2   | 战术层 | 日/周     | 在战略池内二次选股，输出高关注清单     | 战略池（L1输出）       | 战术精选清单 |
| L3   | 执行层 | 分钟/Tick | 在战术清单内捕捉买卖时机，优化执行价格 | 战术清单（L2输出）     | 实际执行订单 |

**不可违反的规则**：

- L3 的因子计算与信号触发**只能在 L2 输出清单内进行**，任何池外信号强制丢弃。
- L2 的因子计算与选股**只能在 L1 输出的战略池内进行**。
- 每层候选池的成分必须基于当时已知的历史快照，禁止使用未来成分数据。
- 回测引擎在合成因子前自动校验因子值的 `universeId` 和截止时间，不匹配则终止执行并报错。

## 5. 因子 Overlay 与域隔离规则

### 5.1 单层 Overlay 执行流程

1. 从 `IMarketDataCache` 获取该层所有因子的数值列。
2. **域隔离校验**：所有因子值必须具有相同的 `universeId` 且信息截止时间一致。
3. 截面 Z-score 标准化。
4. 按配置权重加权求和得复合得分。
5. 丢弃低于 `minimumCompositeScore` 的候选。
6. 取前 `targetPositionCount` 只作为本层输出。

### 5.2 因子组合铁律（硬校验）

- **候选池一致**：参与合成的因子值必须在完全相同的股票集合内计算和标准化。
- **信息截止时间一致**：同一决策点，所有因子使用的数据截止时刻必须相同（日频因子用 T-1 收盘，分钟因子用上一完整分钟）。
- **截面标准化一致**：合成前必须基于同一候选池截面做 Z-score 或排名映射。
- **频率对齐**：不同频率因子合成时，必须统一到决策频率（高频降频快照，或低频前值填充并标记过期）。

## 6. 规则模板与外部规则检查

### 6.1 引擎规则消费方式

引擎通过 `IRuleChecker` 接口消费规则，自身不解析规则 DSL、不存储规则定义。

```cpp
struct RuleCheckResult {
    bool blocked = false;      // 入场是否阻断
    bool forceExit = false;    // 是否强制退出
    RuleDecision decision;     // 原因与代码
};

class IRuleChecker {
public:
    virtual ~IRuleChecker() = default;
    virtual RuleCheckResult checkRules(const StrategyContext& ctx,
                                       const Symbol& symbol,
                                       DecisionType type) = 0;
};
```

### 6.2 规则应用时机

- **入场阻断**：对 Overlay 输出的每个候选，在生成订单前调用 `checkRules(..., DecisionType::ENTRY)`，若 `blocked=true` 则移出候选池。
- **强制退出**：每日对已有持仓，调用 `checkRules(..., DecisionType::HOLD)`，若 `forceExit=true` 则以市价立即平仓。
- 规则执行结果汇总写入 `RuleTemplateSummary`，包含阻断次数、强退次数及原因分布。

## 7. 执行模拟与订单管理

### 7.1 执行模拟接口

```cpp
struct Order { Symbol sym; double quantity; OrderType type; };
struct Fill { double price; double qty; double fee; };

class IExecutionSimulator {
public:
    virtual ~IExecutionSimulator() = default;
    virtual Fill execute(const Order& order, const MarketDataSlice& current) = 0;
};
```

引擎通过 `IExecutionSimulator::execute()` 获取成交结果，**不假设一定成交**，不管理订单簿。成交后立即同步更新持仓、现金和权益曲线。

### 7.2 默认实现与保真度分级

- **V1.0 默认**：`FastExecutionSimulator`，按 bar 固定滑点或 VWAP 成交，订单立即全部成交或取消（FOK）。
- **后续版本**：`HighFidelitySimulator`，支持限价单、部分成交、订单簿重建等，引擎仅需切换注入的实现。

## 8. 主事件循环与多频率时钟

### 8.1 主循环逻辑

```
for each 交易日 in window:
    if 调仓日:
        执行L1决策
    执行L2决策
    if 启用日内:
        for each 分钟 bar:
            执行L3决策与订单
            更新持仓/现金
    else:
        生成L2目标订单并批量执行
    记录权益、交易、基准
    可选进度回调
最终生成BacktestResultDto
```

### 8.2 分钟子循环时间戳保证

- 引擎使用的分钟数据必须保证是已完整生成的闭包 bar（如 `09:59` 的 bar 在 `10:00` 才可用于决策）。
- 因子计算中使用的数据截止时间严格为上一决策时刻，引擎在诊断中声明此假设。

## 9. 引擎内部职责与外部边界（已冻结）

### 9.1 引擎内部必须承担的规则逻辑

1. 分层候选池约束与逐层过滤。
2. 因子域隔离校验（同池、同时、同截面标准化）。
3. 调用外部规则检查接口，执行阻断/强退。
4. 持仓与资金管理（现金检查、整手取整、仓位上限、权益更新）。
5. 调用执行模拟器并获得成交反馈，更新状态。
6. 收集规则执行统计并生成摘要。
7. 记录引擎自身简化假设至 `diagnostics.assumptions`。

### 9.2 外部模块职责（引擎绝不涉足）

| 模块     | 职责                                               | 接口                                  |
| -------- | -------------------------------------------------- | ------------------------------------- |
| 数据缓存 | 数据清洗、复权、分红、停牌处理、财务数据 PIT、预热 | `IMarketDataCache`                  |
| 规则引擎 | 规则定义、DSL 解析、模板管理、实际条件判断         | `IRuleChecker`                      |
| 执行模拟 | 订单簿重建、撮合逻辑、滑点、冲击成本               | `IExecutionSimulator`               |
| 组合优化 | 风险预算、权重优化、行业中性约束                   | `IPortfolioOptimizer`               |
| 绩效分析 | 归因计算、报表生成                                 | `IAnalyzer`                         |
| 参数优化 | 网格搜索、遗传算法、过拟合检验                     | 应用层（通过多次 `execute()` 实现） |
| 实盘桥接 | 信号转换、订单下发、差异分析                       | 实盘适配层                            |

### 9.3 硬边界清单（不可逾越）

- 引擎不进行任何 I/O，所有数据通过预加载的缓存获取。
- 引擎不解析规则 DSL，仅消费 `RuleCheckResult`。
- 引擎不修改数据视图，只读访问。
- 热路径禁止动态内存分配。
- 因子合成前强制校验候选池与时间戳，失败即终止（无降级模式）。
- 规则阻断/强制退出决定不可覆盖，必须执行。
- 所有简化假设写入 `diagnostics.assumptions`，如“使用完整日线”、“按收盘价成交”等。
- 基于快照运行，回测期间策略修改不影响运行中实例。

## 10. 性能基础设计（已冻结）

| 策略                 | 具体措施                                                                                    |
| -------------------- | ------------------------------------------------------------------------------------------- |
| **列式存储**   | 各字段（价格、因子值）独立连续存储，通过 `const double*` 指针遍历，利用 CPU 缓存和 SIMD。 |
| **整数索引**   | 所有股票分配固定 `int id`，全部查找使用数组下标，禁止字符串 key。                         |
| **预分配内存** | 结果容器、事件队列在初始化时 `reserve` 足够容量，循环内零分配。                           |
| **惰性求值**   | 上层池不变时下层不重复计算；非调仓日跳过低频层。                                            |
| **无全局状态** | 引擎实例完全自包含，支持多线程并行批量回测。                                                |
| **性能门禁**   | CI 包含基准测试（10年日频/5000股/单层overlay <5秒）。                                       |

## 4. 输入输出合同

### 4.1 输入：BacktestRequest

```cpp
struct BacktestRequest {
```

## 5. 功能详细设计

### 5.1 分层决策漏斗

策略由多个 `DecisionLayer` 组成，配置在 `StrategySpec` 中。每层结构：

```cpp
struct DecisionLayer {
    LayerId id;
    LayerType type;                // STRATEGIC, TACTICAL, EXECUTION
    UniverseId inputUniverseId;    // 输入池来源
    FactorOverlayConfig overlay;   // 因子合成规则
    RuleTemplateId ruleTemplateId; // 绑定的规则模板
    CandidateCount targetPositionCount;
};
```

执行规则：

- L1 层在调仓日执行，输出“战略池”。
- L2 层在每日执行，基于 L1 池输出“战术精选清单”。
- L3 层在日内分钟循环中执行，仅能在 L2 清单内触发信号，**绝不越界选股**。

### 5.2 因子Overlay与域隔离

每层 Overlay 执行流程：

1. 从 `IMarketDataCache` 获取该层所有因子的数值列。
2. **域隔离校验**：确保所有因子值具有相同的 `universeId` 和时间戳（信息截止时间一致）。
3. 截面 Z-score 标准化。
4. 按配置权重加权求和得复合得分。
5. 丢弃低于 `minimumCompositeScore` 的候选。
6. 取前 `targetPositionCount` 只作为本层输出。

**硬规则**：合成前因子值必须同池、同时，引擎内置断言校验，失败则终止并报错。

### 5.3 规则模板Gating

引擎通过 `IRuleChecker` 接口消费规则，自身不解析规则。规则绑定到决策层，在入场和持仓阶段调用。

- **入场阻断**：对 Overlay 输出的每个候选，调用 `checkRules(ctx, symbol, DecisionType::ENTRY)`，若返回 `blocked=true` 则移除。
- **强制退出**：每日对已有持仓，调用 `checkRules(ctx, symbol, DecisionType::HOLD)`，若返回 `forceExit=true` 则以市价平仓。
- 规则执行结果写入 `RuleTemplateSummary`。

### 5.4 执行模拟与订单管理

引擎生成订单后调用 `IExecutionSimulator::execute(order, currentData)`，获取成交结果。订单按整手（100股）向下取整。资金分配基于当前权益、目标仓位比例和现金可用性，默认等权，可由 `IPortfolioOptimizer` 替换。

成交后同步更新持仓、现金和权益曲线。

### 5.5 事件驱动主循环

```text
for each 交易日 in window:
    if 调仓日:
        执行L1决策
    执行L2决策
    if 启用日内:
        for each 分钟 bar:
            执行L3决策与订单
            更新持仓/现金
    else:
        生成L2目标订单并批量执行
    记录权益、交易、基准
    进度回调(可选)
最终生成BacktestResultDto
```

循环中所有数据访问使用列式指针和整数索引，无字符串操作，无动态内存分配。

## 6. 边界与约束

### 6.1 引擎内部职责

- 校验 `BacktestRequest` 完整性。
- 驱动分层漏斗与因子合成，执行域隔离。
- 调用外部 `IRuleChecker` 进行入场/退出判断。
- 调用 `IExecutionSimulator` 进行交易模拟。
- 管理持仓、现金、权益曲线。
- 生成完整的 `BacktestResultDto`，包含分层归因和规则摘要。
- 记录诊断信息（引擎简化假设、性能指标）。

### 6.2 外部模块职责（引擎绝不涉足）

| 模块     | 职责                                                 | 接口                    |
| :------- | :--------------------------------------------------- | :---------------------- |
| 数据缓存 | 数据清洗、复权、分红处理、PIT 数据提供、预热数据准备 | `IMarketDataCache`    |
| 规则引擎 | 规则定义解析、DSL 编译、市场状态判断、规则优先级     | `IRuleChecker`        |
| 执行模拟 | 订单簿重建、滑点模型、冲击成本、挂单管理             | `IExecutionSimulator` |
| 组合优化 | 风险预算、权重优化、行业中性等                       | `IPortfolioOptimizer` |
| 绩效分析 | 归因计算、报表生成、图表数据准备                     | `IAnalyzer`           |

### 6.3 硬边界清单

- 引擎**不进行任何 I/O**，所有数据通过预加载的缓存获取。
- 引擎**不解析任何规则 DSL**，仅消费 `RuleCheckResult`。
- 引擎**不修改传入的数据视图**，只读访问。
- 引擎**不在热路径使用动态分配**，所有容器预分配。
- 因子合成前**强制校验候选池一致性与时间戳**，否则终止。
- 规则阻断或强制退出的决策**不可覆盖**，必须执行。
- 所有假设（如“使用完整日线数据”、“未建模挂单”）写入 `diagnostics.assumptions`。
- 不保留策略定义的动态链接，全部基于快照运行。

## 7. 性能基础设计

1. **列式存储与内存映射**
   数据以列式 `std::vector<double>` 存储，通过 `const double*` 指针遍历，利用 CPU 缓存和 SIMD。
2. **整数索引代替字符串**
   所有股票映射为整数 ID，所有查找使用数组索引，无哈希。
3. **零动态分配**
   结果容器、事件队列在初始化时一次性分配足够容量，循环内禁止 `new/delete`。
4. **惰性求值与脏标记**
   上层池不变时，下层不重复计算；仅调仓日执行低频层。
5. **无全局状态**
   `BacktestEngine` 实例完全自包含，支持多线程并行跑不同参数组合。
6. **性能门禁**
   设置基准测试（如 10 年日频 5000 股 < 5 秒），纳入 CI 强制通过。
