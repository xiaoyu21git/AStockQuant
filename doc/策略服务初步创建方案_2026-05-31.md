# 策略服务初步创建方案（运行时层）

日期：2026-05-31

## 1. 目标

本方案用于启动运行时 StrategyService 的第一阶段落地，交付三类资产：

1. 初步创建文档。
2. typed 类型定义。
3. 抽象服务接口。

本方案只覆盖运行时层，不覆盖 QML 桥接层 StrategyManage。

## 2. 分层边界

依据现有分层文档，统一采用以下边界：

1. 桥接层 StrategyManage 负责页面输入、仓储协调、展示投影。
2. 运行时 StrategyService 负责编排 FactorService、策略求值、规则校验与订单请求。
3. 运行时主链禁止 QVariantMap 和页面字符串语义进入。

## 3. 初始目录落位

本次初步创建文件落位如下：

1. src/domain/strategy/include/StrategyServiceTypes.h
2. src/domain/strategy/include/IStrategyService.h

说明：

1. 放在 domain::strategy 目录，避免和当前策略算法子类边界混淆。
2. 首批以头文件合同为主，不引入临时实现和兼容分支。

## 4. 类型合同（第一批）

第一批类型覆盖运行时主链最小闭环：

1. InstrumentId：标的 ID（typed value）。
2. StrategyInstanceId：策略实例 ID。
3. FactorKey：因子键。
4. MarketDataPoint：行情点。
5. StrategySignal：策略信号。
6. RuleCheckResult：规则校验结果。
7. OrderRequest：订单请求。
8. StrategyExecutionStats：批次执行统计。
9. StrategyServiceExecutionPlan：批次容量和执行上限控制。

约束：

1. 类型字段全部是枚举和值类型。
2. 不使用字符串作为主链业务判定键。
3. 缺失关键 typed 字段时由调用方直接失败，不做兜底补写。

## 5. 抽象接口（第一批）

第一批抽象接口：

1. IRuntimeFactorService：批量/增量更新与按键读取。
2. IRuntimeRuleService：单条和批量规则校验。
3. IRuntimeStrategy：策略实例求值接口。
4. IStrategyService：运行时编排总入口。

说明：

1. 为减少文件数量，上述接口统一定义在 IStrategyService.h。

入口约束：

1. 主入口统一支持 onMarketDataBatch。
2. 单行情 onMarketDataPoint 作为低延迟补充入口。
3. 批处理输出缓冲由调用方/服务方显式复用，避免重复分配。
4. 执行前必须配置 StrategyServiceExecutionPlan；容量不足时直接返回 CapacityExceeded。

## 6. 非目标

本阶段明确不做以下内容：

1. 不实现具体 FactorService 算法。
2. 不实现具体规则引擎适配。
3. 不实现订单网关发送。
4. 不引入 EventBus 异步消息主链。

## 7. 代码准则

1. typed-only 边界。
2. 运行时热路径不使用 QString 做业务判断。
3. 不引入旧字段兼容、别名字段和回退映射。
4. 接口保持最小必要集，先稳合同再补实现。
5. 仅在策略模块内做性能优化：容量规划、批处理复用、最小重算；不扩散到其他模块。

## 8. 下一步

1. 在 infrastructure/application 层提供 IRuntimeFactorService、IRuntimeRuleService 的最小可测实现。
2. 在 StrategyService 实现中完成策略注册、批量求值、规则校验和订单请求输出。
3. 增加运行时回归测试：空批次、无策略、无信号、规则全拒绝、规则部分通过。
