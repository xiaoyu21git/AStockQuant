# 因子回测链市场环境对齐清单

## 1. 目标

本文只覆盖因子回测这一条链，不讨论策略回测和实时执行。

目标是把“市场环境开关”落到因子回测的单一合同中，并明确：

1. 当前哪些位置直接控制因子回测语义。
2. 后续要新增哪些字段。
3. 哪些同语义字段、兼容字段和歧义表述必须禁止。
4. 配置、执行器、结果合同、缓存键和测试矩阵各自怎么对齐。

本文是模块级清单，不是实现说明书。

## 2. 当前锚点

当前因子回测链的关键锚点有五个：

1. 运行参数入口：`FactorBacktestController::backtestRuntimeParams`，见 [src/ui/bridge/src/FactorBacktestController.cpp](../src/ui/bridge/src/FactorBacktestController.cpp#L1095)。
2. 回测配置结构：`factor::BacktestConfig`，见 [src/domain/factor/include/FactorBacktestExecutor.h](../src/domain/factor/include/FactorBacktestExecutor.h)。
3. 执行主链：`FactorBacktestExecutor`，尤其是 future return、benchmark 对齐、result 日期归属等逻辑，见 [src/domain/factor/src/FactorBacktestExecutor.cpp](../src/domain/factor/src/FactorBacktestExecutor.cpp)。
4. 结果合同：`FactorBacktestResultContract`，见 [src/ui/bridge/src/FactorBacktestResultContract.cpp](../src/ui/bridge/src/FactorBacktestResultContract.cpp)。
5. 页面回传配置：`buildConfigMap` / `buildResultMap`，见 [src/ui/bridge/src/FactorBacktestController.cpp](../src/ui/bridge/src/FactorBacktestController.cpp#L572) 和 [src/ui/bridge/src/FactorBacktestController.cpp](../src/ui/bridge/src/FactorBacktestController.cpp#L2034)。

此外，回测结果缓存键目前只看 `instanceId + startDate + endDate + forwardDays + numGroups + riskSignature`，见 [src/domain/factor/src/FactorCacheManager.cpp](../src/domain/factor/src/FactorCacheManager.cpp#L23)。

## 3. 当前问题

当前因子回测链存在四类直接问题：

1. 没有正式的 `marketEnvironmentProfile` 字段。
2. `forwardDays` 的语义仍然偏模糊，更像“往后看几天”，没有和市场制度绑定。
3. 结果合同里只有 `forwardDays`、`rebalanceDays` 这类参数快照，没有显式说明结果是在什么市场环境下计算出来的。
4. 缓存键没有市场环境维度，未来一旦切换市场环境会误复用旧结果。

## 4. 硬约束

后续实现必须遵守下面这些硬约束：

1. 不允许新增同语义兼容字段。
2. 不允许同时保留 `marketType`、`marketEnvironment`、`marketEnvironmentProfile` 这类重复语义字段。
3. 不允许用字符串作为 C++ 内部的市场环境真源。
4. 不允许在结果合同里继续使用模糊表述，如“预测窗口”但不说明信号日和执行日起点关系。
5. 不允许为了兼容旧结果而保留双口径字段并存。

## 5. 目标合同

### 5.1 顶层输入

因子回测链第一阶段只允许新增一个用户输入字段：

1. `marketEnvironmentProfile`

该字段应作为整数枚举值进入 `backtestRuntimeParams`，再由控制器写入 `factor::BacktestConfig`。

### 5.2 内部解析结果

执行器内部不应直接根据 `forwardDays` 自行猜测市场语义，而应在执行前拿到解析后的环境语义。

最少应解析出：

1. `executionLagTradingDays`
2. `allowSameDaySellAfterBuy`
3. `returnAttributionMode`
4. `executionPriceModel`
5. `shortSellingMode`
6. `priceLimitMode`

第一阶段可以先把这些放在执行器内部的解析结构里，不要求页面直接展示全部细项。

## 6. 配置层对齐

### 6.1 `backtestRuntimeParams`

当前 `backtestRuntimeParams` 是 `QVariantMap` 直传，见 [src/ui/bridge/src/FactorBacktestController.cpp](../src/ui/bridge/src/FactorBacktestController.cpp#L1095)。

后续应新增：

1. `marketEnvironmentProfile`

禁止新增：

1. `marketType`
2. `marketEnvironment`
3. `isAShare`
4. `useTPlusOne`

原因：

- 这些字段都属于重复表达同一制度语义，会直接制造歧义。

### 6.2 `factor::BacktestConfig`

后续应在 `BacktestConfig` 中新增：

1. `marketEnvironmentProfile`

同时应收紧现有字段注释和解释：

1. `forwardDays` 不再写“预测未来几天”，而应改成“执行日起算的持有交易日窗口”或等价单一语义。
2. `rebalanceDays` 继续只表示调仓间隔，不再承担环境制度语义。

禁止做法：

1. 保留旧注释不改，只靠新文档口头解释。
2. 继续让 `forwardDays` 同时表示“研究窗口”和“执行持有窗口”。

## 7. 执行器层对齐

执行器层需要对齐四个面：

### 7.1 收益起点

`FactorBacktestExecutor` 必须从 `marketEnvironmentProfile` 解析出收益起点规则，而不是默认 same-day 起算。

最直接受影响的位置：

1. cached future return 预计算。
2. `calculateFutureReturn` helper。
3. IC 和分组收益聚合时的起始索引。

### 7.2 日期归属

必须显式区分：

1. `signalDate`
2. `executionDate`

即便第一阶段不把这两个字段全部暴露给页面，执行器内部也必须先完成这层拆分。

禁止做法：

1. 继续只保留一个 `factorResult.date` 就让它同时承担信号日和执行日语义。

### 7.3 benchmark 对齐

benchmark 的收益起点和日期归属必须跟策略收益序列服从同一市场环境规则。

禁止做法：

1. 策略收益改成执行日起算，但 benchmark 继续按信号日起算。

### 7.4 actualStartDate

`actualStartDate` 必须解释为“首个可执行样本日”，而不是“首个有因子计算结果的日期”。

## 8. 结果合同层对齐

### 8.1 `config`

后续结果 `config` 至少应新增：

1. `marketEnvironmentProfile`

必要时补充：

1. `signalDateSemantics`
2. `executionDateSemantics`
3. `returnAttributionMode`

约束：

1. C++ 内部保存枚举或结构化值。
2. QML 需要展示文字时，由桥接层单独映射标签。

### 8.2 `metrics`

结果指标层后续应显式区分研究和执行语义，不允许再靠标题文案隐含市场环境。

至少要保证：

1. 因子质量指标使用的收益口径可追溯。
2. 多空研究指标和执行指标不能混算。
3. A 股环境下保留多空研究指标时，要同时支持多头替代指标的扩展位。

### 8.3 禁止的结果字段演进方式

禁止：

1. 新增 `marketEnvironment` 字符串展示字段作为真源。
2. 同时保留 `forwardDays` 老解释和新解释并存。
3. 靠 `subtitle` 或 `title` 文案偷偷改变指标语义。

## 9. 缓存层对齐

后续因子回测缓存键必须纳入：

1. `marketEnvironmentProfile`

必要时继续纳入：

1. `returnAttributionMode`
2. `executionPriceModel`
3. `environmentContractVersion`

禁止做法：

1. 因为担心缓存失效而继续复用旧 same-day 结果。
2. 用一个布尔位兼容旧缓存和新缓存。

## 10. QML 与桥接层对齐

### 10.1 页面入口

因子回测页后续应新增统一市场环境选择器，但必须满足下面约束：

1. 不通过放大控件硬塞进去。
2. 不额外暴露一组重复制度布尔项。
3. 只让用户选择 `marketEnvironmentProfile`。

### 10.2 桥接职责

桥接层只负责：

1. 把页面枚举值写入 `backtestRuntimeParams`。
2. 把结果中的枚举值映射成页面展示标签。

桥接层不应承担：

1. 默认 A 股兜底。
2. 自动猜测用户想要哪种市场环境。

## 11. 测试矩阵

因子回测链至少要新增下面几类测试：

1. 配置序列化/反序列化测试：`marketEnvironmentProfile` 正常进出 `BacktestConfig`。
2. 执行语义测试：不同市场环境下收益起点不同。
3. result map 测试：`buildConfigMap` / `buildResultMap` 能正确暴露环境字段。
4. 缓存键测试：不同市场环境不复用同一回测缓存。
5. benchmark 对齐测试：不同市场环境下 benchmark 和策略收益保持同一口径。

## 12. 推荐实施顺序

建议按下面顺序推进：

1. 先在 `backtestRuntimeParams` 和 `BacktestConfig` 加入 `marketEnvironmentProfile`。
2. 再统一执行器的收益起点、日期归属和 benchmark 对齐。
3. 然后补结果合同和页面显示。
4. 最后补缓存键和测试矩阵。

这个顺序可以保证：

1. 先固定配置真源。
2. 再让执行行为服从真源。
3. 最后再让缓存和展示跟上。

## 13. 结论

因子回测链的关键不是“加一个 A 股 T+1 判断”，而是把市场环境开关收口成单一合同，并让配置、执行器、结果合同、缓存键和测试矩阵共同服从它。

后续实现必须严格遵守一个原则：

1. 只保留单一市场环境字段。
2. 不保留同语义兼容字段和歧义字段。
3. 不靠页面文案和隐含默认值维持行为。

只有这样，因子回测链的市场环境支持才算真正收口。
