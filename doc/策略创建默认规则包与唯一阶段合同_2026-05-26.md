# 策略创建默认规则包与唯一阶段合同

更新时间：2026-05-26

## 1. 目标

本合同用于约束策略创建页的默认规则包生成方式，以及规则编排页内部使用的唯一阶段口径。

本次改动只覆盖以下范围：

1. 策略创建第二步的默认规则包生成。
2. 规则编排页内部阶段字符串口径。
3. 桥接层对规则模板绑定 phase 的主顺序与主绑定选择。

本次不修改 Python 端规则建议 worker，不修改规则模板 YAML 内容。

## 2. 唯一阶段口径

策略创建页内部只允许使用以下阶段值：

1. market
2. eligibility
3. signal
4. portfolio
5. rebalance
6. execution
7. account_risk

禁止再接受以下旧阶段字符串：

1. entry
2. exit
3. risk
4. watch

如果外部输入仍然提供上述旧值，本轮创建页默认规则包链路不再做兼容映射。

## 3. 默认规则包内部合同

默认规则包只允许使用以下字段：

1. stageId
2. groupId
3. groupTitle
4. groupRole
5. groupOperator
6. templateId
7. templateDisplayName
8. fileName
9. summary
10. category
11. termId
12. termDisplayName
13. defaultInjected

约束：

1. 默认规则包内部禁止再混用 snake_case 字段。
2. 默认规则包内部禁止再出现第二套别名字段。
3. 默认规则包内部阶段字段统一为 stageId，不再用 phase 表达。

## 4. 默认规则包策略

### 4.1 模板驱动型策略

以下策略默认加载完整默认规则包：

1. TrendFollowing
2. TrendBreakout
3. Momentum
4. MeanReversion
5. EventDriven
6. HighFrequency
7. Custom

完整默认规则包至少覆盖：

1. 市场环境
2. 基础过滤
3. 入场确认或观察信号
4. 调仓退出

### 4.2 组合/模型驱动型策略

以下策略默认加载轻规则包：

1. MultiFactor
2. MachineLearning
3. Arbitrage

轻规则包只负责外层门禁，不替代模型本身的候选生成逻辑。

轻规则包至少覆盖：

1. 市场环境
2. 基础过滤
3. 调仓退出

不强行伪造不存在的信号模板。

## 6. 实施规则

1. 策略类型一旦确定，规则编排器先加载对应默认规则包，再允许用户局部增删改。
2. 默认规则包是主入口，智能推荐和模板库是补充入口。
3. 不允许为了兼容旧阶段字符串而继续保留 entry/exit/risk/watch 的归一化映射。
4. 本次不伪造不存在的模板文件；执行约束和账户风控如果缺少已验证模板，先保留为空组。

## 7. 创建页交互入口

### 7.1 主入口顺序

策略创建第二步的规则操作入口统一为：

1. 默认规则包操作栏。
2. 当前规则组快捷引入。
3. 智能推荐侧栏。

不再把右侧智能推荐侧栏当作默认主入口。

### 7.2 默认规则包操作栏

默认规则包操作栏至少提供以下动作：

1. 恢复整包默认项。
2. 恢复当前阶段默认项。
3. 展示当前选中阶段、当前规则组、当前阶段规则数。

### 7.3 当前规则组快捷引入

当用户选中阶段和规则组后，页面需要直接给出该位置可引入的默认规则项。

要求：

1. 优先显示与当前 stageId 和 groupId 完全匹配的默认项。
2. 如果当前组没有精确匹配项，再退到同阶段同角色默认项。
3. 再无匹配时，才展示同阶段其它默认项。
4. 已经在当前组里存在的 templateId 不再重复展示为快捷引入项。

### 7.4 按钮文案

规则组卡片底部按钮不再使用“添加规则”，统一改为“引入规则”。

原因：

1. 当前操作首先是从默认规则包或模板池引入，不是手工从空白状态创建规则。
2. “引入规则”更符合默认规则包主入口和建议侧栏补充入口的合同。
