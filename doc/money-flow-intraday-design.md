# 资金流盘中聚合设计（B1 tick 估算口径 + L2 可接 seam）

> 决策记录（2026-08-14）：用户要求 ①资金流是后续特征，**易扩展**——以后加任何字段不得破坏流程；②要看**连续流入**；③**盘中**也要能看到资金流入。数据源选 **B1**（tick 快照估算口径，主动买盘−主动卖盘），因当前**无法获得 L2 行情**；同时**必须记录 seam：后续有 L2 时能直接接进来**。官方数据源（gmsdk `stk_get_money_flow`、`fund.money_flow_daily`）均仅日频，**无分钟级资金流**——盘中资金流只能通过 **B1 tick 归类的分钟级聚合**完成（用户确认 2026-08-14："目前也只能通过分钟级的聚合来完成了"）。
> 本文档为设计定案与决策留痕，不包含实施（实施须另行确认后启动）。

---

## 1. Context（为什么是 B1）

| 口径 | 数据源 | 现状 |
|---|---|---|
| B1 快照估算（选中） | 现有 "tick" 订阅快照：`cum_volume/cum_amount` + 五档买卖盘 | ✅ 已订阅（策略池标的）、已有单点入口 `MarketDataService::onTick` |
| B2 真实逐笔 | gm 实时逐笔（`transaction`/l2transaction 频率） | ❌ 无 L2 权限；本版 sdk 实时逐笔支持未实测；回调量级大 |

gmsdk `struct Tick`（gmdef.h:332）字段：price/open/high/low、cum_volume/cum_amount、last_amount/last_volume、quotes[5]（bid/ask 价+量）。**无内外盘字段、无逐笔 side**——精确口径必须逐笔，B1 用业界通用 tick 规则估算近似。

## 2. 需求三条（用户原话要点，设计约束）

1. **易扩展**：资金流是后续特征。添加任何字段（个股/板块、历史/盘中、新口径）不得破坏现有评估流程。
2. **连续流入**：能看"连续 N 日净流入"。
3. **盘中可见**：交易时段内能看到当日资金流入情况。

## 3. B1 算法（Lee-Ready tick 规则近似）

每个 tick 快照到达时：

1. 成交量增量 `ΔV = td.cumVolume − 上一快照 cumVolume`（上一值取 LiveData 日K volume，更新前读取）；`ΔV <= 0` 或快照间隔无成交 → 跳过。
2. 方向归类（用**当前** tick 的最新价与买卖盘）：
   - `price >= ask1` → 主动买（额 += price × ΔV）
   - `price <= bid1` → 主动卖（额 += price × ΔV）
   - `bid1 < price < ask1` → 中性，不计入两侧
3. 边界规则：
   - 集合竞价（isAuction）或 bid/ask 任一空 → 跳过归类
   - 涨停（无卖盘）按 `price >= ask1` 归主动买；跌停（无买盘）按 `price <= bid1` 归主动卖
4. **聚合桶（参数化粒度，两个桶共用同一份逐 tick 归类结果）**：
   - **分钟桶**（主粒度）：按当前分钟 `minuteKey`（对齐已有 1 分钟 K 线）归集 → 每分钟净流入 = 该分钟内 Σ(买−卖)。分钟桶序列供盘中资金曲线。
   - **日桶**：当日累计 `主动买额 / 主动卖额 / 净流入 = 买 − 卖`（= 分钟桶累加）。
5. **日切重置**：`MarketDataService::onTick` 已有交易日变更检测分支（dayChanged），在清空分时 K 线的同点重置分钟桶序列与日桶累计器。

精度声明：B1 是估算口径（快照间隔内的成交按盘口位置归类），与真实内外盘存在偏差，仅供盘中参考；历史口径仍以 `fund.money_flow_daily`（每日权威数据）为准。

## 4. 落地架构（单点聚合 + 两条消费路径）

### 4.1 聚合落点：`MarketDataService::onTick` 单点

- 每标的的归集状态挂在 `LiveData` 上（与日K/五档/分时同级）：日桶累计（主动买/卖额、净流入）+ 分钟桶序列（对齐 `period(1)` 分钟 bar 的 minuteKey）。全部在现有 `mutex_` 锁内更新，零新增线程模型。
- 日切重置复用现有 dayChanged 分支，零新增触发机制。
- 分钟桶序列内存保留（当日有效），不落库（§7 边界）。

### 4.2 消费落点（两条路径，均零管道改动）

- **盘中分钟资金曲线**：桥接层查询 `MarketDataService` 的分钟桶序列（桥接层只转发/查询，不做计算，CLAUDE.md 1.2.1）。评估管道/提交器/调度器**零改动**。
- **日频评估因子消费**：盘中资金流字段（如 `intraday_net_inflow` 日桶）走既有扩展机制：因子 `getRequiredFields` 声明 → 视图列装配 → 因子计算。装配时该字段的数据来源与历史列不同（历史列来自 PG rows，盘中列来自 `MarketDataService` 内存累计器）——在视图列装配层做单点分支（按字段注册表区分"实时列/历史列"），仍不触碰评估主链。

### 4.3 连续流入（个股级）

- 数据已在库：`fund.money_flow_daily` 每日一条（v0.16.0 管线已注入视图）。
- 连续流入天数 = 因子内对视图历史行做连续符号计数（如连续 N 日 `main_net_in > 0`）——纯因子计算，零管道改动、零新存储。
- **不推荐**依赖 MarketDataBridge 内存 `m_sectorNetInHistory`（重启即失、仅板块粒度）作为正式路径。

## 5. 扩展性保证（三层扩展点，新字段不破坏流程）

| 层 | 机制 | 加新字段的动作 |
|---|---|---|
| ① 视图列层 | 因子 `getRequiredFields` → 视图列装配 | 声明字段 + 装配注册（历史列/实时列二选一），评估管道零改动 |
| ② 快照层 | `EodDayBar` 值类型（close/volume/preClose） | 加字段不改接口签名，管道按需读取 |
| ③ 持久化键层 | 键仅绑定 (strategyId, period) | 新字段不参与去重键，幂等语义不变 |

## 6. L2 后续接入 seam（换源不换链）

**关键约束：以后拿到 L2 权限时，接真实逐笔不得改动评估链路。** 为此：

- **源抽象**：资金流聚合与"分类来源"分离。定义源接口（如 `onTrade(symbol, price, volume, side)` 级别），累计器（分钟桶 + 日桶归集、日切重置）与源无关。
  - **B1 适配器**：快照 tick → tick 规则归类 → 产生带方向的伪逐笔 → 喂累计器。
  - **B2 适配器**（未来）：L2 逐笔回调（`L2Transaction.side` 直接给出方向）→ 直通喂累计器。分类逻辑在适配器内，累计器/消费层/视图列**零改动**。
- **装配点唯一**：源适配器的选择在装配处（类似 `PriceProviderFactory` 模式：枚举源类型，单一构造点），接入 L2 只换装配，不动 `onTick` 主链与下游。
- 未来 L2 接入时的前置确认项（届时再验证，勿提前实现）：gm 实时逐笔订阅频率是否可用、L2 权限范围、逐笔回调量级与线程模型、逐笔与快照双源并存时的去重/口径切换。

## 7. 边界 / 不做

1. **B2 实现本次不做**（无 L2 权限），只留 §6 seam。
2. **全市场 tick 订阅不做**（后续任务，见 daily-tick 双层架构约定）。当前 tick 订阅仅策略池 → 盘中资金流可见范围 = 已订阅标的；全市场盘中资金流依赖全市场订阅先行。
3. **盘中聚合不落库**（内存分钟桶序列 + 当日累计，收盘后权威数据走 `fund.money_flow_daily` 管线，避免两套口径并存）。
4. **盘中资金流字段不进回测**：回测视图列不注册实时列（tick 快照无历史回放），回测路径（step/stepBatch/runBacktestLoop）零改动，守住 10.75% V9 基线零漂移门禁。
5. 板块级盘中资金流（全市场聚合）依赖第 2 条，本次不设计。

- 全市场盘中资金流：等全市场 tick 订阅任务。
